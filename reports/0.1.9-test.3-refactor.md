## 交付

1. **固定契约互操作**：Rust 与 Dart 从同一 Cap’n Proto schema 生成绑定。运行期协议升为 2，请求携带运行期与内容 schema 摘要（源文本统一 LF 后 SHA-256）。双方严格核对，拒绝旧版本和摘要不符；这不是多版本能力协商，也不承担授权身份认证。生成器检查在临时目录重建绑定，验证源码与生成文件一致。
2. **原生／Wasm ABI**：Rust 提供相同的缓冲区分配、指针、长度、处理、状态、释放和活跃数量接口；一次最多 16 个缓冲区，每个不超过 64 KiB，句柄在同一实例生命周期内不复用。处理使用固定输入副本，Dart／Worker 复制输出并释放输入和输出。原生客户端必须同步独占句柄；此同进程指针接口不是插件安全隔离边界。
3. **精确 UInt64**：客户端使用 BigInt，不经过 JSON 或 JavaScript Number。原生 Dart 与 Dart/Wasm 都覆盖 1、2^53+1 和 2^64−1。Rust 生成单段／多段向量，由 Dart VM 和 Chrome Dart/Wasm 解码并经核心往返。消息正文始终为 Cap’n Proto 二进制。
4. **宿主状态原型**：HostPolicy 分配带宿主身份和实例代次的句柄；重命名授权限定对象和期限，依赖关系不能自动授予权限。接单固定请求，完成前再次核对同一授权和固定请求；本轮没有依赖解析器。正常停止拒绝新任务并排空，达到截止时间则撤权；安全停止先撤权后取消，不依赖插件回调。宿主须驱动单调时钟与 expire_drains，迟到结果也检查排空期限。
5. **提交观察状态**：区分未提交、结果待核对、本地已提交、已封存、已见证与查证未提交。超时保留待核对或已知提交状态，不能据此推断未执行或回滚。该状态类型不是耐久日志，没有实现封存、见证或存储查询。

`morrow_buffer_process` 目前只校验、解码并重新编码请求，不调用 HostPolicy、不修改卡片或持久化；HostPolicy.complete 只产生内存编辑提案。权限检查与持久化提交之间的原子边界必须在 M2 建立后，才能宣称真实写入受控。

## 明确的 Web 限制

固定候选 capnpc_dart／capnproto_dart 0.1.0 生成了 UInt64 schema ID 整数字面量；普通 `dart compile js` 实际失败，提示这些值无法被 JavaScript 精确表示，日志保留在 `build/core-test.3/javascript-probe.log`。没有通过截断、改成 double 或绕过校验让它编译。

本轮通过的是 **Dart/Wasm 客户端**，尚不能把该包直接编入现有 Flutter JavaScript 产物。新客户端未加入主应用 pubspec。下一步比较可独立加载的 Wasm 协议适配与精确整数替代生成链；其他浏览器、移动端、Apple／Linux、跨进程 mmap 和实际插件隔离均需独立证据。此处的 Worker 只承载可信核心，不代表第三方插件已被隔离。

## 复现

```powershell
# 首次在 packages/morrow_core_client 中运行 dart pub get
python -X utf8 tool/generate_core_client.py --check
pwsh -File tool/verify_core.ps1 -Web
pwsh -File tool/verify_core_client.ps1 -Web -Python python
flutter analyze --no-pub
flutter test --no-pub
```

需要 Flutter／Dart 3.12、Rust 1.95、Cap’n Proto compiler 1.4.0、Rust wasm32-unknown-unknown 目标、Node 和 Chrome／Chromium。脚本遵循已锁定依赖，不自动升级工具链。生成器读取 Pub 的工具元数据 JSON；它不是业务通信、存储、审计或核心配置。
