# 0.1.9-test.10 重构记录

日期：2026-09-11。应用 0.1.9-test.10+19；Rust 核心、Web 适配及独立 Dart 包 0.1.9-test.10。分支 codex/refactor-test.10，基于 test.9 的 cf08ebf。

本轮推进 M1-01、M2-01／M2-02／M2-04：工作区、视图位置和既有卡片草稿进入同一 Rust 存储核心。没有切换工作台保存路径、读取真实旧资料、推送远端或发布安装包。完整插件系统和 M5／0.2.0 验收仍未完成。

## 实际交付

- Workspace、ViewPlacement、Draft 新增独立 UInt64 修订；三类记录各用明确的 Protobuf＋LZ4 容器。保留未编辑的原始 Protobuf 字节，已知字段修改保留未知字段，不用投影覆盖完整记录。
- 工作区创建／改名；视图位置创建／修改顺序、折叠和宽度。同一卡片可被多个工作区引用，各视图独立变化，卡片本体不复制、修订不变化。
- 草稿关联既有卡片、基准修订和类型／格式，保存不透明正文。草稿修订独立递增，不修改正式卡片；卡片后来修改时，仍可保存旧基准草稿，不伪装成已经合并。
- 同一 SQLite IMMEDIATE 事务提交记录、操作结果和待封存事件。与卡片共用操作 ID 命名空间、事件预算及 outbox；相同完整命令重试得到原结果，跨类型复用操作 ID 或不同命令复用 ID 拒绝。
- 对象结果查询同时限定类型、对象 ID、操作 ID。卡片查询不会查到同名工作区；启动检查引用、操作／事件一致性，以及当前完整记录和最新事件结果的原字节一致性。
- record_transaction.proto 保存固定命令和完整结果原字节、摘要。新事件 MORROWR1 与既有卡片事件共同进入 pending；摘要不代表签名或封存，未来审计读取端须按容器类型分派。
- 新 CLI 可创建和修改上述记录、独立查询及导出完整容器。导出先写同目录临时文件，完整同步后发布且不覆盖已有文件。Web 通过第一方管理入口复用同一 Store，草稿创建从调用者保留的固定卡片容器取得基准，重试不重新读取当前卡片拼出不同命令。

新记录入口目前仅供可信本地宿主／CLI／浏览器实验适配，尚未进入通用 Cap’n Proto 授权分派或 Dart 主应用界面。没有开放给第三方插件选择身份、对象类型或数据库路径的旁路。

## 验证结果

原生最终检查：96 项默认 Rust 测试及 7 项故障测试，共 103 项；故障矩阵覆盖 44 个子进程退出场景，其中新增记录创建和草稿保存的 12 个提交前后边界。Rust fmt／Clippy -D warnings 通过。

新增覆盖同卡多工作区、视图及草稿互不覆盖、重启恢复、严格修订、跨类型全局去重、查询隔离、缺失引用与类型不符、事件容量总回滚、未知字段保留、容器截断／跨类型拒绝、最大 UInt64 和溢出、记录篡改／删除后启动拒绝。实际限制 SQLite 页数，触发草稿正文保存时 StorageFull，验证原草稿、操作和事件完整保留。

既有客户端回归：10 项 Dart 测试、生成绑定、分析、真实 DLL 调用与 5 MiB＋17 字节附件读取通过；旧 Dart/Wasm→Worker→Rust/Wasm 协议探针通过。现有 Flutter 分析和 71 项测试通过。

Chrome 152.0.7977.83 的 47 个 Worker 中断点全部通过，其中包括工作区改名、视图修改、草稿保存的 18 个新终止点。独立页面重开恢复、多工作区、固定草稿基准重试、既有附件读取与原生→Web→原生最大 UInt64／未知字段保留均通过。Web fmt／Clippy -D warnings 及默认／故障构建通过。

浏览器测试曾因独立数据库累积使文件池达到 64／64，创建下一个数据库被 SQLite CannotOpen 拒绝。已增加仅 fault 构建启用的 SQL／池占用诊断，并将新增矩阵放入单独的 64 槽测试池。没有扩大默认容量、删除旧测试数据或退回内存；该问题是测试数据集资源边界，不能作为磁盘配额恢复证据。
