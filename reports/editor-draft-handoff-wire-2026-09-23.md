# 草稿交接私有协议与原生客户端

日期：2026-09-23。基于未提交的开发工作树，应用仍为 0.1.9-test.54+58。未提交、推送或发布。本轮接通已有 Rust 交接底座的私有协议和 Dart 客户端，不代表正式编辑器已默认启用自动保存。

## 实现与边界

私有协议完整传递 ParentLink、ParentRetirement、parentDraft 附件来源与分页关系。新增 action 114（完成交接）、115（条件退休父草稿）、116（只读发现）；既有 action 编号保持不变。契约摘要及生成绑定同步更新，公开插件 ABI 没有新增交接权限。旧格式的普通草稿保存不接受 parentDraft 来源；必须经过完整交接证明校验。

每份 Record 增加宿主计算的 requestSha256，即精确 Protobuf WriteRequest 字节的 SHA256。Dart 不能用自己的 Capnp 编码摘要代替。构造父链接需要当前、活动且带有该摘要的宿主记录；宿主仍重新核验父历史、真实业务提交证据和完整快照。客户端缺少摘要、摘要长度非法或链接形状非法时拒绝，不能静默补零。

NativeEditorDraftHandoffControl 与普通草稿保存、附件导入共用原串行队列。请求在排队前冻结，交接分段上传并核对精确原请求；发送完成动作以后无法确认结果时保留 Unknown，不生成新操作、不自动重试。首个完成回复丢失后，只用原上传 token 清理对应回复缓存；退休使用发送前固定的请求关联标识。清理传输缓存不意味着撤销已提交的草稿。

退休请求固定卡片、父/子 draftId、首代子 operation、原父代次和退休 operation，回执必须包含对应父记录及退休标记。历史交接回执的 generation 与 currentGeneration 分开保留；原子草稿后来继续保存或退休，不能使旧交接回执冒充当前活动状态。

关系发现每页 1–32 项，宿主按私有草稿键排序并回显 cursor/limit；客户端严格检查顺序、上下文、重复身份与下一页推进。全扫描在一次共享队列任务内完成，最多 256 项，返回不可变快照。只读发现不要求已启用插件包，不执行恢复动作，不授予任何写入权限。该快照也不能替代实际提交前的宿主校验。

中间草稿可以同时具有来自上一代的 ParentLink 和交接给下一代的 ParentRetirement。首次复核发现客户端误把这两者视为互斥，已移除错误限制，保留真实的身份、代次和状态检查。真实 A→B→C 测试核对了 B 的双关系、分页发现、重开和历史原操作重试。

## 验证

- Rust 模型/协议单元 22 项通过；真实宿主交接、边界、新协议与原协议集成 22 项通过，共 44 项，不累计上一阶段重复运行结果。
- 客户端编解码 14 项通过；真实 Windows 客户端组合 8 项通过，无跳过。其中交接测试后来扩展为三代并单独重跑通过，不重复计数。
- 新协议测试覆盖真实正式提交、较大分段回复、错误外层身份拒绝、丢首回复后精确 token/correlation 清理、原操作 repeated 回执、无包重开和只读分页。
- 客户端真实测试覆盖两附件顺序与别名、删除原文件后继承 pin、父代次变化拒绝、错误摘要拒绝、条件退休、读取恢复、子附件改为 previousDraft 后继续保存，以及三代交接。原草稿会话、新卡、附件目录、工作区保存及导入恢复发现回归通过。
- 静态分析 8 个文件通过；生成绑定检查通过。最终 Windows x64 Release INSTALL 重建成功；最终产物上的客户端组合 22/22 通过，无跳过（14 编解码 + 8 真实客户端）。

主要日志位于 build/review-editor-draft-handoff-wire-*：unit、rust、codec、native-initial、native-final、analyze、codegen-check、windows 及 windows-final。final-client 日志记录最终产物组合验证。

## 尚未完成

交接请求目前由调用者固定并持有。已提交的子关系可以从宿主重新发现；尚未完成“发送前的交接提案”跨应用重启持久发现与明确处理，不能把只读关系列表当作完整 Unknown 恢复系统。原操作重试验证保留了测试调用者的提案；Rust 对象重开与同一 Dart 测试进程内重新启动宿主，也不是独立应用客户端进程崩溃后自动恢复的资格。

下一步持久固定交接提案和原退休操作，再接通工作台草稿拥有者、正式编辑器关闭/恢复流程及界面选择。先确保父最新完整快照可恢复，再建立子和条件退休父；子可恢复之前不清除正式 S1 的恢复证据。仍需富捕获来源链、长期草稿/历史维护、语言/字体待决提案、迁移界面、完整错误/私有诊断、远端 Unknown、SDK 与其他平台资格。本轮没有新增 Android/Web、实际窗口交互或性能验收；现有 content_api 的 3 处 dead_code 警告不等于严格 Clippy 清零。
