# 按资源依赖撤销与 Windows 验证（2026-09-21）

基于 `2dd8fc5`，保持 `0.1.9-test.52+56`；本轮仅本地开发，无推送或发布。

## 行为与边界

原 Store 的配置 ID、入站批准引用、出站端点/凭据引用分别追踪撤销代次。端点依赖自身和所用凭据；服务依赖配置、发布批准和全部认证记录。无关资源写入不再撤销它们。相同字节的入站/出站引用不会混用。

解析前仍取得原 Store 的全写入守卫，记录全部读取后，在同一撤销锁内收窄为精确依赖；读取期间发生撤销时拒绝签发。最多 2048 个活跃资源代次，死亡条目可回收，超限原子拒绝。原 Store 销毁、显式全局撤销、旧全写入守卫的保守行为不变。

队列接受修改时先撤销匹配依赖；实际写入仍在原拥有者内按 CAS/身份规则串行完成。直接写入的前置 CAS 冲突不撤销，开始修改后的容量回滚不复活旧租约；未知提交和已发出的网络效果不能当作回滚或自动重试。

主应用服务的固定范围包含全部**明确选择**的出站资源。选中端点/凭据的撤销、到期或时钟倒退，通过限制性依赖一并约束监听、Principal、内容权限、历史与 Ready/read 交付；已缓存响应也不能绕过。未选端点的新增/停用保持原服务身份和缓存可用。当前不是逐请求依赖：多个选中端点中任意一项失效，整个依赖服务仍退出。没有持久化 Schema 或公共 SDK ABI 变化。
