# 附件放弃决定：持久身份与独立客户端进程恢复

日期：2026-09-23。应用仍为 0.1.9-test.54+58，第一方插件仍为 0.1.9-test.54.3；本地工作树基于 ddd9cc8eec224af51f4e58654c9b297332147d96。未提交、推送、发布或修改公共插件 SDK。本报告覆盖客户端/宿主恢复机制，不宣称编辑器自动保存与恢复 UI 已启用。

## 持久决定与准确状态

增加独立、仅含元数据的决定 journal，不向 CardRecord attachments 写入暂存字节，也不占用暂存记录的 256 次修订预算。先以确定的内部操作登记原导入请求、原放弃操作号和决定基线，再允许执行实际放弃。Prepare 回复未确认时，客户端不发送放弃事务；重启可先找回已持久决定，再由用户明确选择重试或取消。

Pending、Committed、Cancelled、Conflict 分别来自原请求、当前基线及确切操作历史。Committed 必须匹配原放弃操作在暂存 journal 的 kind4 提交、完整导入请求与决定基线，并携带确切历史提交修订。自动 Retired、主草稿丢弃、后续清理都不能冒充某个放弃决定已提交。

取消使用原 abandonOperation 作为 Core 事务号，将决定记录原子更新为 Cancelled。取消和实际放弃争用同一个全局操作身份，至多一个提交；取消后迟到的旧放弃请求被拒绝。即使基线已经推进或整份草稿失活，仍可封存尚未提交的旧操作，不能悄悄换号或重新定基。

每条决定最多两次修订，正文上限 64 KiB，全局最多 256 个决定身份。达到上限拒绝新决定；已有决定的精确重试、检查和取消不受新身份容量阻断。旧版本已经真正提交的放弃操作，在额度满时可以返回只读 Committed 历史投影，decisionRevision=0 明确表示未新增决定 journal；只能据确切 kind4 历史确认，不能用此路径创建新的放弃。未归档旧历史不会自动出现在决定列表中。

## 私有协议、范围发现与客户端

私有动作 109–112 接入 Prepare、Inspect、分页 List、Cancel，原 107 对新放弃要求已准备决定；旧确切提交保留只读确认。新增只读动作 113 枚举决定所在的全局卡片/草稿范围，包括失活草稿和终态决定，并验证对应 Prepare 审计历史。因此整份草稿被丢弃后，不依赖仅返回活动草稿的旧列表，也能找到遗留决定。

范围和决定列表均限制每页 1–32 项，校验游标归属、原请求身份和回显上下文。全局范围响应使用空业务身份、零主代次和失活状态；它只提供发现入口，不代表业务执行或当前授权。所有新旧草稿通信共用整段传输队列。

Dart 会话可由宿主决定只读重建，分别保留导入与放弃的未知结果。恢复本身不执行新请求、不重新打开源文件；显式重试仍使用原操作和原基线，取消不重新授权已封存操作。迟到的旧工作区回复不能改变当前会话。

分页为有界实时扫描，不是跨页快照。将来恢复 UI 必须在扫描期间阻止本工作区新增决定，或重新从头扫描；并发插入排序位于游标之前的记录时，本轮可能漏列。单个决定在操作前仍须重新核验。本轮独立进程验收在恢复扫描期间没有并发新增操作，不声称验证了任意并发下完整枚举。
