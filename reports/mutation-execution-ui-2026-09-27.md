## 完成范围

Windows IO 设置新增 `MutationExecutionManager`，接入现有 owner 的 Create／Delete。仅显示当前目录版本中已启用、可用且已批准对应能力的插件。Create 选择目录、单级文件名和可选内容文件；Delete 选择目标文件。第一次确认展示包身份、路径、操作、内容长度及 SHA-256，只准备计划；执行另需确认，Delete 明示永久删除。取消确认不执行文件效果。

内容先捕获为有界快照，再绑定审批摘要；上限引用共享 16 MiB 定义，分块上限 60 KiB，文件大小读取有期限，流读取有总期限及取消入口。选择器、源流和对话框的迟到结果受后端、目录修订与页面代次约束。准备期间可停止，不因迟到回执继续上传、提交或执行。

`MutationExecutionSession` 独立于页面，保存任务身份、规范计划和最后结果。页面隐藏停止展示轮询，离页返回不重复执行；丢回执只允许显式重取原提交或读取已知结果，不自动续完准备链。终态、停止中、待核对或操作 ID 不匹配不能执行。任务错误与清理错误分开显示，ACK 后仍保留结果供展示。新操作需重新明确准备。

清理后“查看文件恢复”仅定位面板并预填包、主体及类型；不会自动发现、核对或授予权限。忙碌中的恢复会话延迟采用预填范围，不改变原任务。新增 27 条文案覆盖中文、英文、俄文、法文、德文、西班牙文、日文、韩文、葡萄牙文；目录与生成资源一致。

## 实际发现并修复的问题

- 对话框返回触发的状态刷新可能抢占已确认的准备／执行；确认期间暂停展示刷新，并在继续前复核范围。
- 准备等待中的 Stop 必须能立即发出管理取消，不能排在自身等待之后；停止闩锁阻止迟到回复推进下一命令。
- 成功 ACK 的 Local 回复现在也核验提交身份，外来非空提交不能清空本会话。
- 真宿主在 ACK 后可能保留原提交编号。原实现把后续 Local 刷新的该编号判为外来状态，导致创建后无法再次选择删除。现只接受与本会话最后请求精确一致的历史编号，其他编号仍拒绝；受控回归与真实 UI 连续操作均通过。

首次联调另外修正了测试夹具路径分隔符和等待下拉列表恢复可用的时序；这些是测试修正，不作为产品功能修复计数。
