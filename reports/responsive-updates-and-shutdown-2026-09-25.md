# 更新流程、卡片 tips 与 Windows 退出优化

最终交付：`build/responsive-v3.5.1-windows/Release/morrow_studio.exe`。关闭旧版本窗口后使用此程序，保留整个 Release 目录。原资料库与主题继续使用；排序和文本偏好仍存于设备本地。

## 1. 拖拽后立即更新

卡片顺序现在先更新本地展示，再异步写入偏好。慢磁盘不会阻止卡片移动；保存失败回到此前已确认的顺序并提示。保存过程中禁止重复拖动，防止旧写入覆盖新顺序。普通排序菜单也立即更新，未改变自定义模式时不重复写盘。

新增测试用尚未完成的保存请求验证：卡片 ID 顺序和实际屏幕位置已经改变；随后注入写入失败，确认恢复原顺序。

## 2. 减少筛选重载和闪空

- 文本搜索保留 200 毫秒防抖；页面、排序和已确认内容修改不再额外等待防抖计时。
- 同一内容服务、同一页面／筛选／搜索／排序下更新内容时，继续显示之前确认的卡片集合，并映射到最新已确认的内容，等服务返回后原位更新集合。删除项立即从实际内容中消失。
- 页面或搜索条件变化、服务更换、权限失效仍清除旧结果。后台筛选失败时也清除保留结果，展示原有错误与重试入口；不把缓存伪装成新的服务确认。
- 未修改内容就关闭编辑页，按稳定 ID 和内容修订比较后跳过重复查询与偏好保存。无修订信息的旧后端保留保守刷新路径。
- 移除插件设置／IO 设置仅进入返回时的无条件查询失效；成功的配置或权限修改仍由原回调触发重新确认。
- 本地展示保存不触发内容查询；Rust 偏好写入不再反复提交未改变的语言、字体，从而减少内容服务队列中的无效工作。

## 3. 卡片内 tips 逐条编辑

原卡片编辑器中的整块待办／tips 文本框改为独立圆角条目，共用现有 tips 编辑样式。支持添加、删除、上下移动和长按手柄排序，随卡片保存；保留总计 1000 字符限制。

底层草稿仍使用原换行字段，不引入业务协议变更。逐条输入与整体草稿双向同步，粘贴的 UTF-16 选区偏移继续准确记录；整段多行粘贴可拆成多个条目。旧文本完成状态与去重规则保持原语义；有稳定任务 ID 的新版清单继续使用原任务面板。

Windows 390 像素宽度实际渲染已目视检查：`build/card-tips-windows-390.png`，中文、条目按钮与拖拽手柄正常，没有布局溢出。

## 4. 关闭窗口与内容服务退出

关窗立即转入后台，并用关闭界面屏蔽原操作。正在提交的编辑器继续存活，避免关闭捕获会话打断提交；等待已提交的卡片、偏好和本地 tips／排序写入结束后，再释放界面、媒体与编辑器，关闭内容服务输入。窗口真正销毁仍以实际服务进程退出为前提，不使用强杀或假定超时等于退出。后台长时间未完成或失败时保留原有提示机制。

额外发送真实 Windows `WM_CLOSE` 后发现：原运行器的内容服务约 80 ms 即退出，但应用随后在 `flutter_windows.dll` 出现 `0xc0000005/0xc000041d` 原生退出异常，完整退出约 7.8 秒。运行器此前收到 `WM_QUIT` 就结束消息循环，在 COM 结束后才隐式销毁 Flutter 窗口成员。已改为在 COM 有效、派生窗口处理器完整时显式 `Destroy()`，析构函数也覆盖部分初始化路径，避免成员释放期间继续处理失效的窗口回调。

最终发布包真实关闭复验：服务退出约 **78 ms**，应用退出约 **113 ms**，应用退出码 **0**，服务无残留。证据为 `build/responsive-v3.5.1-qualification/window-close.json`。该测试遵循隐藏启动要求，向本次独占测试进程的隐藏窗口发送原生消息，测量的是本机进程退出耗时，不能将其隐藏状态观测值解释为可见窗口动画耗时，也不保证繁忙资料库具有同样时间。旧异常基线保留在 `build/responsive-v3.5-qualification/window-close-baseline.json`。

测试工具：`tool/qualify_window_close.ps1`，仅定位本次启动且进程 ID 匹配的 Flutter 窗口，记录所属内容服务退出情况，不关闭其他窗口或强杀进程。
