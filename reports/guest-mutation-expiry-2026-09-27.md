# Guest 审批到期与安全收尾

日期：2026-09-27。当前开发工作树 `codex/io-safety-refactor`，应用版本仍为 `0.1.9-test.56+60`。本轮接续完整 Windows 构建后的人工审批期限问题，不改变 Rust 协议或延长授权。

## 修正

- Session 从首次发送 Start 前记录单调时间，使用原请求的 `timeoutMs`（UI 为 30 秒）作为保守的本地审批截止。刷新、Prepare、Execute、精确重试和页面往返不续期。该计时只能提前关闭本地入口，不能替代原宿主的权限核验，也不宣称是宿主准确的剩余时间。
- 截止后禁止新的 Prepare、Chunk、Commit、Execute 和同任务 Query/Cancel/Release；保留状态观察、已有回执读取、停止、实际退出后的修复及确认回收。收到宿主的明确 Expired/Deadline 结果也关闭本地审批入口。
- **到期后禁止提交重试，包括原 token 的精确重试。** 原请求可能根本没有抵达宿主，重试可能成为首次执行；不能因为 token 相同就允许它跨过本地审批截止。未取得提交回执时保留不确定性，回收后通过独立只读恢复核对。
- Prepare/Execute 弹窗会更新到期状态并禁用确认；确认返回后重新观察原任务，再次核对会话、epoch、目录版本、包与计划摘要后才能提交。取消弹窗恢复页面轮询。
- 后端或目录授权变化时精确移除旧审批 DialogRoute，不弹出其上的其他对话框。弹窗计时器在到期、关闭或视图释放时取消。
- 九种语言的截止提示不再建议到期后直接 Release，改为 Stop、等待实际退出、必要的 Repair/ACK，以及对已提交操作先核对、不得重复执行。

## 验收边界与后续

本轮 Dart/i18n 修改发生在上一轮不可变 Windows 预览 ZIP 生成之后，**不在该旧 ZIP 中**；没有覆盖旧包，也没有推送或发布。测试会编译当前 Dart 源码并连接固定原生宿主。

真实 30 秒到期场景本轮覆盖 Rust Guest Create；正向原生与 Widget 回归覆盖 Create/Delete。伪时钟回归不代替真实宿主到期，也不把原生测试声称为系统文件选择器或人工点击验收。最大 16 MiB、三语言故障矩阵仍绑定各自历史产物，其他平台、断电和条件 Replace 资格没有由本轮扩展。

下一步仍需系统文件／目录选择器和实际人工审批验收；重新生成完整应用时，应将本轮修复纳入新的不可变本地输出。SDK 尚未冻结。
