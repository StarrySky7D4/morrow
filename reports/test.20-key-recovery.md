# test.20：Windows 原保护文件恢复

日期：2026-09-12。应用 `0.1.9-test.20+25`，审计／工作台宿主 test.20；核心仍为 test.19，工作台 Rust 插件 test.13，SDK／执行后端 test.11。当前为本地开发版，未推送或发布。

## 解决的问题

test.19 在保护文件丢失时拒绝打开内容库，但只能由用户手动把原文件放回。test.20 的启动失败页加入「选择恢复文件」与「重试打开」：取消选择保持原状态，处理中禁用重复操作，错误文件保留失败提示并允许重试，成功后重新打开同一内容库。采用柔和色调、圆角面板及可换行按钮，380px 窄屏布局通过组件测试。初始化后续失败会关闭已打开的宿主，避免重试时残留会话锁。

Flutter 只传递用户选择的文件路径。Rust 在与普通工作台相同的会话锁下，一次读取并固定保护容器字节，使用原系统账户解密并核对绑定身份，再只读验证全部内容库历史。所验证的保护字节才会被写回；不生成新身份，不创建、迁移或修改数据库。已绑定空库及旧格式 5 的已签名库也要求正确原身份。

若目标缺失，发布禁止覆盖新出现的文件；若现有文件已有效且匹配，返回幂等成功。现有文件损坏或属于另一身份时，先保存并同步同目录 `morrow-audit-key-before-restore-*.backup` 副本，再原子替换。用户选定的备份保持原位。发布之后无法确认结果时提示重新核对，不声称恢复已回滚。

这是可信桌面控制入口 `morrow-workbench-host --restore-key DATABASE ORIGINAL_PROTECTED_FILE`，不需要插件加载，不增加插件恢复、文件系统或密钥访问权限。私有工作台消息契约保持不变，生成绑定检查通过。

## 验证结果

- 审计原有 26 项测试全部通过；新增恢复测试最终 7 项通过（含故障子进程入口），总计 33 项。覆盖正确恢复、错误候选拒绝、损坏历史拒绝、会话占用、未绑定库拒绝、幂等、原件保留、64 KiB 限额、空绑定库及旧签名库。
- 实际子进程在「副本保留后」「发布前」「发布后」直接退出，分别验证目标缺失与损坏两种情况，共 6 个中断场景。重新恢复后保护文件与原字节一致，数据库字节保持不变，损坏原件副本保留。
- 审计与宿主严格 Clippy 通过。
- Flutter 恢复界面组件测试通过：窄屏、取消选择、处理期间阻止重复操作、失败显示与重试。
- Flutter 到正式 Release 宿主的 2 项集成测试通过：原业务／配置／附件往返，以及保护文件缺失、错误恢复文件拒绝、选择原备份恢复、原记录读回和保护文件字节保持。
- 最终 Flutter 静态分析无问题，Windows Release 编译通过，源码差异空白检查通过。
- 真正的 Windows Release 应用在全新合成目录运行，画布接口、静音 WAV 解码、播放时钟／跳转／互斥、工作台渲染检查通过，退出码 0。随后使用随包宿主恢复该合成库丢失的保护文件，恢复前后数据库 SHA-256 不变，保护文件 SHA-256 与原件一致。

实窗与随包宿主证据目录：`build/workbench-host/test20-runtime-3818afe3f3b348b6ad90590c2ca989a8/`，包含 `result.md`、`result.png`、`restore.txt` 及合成 `data/`。验证未读取实际用户资料。
