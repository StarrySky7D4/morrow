# 宿主持久草稿交接提案

日期：2026-09-23。应用仍为 `0.1.9-test.54+58`，内置包 `0.1.9-test.54.4`；基于未提交开发工作树。未提交、推送或发布。本轮补齐 Rust 宿主发送前提案，尚未接入新私有 wire/Dart 或正式编辑器自动保存。

## 解决的问题

上一阶段已能持久保存已完成的父子关系，但未提交的完整交接请求只由调用方持有。客户端进程退出后，仅列出已存在的子槽无法恢复原 child operation、完整快照或父退休操作。

现在新增宿主 prepare、inspect、list、complete、retire、cancel 六类库 API。Prepare 在同一宿主 owner 的串行边界核验真实 S1 审计证明、精确父代次/请求摘要、完整原始文字与附件顺序/别名；将完整 child WriteRequest、ParentLink 和固定 retirement operation 写入独立 Protobuf journal，通过已有 Core 存储与审计事务持久化。

Prepare 本身不建立子草稿、不退休父、不提交正式内容。读取和分页发现也不重发动作。状态明确区分 Pending、ChildCommitted、ParentRetired、Cancelled 和 Conflict，同时提供当前父子代次/活动状态。原历史证据和当前状态分开核对；损坏历史不转换成“没有执行”。

## 一致性与生命周期

- 已备提案冻结父的新保存/丢弃/导入，预留子身份与操作；精确旧历史重试先返回。新的子快照必须由该提案执行，普通保存或旧直接交接不能抢占。
- 子确认持久后，父仅能以原提案中的退休号条件退休。父退休失败时允许父子均活动，并保留原快照和附件。合法子后续保存/丢弃不会抹掉原交接历史。
- 取消只针对未执行子提交，以原 child operation 原子写入取消记录，在 Core 全局操作表永久封存迟到 child。退休号保留为提案预留身份，不能被另一提案或旧退休入口复用。
- 取消之后可显式准备新提案，但不能切回旧直接接口绕过该父的提案流程。未涉及任何提案的旧私有接口暂保留兼容；不能宣称这些调用已获得本轮发送前恢复能力。
- 所有提案具有审计 Prepare/Cancel 核验、严格游标、单条与累计字节限制及取消字段的预留余量。当前 256 提案身份、64 MiB 提案元数据上限是资源约束，不是长期历史维护完成的证明。
- 暂存清理保留原有“已消费/已失活”证明核验；不能因交接冻结永久阻断父退休后的安全清理。本轮已验证暂存归属释放后子 pin 仍可导出原字节。

S1 来源继续依赖持久 operation_commit/operation_evidence，不借内存 capture scope 推断成功。正式 UI 清除 S1 恢复提示及临时来源的时机仍须在接线时调整。
