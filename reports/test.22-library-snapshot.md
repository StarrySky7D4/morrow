# test.22：内容库一致性快照

日期：2026-09-12。应用 `0.1.9-test.22+27`，核心／审计／宿主 test.22；Rust 业务插件 test.13、SDK／执行后端 test.11。当前为本地开发版，未推送、打标签或发布。

## 实现与边界

设置的内容保护卡片增加「备份内容库」，原保护文件备份入口保留。可信核心在固定读取事务中用 SQLite backup API 生成一致性暂存快照，拒绝现有目标并限制复制规模／迭代。宿主验证快照完整性后，以版本化 Protobuf＋LZ4 清单和 1 MiB 数据块封装为 `.morrowbackup`。清单包含整库字节数、SHA-256、原受保护容器与公开身份；SQLite 页只是引擎拥有的中间载荷。

库内卡片、偏好、附件、原始操作、待封存事件和签名历史一起保存。导出不清空源待封存队列、不生成新身份，也不直接复制运行中的数据库文件。外部素材保留引用，插件程序、缓存及库外原件没有打入包内。

读取时限制压缩帧和解压后长度、分块序号、总字节数、数据库摘要及尾部字节，并验证保护文件归属和完整内容库。数据库上限 8 GiB，是格式限额而非已经验证的规模性能。UI 对快照命令采用独立的 30 分钟等待上限，超时按结果待核对处理。

恢复目前通过 `morrow-workbench-host --restore-snapshot ARCHIVE NEW_DIRECTORY` 或对应可信 Dart 客户端入口，在同一父目录的临时目录完成解包、同步与完整验证，再发布新目录。已有目标拒绝，不覆盖、迁移或自动切换原活动库。恢复得到 `workbench.db` 与匹配的 `workbench.db.audit-key`。
