# test.24：活动内容库恢复与插件底座并行推进

日期：2026-09-12。应用 `0.1.9-test.24+29`，审计／工作台宿主 test.24；核心 crate 保持 test.22（格式 6），执行后端 crate 保持 test.11，本轮向两者新增独立模块；业务插件 test.13、SDK test.11。当前仅本地开发，未推送、打标签或发布，已发布的 test.14 附件保持不变。

## 已接入默认 Windows 工作台

新增 Rust 权威活动库登记，以固定 Protobuf＋LZ4 保存目录、原日志身份、公钥、代次和上一目录。默认启动通过 `--managed ROOT PACKAGE` 使用该登记；第一次成功打开原根目录内容库后登记，以后按登记目录打开。登记目标缺失、保护文件丢失、路径被另一合法身份替换、持久格式损坏或未知时，拒绝打开，不能当作新安装自动初始化空库，也不回退原目录。

宿主全生命周期持有根目录的登记锁，选择新目录须等待原宿主确实退出。`Session::open_expected` 在数据库租约内比对固定保护文件的身份，随后才打开可写审计库，避免只读核验与可写打开之间换库。登记文件同目录暂存、同步后原子替换；发布尝试起至读回确认前属于结果待核对状态，失败后对象不能继续使用旧内存路径，须重新打开核对。

启动失败页增加「从内容库备份恢复」：选择原 `.morrowbackup` → 验证并恢复到新的 `ROOT/recovered/library-*` 目录 → 可信宿主激活 → 重新打开。原目录保留。界面说明恢复到备份时点且仍需原账户；当前不做运行中的切换，防止未排空的保存队列与关闭交叉。保护文件恢复也经 `--restore-active-key` 定位实际所选库，不能误写原根目录。

显式 `--data-directory` 默认继续使用独立实验目录；资格验证可加 `--managed-library` 验证新登记路径。登记表损坏时本轮没有自动修复／重置入口，直接快照解包仍可保留恢复资料；后续需提供保留损坏登记的受控修复流程。登记表不是快照中包含的用户内容库，也不作为插件能力传递。

## 子代理交付与交叉审查

- **插件选择与批准状态**：新 `core::plugin_package::registry` 以 PB＋LZ4 保存包摘要、启用状态、批准能力和全局修订。升级默认禁用，批准保留交集；所有变更校验预期修订，批准／启用还绑定摘要，防止旧确认批准刚升级的包，或重新授予已经撤销的同摘要能力。移除选择保留不可变包及用户内容。详见 [接口与边界](../docs/PLUGIN_REGISTRY.md)。
- **在线 UI 会话**：新 `plugin_runtime::ui_session::UiSession` 关联固定包、实际连接、后台 Worker 和核心 UI Session；单事件背压、身份／动作／修订校验、执行失败回执、取消与迟到结果丢弃已建立。Rust／C／C++ 真实 Wasm 各完成连续 27 个有效快照，无阶段间磁盘拼接，且不把 UI 更新当作内容提交。详见 [验证记录](plugin-ui-online-session-validation.md)。
- **独立验收**：补充顺序历史分叉边界证据，以及路径丢失、合法身份替换、非法登记、并发占用、真实系统发布失败、预期身份错配的回归。审查发现的发布未知状态复用和身份检查时序问题已修复；两名子代理交叉指出的过期插件批准问题也已修复。

上述插件模块尚未构成主应用生产插件管理：登记批准须进入真实 Connection 的授权上限，禁用／升级须停止或撤销已有实例；UI 包注册、Flutter 在线控件、跨视图调度和持久状态／内容提交尚未接入。
