# 编辑保存期间的新草稿共存

日期：2026-09-23。基线 `ddd9cc8eec224af51f4e58654c9b297332147d96`，当前为本地未提交工作树。应用 `0.1.9-test.54+58`、第一方插件 `0.1.9-test.54.3` 不变。未提交、推送或发布。

## 行为与身份

编辑窗口同时保留已确认基线、当前文本/选区/输入法组合区、编辑代次、固定提交提案 S1 和结果。S1 等待保存或结果未知时允许继续普通文字输入、类别调整及附件移除。再次核对仍提交同一个 S1 对象与固定原操作，新的 S2 不会混入该请求；S2 标题暂时为空也不妨碍先核对原 S1。

S1 确认后，若用户已经继续编辑，窗口保留 S2 并在 S1 的精确确认修订打开新的编辑会话。此时不会自动保存 S2；用户再次明确保存才会提交。V2 保留 TaskId 与三态待办，旧格式走自己的兼容编辑路径。外部修订变化、已删除内容、异库返回或历史回执不允许静默重新定基。后续会话打开失败时保留已确认结果和新输入，继续操作只重试打开，不重复 S1 保存。

旧格式的原保存重试与后续会话打开之间增加互斥门禁，避免迟到的同一 S1 结果替换正在核对的确认对象。新旧适配器均在后续会话可用后退出原会话；失败或切库时关闭未交付的后续会话。

## 附件继承

S1 中仍被 S2 选中的本地附件，按固定提案的顺序及名称、种类、精确字节数核对后替换为 S1 已入库的附件引用。已入库附件也可能拥有本地预览文件，是否入库由插件附件 ID 判定，不由预览文件的 local 标记判定。S2 已移除的附件不重新加入，S2 新附件不被旧结果覆盖。

正文中指向这些旧本地附件的精确链接改为已确认附件 ID，同时换算 UTF-16 选区与输入法组合区，保留方向、亲和性和无效选区。含糊别名或不匹配元数据拒绝应用。后续会话已经打开后若别名校验失败，窗口保留该会话；用户修正文案后复用它继续，避免重新使用已关闭的 S1 编辑器或泄漏新会话。

## 保留的缺口

本轮只解决同一编辑窗口中的 S1/S2 共存，不宣称完成 T37–T39 的全部持久恢复。S1 已形成的 V2 提交提案沿已有持久恢复记录处理；新 S2、尚未保存的输入和选区尚未跨进程恢复。旧格式编辑没有同等的持久 S1 恢复链。

S1 未核对期间，依赖捕获会话的富剪贴板转换与新附件导入仍暂停；普通文字输入不被锁住。不把旧捕获票据转成普通字符串来绕过来源核验。

后续会话因外部修订变化拒绝时，目前显示继续编辑失败并保留本窗口草稿，尚无逐字段冲突合并界面。诊断关联、统一错误信封、语言/字体在途提案、正式迁移入口和其他平台资格仍为独立任务。

后续进展见[宿主持久草稿记录](editor-draft-journal-2026-09-23.md)：Rust 底座和真实进程恢复已验证，应用自动保存与恢复接线仍待完成。

## 下一阶段：独立的持久草稿记录

1. 草稿由宿主持有，绑定资料库、卡片、草稿身份、代次以及前驱 S1 操作/摘要/精确投影修订，采用代次 CAS；不能复用唯一的 S1 提交恢复槽，也不作为正式卡片写入。
2. 保存五个原始文本编辑值（包括空值、选区和组合区）、有序附件元数据与精确 blob 引用；草稿及引用原子确认。只有已确认代次可以声称跨重启保留，防抖期间的新输入仍须明确区分。
3. 来源证据必须由宿主生成并绑定原包摘要、捕获观察和插入事件。已有内存捕获 scope 受连接、包和时限约束，重启不能直接复活 scope ID 或接受 UI 自造票据。
4. 重新打开先只读恢复；经当前授权与版本核验后重建会话。S1 确认值、当前内容和 S2 进行三方比较；冲突需明确处理，不自动发送 S2。
5. 字节/槽位预算同时计入附件和证据；S1 确认或复用槽位不能使 S2 唯一引用失效。历史审计保留与活动草稿预算分开核算。
6. 验证需覆盖实际重启、S1 回执丢失与 S2 新输入并存、保存期间继续输入、附件原件删除、包/权限变化、损坏证据和容量边界；纯 Widget 保活或假后端测试不能替代这些条件。

### 代码复核后必须加入的持久化约束

- 当前 `Store::import` 的 blob 写入与编辑会话中的 staged 归属分开，后者保存在内存；重启后单凭附件 ID 不足以证明归属。草稿提交须从当前卡片、精确 S1 投影/恢复证据或宿主持有的草稿暂存中解析附件，验证摘要、长度、名称/种类，并在草稿提交中绑定 blob。继承关系须有可持久化的来源/位置及别名，不能依赖本轮仅适用于单窗口的 Dart 对象身份。
- 草稿每一代都走普通卡片审计会产生历史 blob 引用；解除当前绑定不等于释放历史占用。需先确定与审计一致的保留/压缩策略，不能宣称槽位或活动字节配额解决了长期磁盘增长。
- 当前编辑代次只检测文字与组合输入，选区单独移动不触发业务提交代次。持久草稿需独立的完整编辑值代次，覆盖只移动选区的变化；不得为了恢复选区而制造新的内容提交。
- 捕获编辑快照现只包含五段文本与别名，scope 中的票据/观察/事件属于内存状态。持久来源片段必须由宿主从有效票据导出实际观察、父链和插入应用，绑定原包与草稿快照；重启后不能接受客户端重新声明这些票据仍有效。来源尚未持久确认或 scope 已失效时，可以恢复原始草稿文字，但必须明确缺少来源证明，不能标为已核验转换。
