# Versioned workspace UI integration plan (2026-09-23)

Status: static code review and integration plan only. No UI wiring or runtime migration acceptance is claimed here. The format-2 normal-reopen failure path below follows directly from the current call chain, but has not yet been reproduced by a running desktop application. This round is preparing the versioned scan in RustWorkbench.loadVersioned; the existing Studio UI has not switched to that scan. Do not expose a migration button until the mixed-format UI and the acceptance gates below are complete.

## Current blocking path

- lib/plugins/workbench_native.dart: RustWorkbench.open probes Action.pageVersioned with limit 1. This proves only that the private route responds.
- lib/plugins/studio_storage.dart: RustStudioStorage.open subsequently calls backend.load(). lib/main_rust.dart waits for this storage initialization before runApp.
- lib/plugins/workbench_native.dart: load() still calls old Action.page, then old Action.read for each ID.
- workbench_host/src/lib.rs: WorkbenchState::page calls Self::decode on every org.morrow.idea Card; Self::decode accepts format 1 only. Thus a page containing a format-2 idea fails instead of returning mixed content. The expected user-visible consequence is startup recovery rather than a usable workspace. This is a static inference, not a measured desktop result.
- The same old Action.read and V1 query path cannot project a format-2 Card. workbench_host/src/query_source.rs explicitly calls WorkbenchState::decode for query candidates; a mixed-library query through the old route fails.

## Target boundary and implementation order

1. Complete and validate the host scan before changing navigation. RustWorkbench.loadVersioned should walk pageVersioned and readVersioned, preserve ID order and unsigned u64 revisions, include both supported formats, omit deleted cards from the visible list, and reconcile IDs learned from concurrent operations before publishing. The initial RustStudioStorage.open load and later editor refresh must use this scan. Read-only operation must still show existing V1/V2 content when the business plugin is disabled. Keep old load/read for V1 compatibility callers only; do not have the mixed workspace invoke them.
2. Keep the two content meanings explicit in Studio state. A small sealed workspace entry or equivalent should hold either legacy Idea or VersionedContentRecord, keyed by stable Card ID. Format-2 tasks, origin, retired IDs, stage and completion counters must remain typed; never synthesize Idea.todos/completed or send a V2 record through Idea.toJson/fromJson. RustStudioStorage.write and _StudioState.snapshot/persist are UI preference snapshots, not content authority: do not serialize a format-2 Card as a legacy idea. On reopen, authoritative Card state comes from the versioned scan. Preserve the existing V1/local-storage route for non-Rust workspaces.
3. Route mixed queries through VersionedContentControl.query in lib/plugins/versioned_content.dart. lib/plugins/query_coordinator.dart currently calls WorkbenchBackend.query; select the versioned capability for the mixed native backend while retaining the same fixed operation across all returned pages and the existing terminal-versus-unknown failure distinction. _StudioState.pluginProjection, visibleIdeas and _calculateVisibleIdeas should consume IDs against the mixed entry map. When the plugin is unavailable, local display filtering may be used, but its V2 rules must use explicit stage and incomplete + legacyAmbiguous counts; it must not be presented as a guest query. Preserve stable recent order and list identity across refreshes.
4. Convert all display consumers in lib/main.dart and lib/pages/workspace_pages.dart to the mixed entry. The common title, description, category, favorite, icon, color and asset summary may share a view adapter. A format-2 project displays the explicit stage/projectedStage, completeCount, incompleteCount and ambiguousCount; progress must not use text membership or infer completion from the stage. Display each task by TaskId, even when labels repeat; show legacyAmbiguous as unresolved rather than silently checked or unchecked. Preserve the separate V1 interpretation for legacy cards. A format-2 asset has metadata only; provide a format-aware attachment display/export adapter using the existing host ExportFile Card/attachment-ID route, rather than pretending it is a cached IdeaAttachment.
5. Split mutations at the UI boundary. Legacy cards retain WorkbenchBackend.apply and WorkbenchEditorSupport. V2 common text and selected attachments use WorkbenchVersionedEditorSupport.openVersionedEditor plus VersionedEditorSession.save; V2 tasks use VersionedContentControl.editTasks; V2 favorite, category, delete and restore use editCard. A typed mutation returns a historical receipt and a separately refreshed current record. Publish only current under a monotonic revision fence, and remove a card only when current.deleted is true. Freeze operation ID, source revision, command, task IDs and payload for an uncertain retry. Generic Retry after a transport-unknown or committed-refresh failure should read current or retry the exact original intent, never generate a fresh business operation.
6. Add the V1-to-V2 migration affordance only after the mixed view and all V2 actions below work. Use planMigration then migrate with the fixed plan operation and source revision. Show the resulting origin and TaskId mapping without treating duplicate legacy text as distinct proven completion. A migration receipt must be followed by the authoritative current read, including when another later operation already advanced the Card.

## Acceptance gates before enabling migration in the main UI

- Runtime desktop reopen: V1-only, V2-only and mixed stores must enter Studio; repeat with plugin disabled/read-only and with a page boundary over 128 IDs. Confirm a migrated V2 Card is visible after a full process restart. A static analyzer or a pageVersioned probe alone is insufficient.
- Mixed query: overview/section, stage, pending, attachment, favorite, text and all sorts return both formats in host order; duplicate or missing IDs are not silently ignored; query pagination preserves one operation. Test a plugin-disabled local fallback separately.
- TaskId UI: two identical labels can have distinct completion states and are toggled independently by ID; legacyAmbiguous is visible and counts as unresolved; rename, reorder, add, remove, setStage and completeAllAndSetStage preserve other IDs, origin and unrelated Card fields. Choosing a completed stage must not implicitly complete tasks unless that explicit command was selected.
- V2 card actions: common-field captured edit with paste and staged attachment, favorite/category, delete and 8-second restore all use typed routes; exported attachments match selected ID/name/bytes. A V1 editor path must reject V2 instead of silently modifying it.
- Late and failed replies: after commit, show current rather than the historical receipt Card; a late older read cannot roll back a newer revision or resurrect a deletion. Inject an unknown transport result and a confirmed-commit refresh failure; neither generic retry starts a new effect. Verify a later current revision survives historical retry.
- Workspace identity and persistence: switching backend while read/query/scan is in flight cannot publish the old workspace's cards or preference snapshot. No format-2 TaskId/origin state appears in legacy Idea JSON. Verify high-bit u64 revisions remain ordered exactly.

This report does not claim the UI, migration entry or these acceptance tests have been completed.
