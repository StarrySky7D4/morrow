基于当前脏工作树推进，主应用仍为 `0.1.9-test.54+58`。第一方插件因新增实际 Wasm 代码与声明升为 `0.1.9-test.54.1`，旧库继续遵守已有的新包摘要审批规则，没有自动继承旧批准。

## 已实现

- `tasks_v2.proto` 独立定义任务 ID、文字、完成状态、退役 ID 和迁移来源；V1 的文字待办字段没有原地改义。
- 每项任务按 TaskId 修改。改名、重排与阶段切换互不修改完成状态；批量完成并切换阶段使用单独命令。插件返回阶段与三类计数，UI 不需要推断权威业务状态。
- 同名且在旧 completed 中出现的任务标为 `LegacyAmbiguous`；未完成的同名项仍未完成。已确认完成、未完成、待确认分别计数。
- 迁移身份绑定卡片 ID、原修订、源 Properties 摘要、迁移器命名空间和原下标；迁移操作 ID 同样确定。基线变化和修订耗尽都拒绝；重排或改名不会重算任务身份。
- 原始 Properties 字节、未知字段、原始标题、映射顺序与旧程序计算出的阶段单独保留。旧字段保留在其原命名空间内，不将未知 V1 字段擅自解释为 V2 字段。
- 后续更新按 Protobuf 字段保留未修改字节；任务内与顶层未知字段均有回归。新增 TaskId 由宿主作为固定命令参数提供，不能复用当前、已退役或迁移来源中的身份。
- 维持 64 KiB 正文与插件值边界；原件和映射也计入容量，超限返回失败，不截断或去重。任务上限 128，退役身份还有独立数量和正文容量限制。
- 独立 Cap’n Proto `tasks.capnp` 和 `workbench.tasks.v2` 处理器覆盖迁移、完成、改名、重排、阶段、显式复合操作、新增、移除与只读投影；Rust 与 Dart 绑定使用同源 schema。

## 验证与边界

插件原生回归共 **20 项通过**，其中 V2 新增 **7 项**。覆盖确定迁移、源修订/摘要变化、重复项歧义、原件保留、未知字段、旧 codec 拒绝 V2、容量拒绝、相邻高位 u64、非法命令和连续操作后完整文档再验证。

实际 Rust Wasm 资格测试使用原有默认预算：20,000,000 fuel、16 MiB 内存。对 2 项及 128 项短文本同名待办样本执行迁移和任务操作，并以实际捕获的证据重新运行同一个归档 guest。源 Card 在整个纯执行过程中保持原字节和修订，旧基线请求被 guest 拒绝。

早期 128 项阶段切换超出 20M fuel；移除重复来源核验、反复摘要字符串分配和整份反射文档展开后，阶段切换降至约 7.56M fuel，未放宽预算。这是执行预算测量，不是 UI 帧耗时或通用吞吐保证；长文本/附件组合仍可能触及现有消息容量，必须拒绝而非截断。
