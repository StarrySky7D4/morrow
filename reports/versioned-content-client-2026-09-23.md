# V1/V2 私有客户端协议与原生接线

本轮继续核验深度复核 v1.2，新增格式感知的 Flutter→宿主私有内容通道。应用保留 `0.1.9-test.54+58`，第一方 Wasm 包保留 `0.1.9-test.54.3`。修改位于未提交工作树，不代表远端或发行包已更新。

## 实现范围

- 在既有私有宿主消息后追加读取、分页、迁移计划、迁移、TaskId 编辑、普通卡片编辑及混合查询七个动作。公开插件 ABI、被冻结的 V1 规则、TaskId 迁移及重放投影不变。
- 新增 `content_api.capnp` 与生成的 Dart 绑定；外层 ID、operation、源修订为调用身份，源正文、授权和执行观察继续由原内容库 owner 获取。
- 原生启动探测使用格式感知分页，避免首条内容已经迁移时仍走 V1 解码。无插件情况下可枚举并读取已有 V2 内容。
- Flutter 的类型化记录保留格式版本、稳定 TaskId、歧义状态、来源映射、原始来源字节和退休 TaskId。修订和附件长度用 BigInt 保留完整 UInt64。
- 提交回执描述历史操作；成功提交后另读当前记录再交付。已知修订单调递增，旧操作重试不能把当前界面退回历史内容。提交已确认但回读失败单独报告，并保留回执。
- 混合查询以原 operation 分页交付固定结果，续页绑定查询条件与操作。限制回复字节大小，避免大结果成功执行却无法交付；续页不重新执行 guest。
- 当前普通内容通道拒绝不完整的编辑器捕获元数据，不把未接通的 V2 粘贴来源支持默认为已完成。

真实故障测试使用仅测试用转发器，保留实际 host/guest 执行，把已提交操作后的第一条读取回复替换为合法错误。客户端保留确切回执与已知修订；随后只以同一个 operation 核对，历史重试没有建立第二个业务修改。分页测试在完成首个查询后新增一张卡，旧 operation 仍交付原 129 项，新 operation 才包含第 130 项。

查询续页只接受既有 Ready 操作；limit 与可知 offset 边界在执行前拒绝，后续仍重新核验条件和当前权限。游标依据规范化查询条件生成，合法 Cap’n Proto 内存布局差异不改变查询身份。私有协议不以跨语言分配布局相同作为合法条件。

最终构建前，13 个既有引擎、迁移/编辑投影和新旧查询实现与上一轮构建摘要一致；没有重新解释历史记录。初次 Dart 分析曾因 Windows 性能临时文件清理失败退出，后续 Flutter 分析已正常完成；该环境故障不计为代码通过证据。

## 仍未完成

主工作台继续使用现有 V1 界面，本轮没有开放迁移按钮，也没有自动迁移用户内容。V2 编辑器的粘贴来源、TaskId 与同名项歧义确认界面、完整保存恢复和错误协议仍需接通。私有协议可用不等于插件 SDK 冻结；没有新增 Android、Web 或其他原生平台资格验收。

后续进展：[V2 捕获编辑保存](captured-cards-editor-2026-09-23.md)已接通普通字段及附件的编辑来源。上节为本报告当轮边界；主 UI 与跨重启编辑恢复仍未完成。
