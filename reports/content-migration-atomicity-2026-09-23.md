# Card 格式迁移：核心原子事务核验

本轮接通的是核心迁移事务，不是工作台用户卡片的自动升级。应用继续使用 V1；旧写入者防护、实际 TaskId 迁移的宿主证据投影、Flutter 入口仍待接入。不得据此将 T31–T34 全部关闭。

## 修改

- 新增 `ContentMigration` 和持久化 `MigrateContent` 命令；新动作只接受 Command schema 2，原命令继续使用 schema 1。历史 SetContent 的含义及旧投影未改写。旧命令用冻结的 v1 解码形状读取，原先未知的字段 7 即使内容不是合法新消息，也不能被重新解释成迁移动作；新增反例回归覆盖此边界。
- 固定保存完整源 Card 原字节。提交时必须与库内当前原件完全相同，因而同时绑定身份、类型、格式、修订、正文、未知字段和关联；过期源不能自动重新定基。
- 目标格式只能向前变化。格式、正文和预览作为一次修订提交，保留标题、附件、关系、创建时间和未知字段。修订溢出及完整目标记录超限均拒绝。
- 使用现有核心事务一次保存卡片、操作回执、事件、附件引用及任务证据。入事务和提交前均核验连接、内容编辑授权及宿主补充条件。
- 同一操作与同一证据重试返回原回执；后续卡片变化不被历史重试覆盖。相同操作却换正文或证据会冲突；跨重开读取和重试仍使用原命令。
- 新命令保存的完整源、目标正文和格式足以独立重建目标 Card，回执解析会核对完整结果摘要与附件摘要。不能用一份合法目标散列掩盖类型、标题、格式或未知字段的错误变动。
- 源原件、目标正文和证据均计入既有容量限制；没有增加协议上限、截断内容或跳过证据保存。通用核心只校验迁移事务，具体迁移算法及来源证据的业务一致性仍由后续宿主投影确认。

## 验证

`core/tests/content_migrations.rs` 五项测试覆盖：

1. 附件可导出，关联/创建时间/外层及预览未知字段保留；后续升级、相同操作重试和数据库重开保留原证据；回执交付仍需要两次授权核验。
2. 卡片身份、类型、格式、正文、未知字段或修订变化均拒绝基线迁移；相邻高位修订精确处理；`u64::MAX` 不能递增；并发编辑不被迁移覆盖。
3. 缺少授权、连接撤销、提交前过期及附加条件拒绝均不留下迁移内容/操作/证据。
4. 事件容量、证据条目容量、完整 Card 容量不足时原件完整；在已经进入写入流程后注入证据引用写入失败，所有变更回滚且不残留无主证据。同一操作在已确认回滚后可以重新提交。
5. 新旧命令版本不可混用；降格迁移及不对应命令的结果拒绝。

另有核心单元测试使用 SQLite `max_page_count` 实际产生 `StorageFull`，确认目标格式、正文、操作与事件都不部分落盘。证据引用失败测试使用临时数据库触发器模拟存储失败，不能称为真实磁盘耗尽发生在证据页。

核心库及关联回归共 **59 通过、1 个子进程夹具按设计忽略**；该夹具由父测试调用。证据存储测试使用合成观察，不冒充 Rust Wasm 的迁移语义测试；实际 guest 的独立执行资格见 [TaskId 引擎报告](tasks-v2-engine-2026-09-23.md)。

宿主相关 **25 项通过**：旧捕获投影 12、旧内容投影 8、偏好提案 4、实际 TaskId Wasm 执行/独立重放 1。Windows Release 重建后，真实客户端/宿主组合 **9 项通过**。核心 `wasm32-unknown-unknown` 编译检查通过；不是浏览器存储或 Web 整包的运行验收。既有未使用代码告警仍存在，未把编译成功描述为零告警。
