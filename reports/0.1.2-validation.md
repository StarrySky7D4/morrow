## Native accessibility investigation

Earlier builds crashed twice while checking scrolling/automatic song changes. Windows Application events at 13:46–13:47 and 13:57 identified `flutter_windows.dll+0x3e735`. Resolving the installed Release PDB maps this to `flutter::FlutterPlatformNodeDelegate::ChildAtIndex+0x3f`. This locates the crash in the native accessibility bridge; it does not independently establish the complete trigger.

Mitigations: keep a stable semantics node for crossfading tips/lyrics, notify playback position only when the visible second or lyric changes, retain the footer toggle and lyric hint across song changes, and avoid replacing the play icon subtree. Accessibility remains enabled.

The final Windows run started at 14:06:55. It ran for over three minutes with repeated automatic song changes, video playback, scrolling, lyrics and native accessibility reads. No new daemon Application crash events were recorded during this run. This is a bounded smoke check, not proof that the underlying Flutter engine issue cannot recur.
