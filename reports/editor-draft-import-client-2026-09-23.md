# 持久附件导入的私有协议与客户端会话

日期：2026-09-23。本地工作树基于 ddd9cc8eec224af51f4e58654c9b297332147d96；应用仍为 0.1.9-test.54+58，第一方插件仍为 0.1.9-test.54.3。未提交、推送、发布或修改公共插件 SDK。

## 本轮结果

宿主持久导入已经接入独立 editor_draft_staging_api.capnp 和 Dart 原生适配。新增登记、完成、检查、列举、导出、放弃与清理七个私有动作（102–108）；宿主/应用需成对使用当前私有协议摘要。旧正文草稿协议摘要和兼容导入动作保持原语义，新接口显式区分主草稿代次与暂存记录修订。

导入请求冻结卡片、草稿、原操作、基线代次、名称、类别、长度和 SHA-256。路径仅作为本次传输入口，不进入提案身份。完成导入先检查原记录：Ready/Retired 直接回原关联和当前状态；Pending 已保留字节时用原 Snapshot 完成确认，不打开路径；仅确实缺少字节时才读取选定文件并验证。

宿主回执包含原请求、逻辑附件身份、阶段、当前可选/保留状态，以及主草稿和暂存上下文。请求最多 64 KiB；回执最多 8 MiB，以不超过 32 KiB 的分块读取。客户端逐块校验 token、offset、长度、SHA 和主草稿代次，解码后再核对内外身份，拒绝改变原提案的回执。

新旧草稿适配器共用整段传输队列，而不只是逐条 RPC 排队。已知的请求关联号在副作用前登记，首次回执丢失仍能精确清理本次回复缓冲；旧 Abort 不清理新回复，也不撤销业务。Inspect/List/Export 可只读访问，Begin/Complete/Abandon/Reconcile 仍受可写门禁约束。

导出不覆盖已有文件。目标不存在时独占创建；丢回执后目标已存在，只有普通文件且长度/SHA 与原导入字节一致才确认已落盘。不匹配时拒绝，保留原文件；写入失败后不按路径盲删可能被其他主体替换的目标。

## 独立 Dart 会话与 Unknown

新增模型、编解码、native 适配和 EditorDraftImportSession。请求深度冻结摘要，u64 用 BigInt 精确表达；本地无效身份、未配对代理项、超限和非法放弃操作在发送前拒绝。

进入可能产生宿主效果的调用后，EOF、异常回执及错误关联保留 Unknown 和原导入/放弃意图。检查不自动补发；Pending/absent 不擅自清除旧 Unknown。精确重试过程中，即使后来一次请求本地未发出，也不能把早先 Unknown 改写成确定未提交。存在待决放弃时，禁止绕回旧导入；只能检查或重试原放弃。切库、销毁后到达的旧回执不更新会话确认状态。

**本轮没有实现应用重启后的完整会话持久恢复。** 宿主已落账的导入提案可通过 List/Inspect 找回，并由调用方重新构建会话；但尚未落账的请求、内存中的待决动作以及原 abandonOperation/currentGeneration 没有新增上层持久恢复入口。Retired 只说明当前不可选，不能证明是某个特定显式放弃操作提交。真实客户端重开测试保留调用方原意图再重开宿主，不冒充 Flutter 进程被关闭后自动找回所有操作。
