## 实际工作台变化

原生 Manager 独占插件注册表，以已批准能力为实际 Connection 上限。即使包声明了某项能力，未获批准也不能经该连接发放对应对象授权。停用、升级、批准变更和移除在持久发布前撤销旧实例；发布失败后保留原登记意图，但旧实例不可复活。过期修订或摘要在撤权前拒绝，不误停有效实例。正常关闭释放核心实例记录，Manager Drop 撤权，已提交内容不因后续取消或 guest Trap 回滚。

设置页新增「工作台插件」组件，沿用主题材质，并列入「组件与卡片 · 独立设置」。启用确认以修订和包摘要为依据；新包升级默认停用。仅在全新注册表首次安装随应用提供的工作台包时，采用明确的第一方安装策略，批准 CreateContent／EditContent／ReadContent 三项声明内能力；后续升级不沿用自动启用策略。这不是任意第三方包自动安装／批准。

插件状态与不可变包放在活动库登记根的 `plugin-manager`，恢复较旧内容库仍沿用当前工作台策略，不从快照自动恢复旧批准。显式独立数据库模式使用其父目录。包损坏、注册表损坏、回退旧包或准备失败时保留资料读取；不清空注册表，也不为失败的版本选择创建替代内容库。Page／Read／附件导出不要求插件，Query 是插件业务筛选，停用后拒绝，Flutter 只读浏览使用现有本地投影。

内容可写状态同时要求完整工作台批准、有效连接及维护正常。创建、修改、配置保存和附件导入共用写前检查。维护失败准确返回只读，设置「刷新状态」可在故障解除后重试有界维护；不会隐式重连被撤销的实例。

## 在线 UI 接线

Flutter 的 PluginUiController／ManagedPluginForm 通过真实 RustWorkbench 私有 Cap’n Proto 传输接到 InlineUi。后者在独立原生宿主进程中借用同一个 Storage／HostRuntime，以纯转换执行真实 Wasm；不打开第二份内容库，也不在 Flutter 绘制线程执行 guest。

新增两个固定 UI 处理器和「文字工具」入口，输入得到大写预览及字符数。表单只保存本次输入，不写卡片；关闭释放会话，重开获得新 generation。文档与事件受固定协议和大小上限约束；视图、连接身份、代次、修订、动作和序号都由宿主检查。旧视图关闭／事件不影响新视图，停用清除当前表单。

Flutter 单事件在途，忙时仅合并同节点最新文本，离散按钮不排队。IME 组合输入和失败草稿保留，迟到结果丢弃，结果未知不自动重试。明确拒绝不消费序号，接纳后的执行失败消费序号但不增加文档修订。纯 UI 输出不是内容提交回执。
