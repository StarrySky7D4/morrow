# 真实宿主启动回执损坏与丢失验证

2026-09-21；基线 `2927a24`，版本仍 `0.1.9-test.52+56`。结论 **PASS_SCOPED**。仅修改测试及夹具，不更改生产协议、Rust/Dart实现或SDK。

## 实际注入边界

测试启动独立Python管道代理，再由代理启动原Windows Release Rust宿主及原工作台插件。所有准备、准入、监听、HTTP和工作台命令仍由原宿主完成。代理使用测试预先计算的完整启动帧摘要匹配目标；只有在收到原宿主完整响应之后才注入一次故障。原始启动响应只存入新建测试目录，匹配/注入/实际子进程退出记录只含元数据，最终由夹具清理。

两条路径均通过：

1. **响应损坏、管道仍可用**：替换真实启动响应为一字节非法载荷。页面会话保留原submission及Unknown；核实前普通业务被阻止，重复启动不外发。只读刷新从原宿主找回相同task/submission；实际服务继续处理HTTP 202，原工作台可保存/读取语言。停止后等待实际回收，按原任务确认退出。
2. **响应丢失、管道EOF**：消费但不交付真实启动响应，关闭原宿主stdin，等待其实际退出，代理才退出。调用方保留Unknown和原submission，不能因管道消失而归档为未执行或自动再启动。验证实际子进程退出码0、后续HTTP连接拒绝，以及同一受保护内容库可以重新打开、原设置保留并可继续写入。重新打开不会恢复旧服务权限或自动启动；旧会话仍保留Unknown。

两条路径均确认目标启动帧只匹配一次、故障只注入一次。第一条在真实HTTP成功后才停止；第二条证明启动已准入但不假定EOF前监听已成功绑定。没有使用模拟服务快照来替代实际Rust行为。

## 辅助编码与主代理审核

SubagentBridge通过统一部署CLI实际调用 `glm-5.3-flash`、`max` 一次，生成Python代理候选。审核发现它先读响应再转发请求会死锁，且只在进程启动时读取注入配置，无法在准备完成后注入；原候选还允许零长度帧且未正确累积短header。主代理修正读写顺序、按请求读取注入配置、精确读取及帧长门槛，再编写并运行Dart实际宿主测试。未修改供应商配置、未购买额度、未自动重试调用。
