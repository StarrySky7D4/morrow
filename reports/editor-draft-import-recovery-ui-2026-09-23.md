# 工作台附件决定恢复入口与编辑状态保护

日期：2026-09-23。应用仍为 0.1.9-test.54+58，第一方插件仍为 0.1.9-test.54.3；本地未提交、推送或发布。此阶段接入附件放弃决定恢复 UI，正式编辑器的正文/附件自动保存仍未启用。

## 用户可用入口

工作台已有历史按钮在宿主同时支持两种恢复时显示菜单：既有编辑保存恢复，以及附件放弃决定恢复。复用同一按钮，不额外占用窄屏横向位置；仅支持一种能力的后端保留单入口。

打开附件决定页只读扫描宿主记录，包括已丢弃草稿留下的决定。显示附件名称和通俗状态，不展示操作号、修订或内部记录。Pending 允许明确重试原放弃或取消；Conflict 只能取消原请求；已完成与已取消只展示。只读内容库不提供写动作。

每次操作前重新检查完整原请求、原操作身份和基线。取消需要确认，确认文案说明原放弃请求不再执行；取消本身不删除附件，也不撤销其他修改。状态文案不承诺附件仍存在，因为它可能因其他已确认操作被清理。关闭仅退出查看，不自动重试、取消或清理业务。

九种语言均增加对应文案，沿用外置语言目录和生成流程。新增翻译未经过母语审校。

## 串行发现与结果分类

新增 `discoverDecisions()`，在同一个共享草稿通信作业中扫描全部全局范围和各范围的分页决定。页内使用不重新加锁的内部方法；同一 Workbench 的草稿、Prepare、Cancel、Abandon 无法插入页间。配合原有单库 owner，这补齐上一报告中的恢复扫描并发缺口；不宣称底层独立分页 API 本身提供任意多写者数据库快照。

扫描检查重复范围/操作、空非末页、不前进游标和最多 256 条身份，结果不可变。真实宿主测试构造同范围 33 条决定以跨过每页 32 条边界，同时排入新 Prepare：第一轮含 34 条旧决定且不含新操作，之后第二轮含 35 条；另一失活范围仍可发现。

协调器防重入、工作区更换和销毁后的迟到发布。已收到操作成功回执，但随后只读刷新失败时，以独立的已确认刷新失败结果保留回执，不再误报业务结果未知。界面明确提示操作已确认，禁用陈旧行的重试/取消，保留手动刷新；只有刷新成功才解除封禁。真正未确认的传输失败仍保留原操作，不生成替代操作。

成功操作已由协调器刷新，界面直接采用结果，不再重复扫描一次。

## 原编辑器修补

原 NewIdeaDialog 仅将文本和输入法组合变化计入在途 S2，忽略选区、亲和性和方向变化。现改为比较完整 TextEditingValue；S1 回执到达前仅调整这些状态，也会保留编辑器和当前值，不自动关闭或提交后继。原先完全未变的 S1 仍正常关闭。

这只是当前窗口的编辑状态修补。S1→S2 的持久来源交接、附件 provenance、富捕获票据及关闭时未确认草稿处理没有被该修改替代。
