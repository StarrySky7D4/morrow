# test.19：Windows 工作台自动审计封存

日期：2026-09-12。应用 `0.1.9-test.19+24`，核心／审计／宿主 test.19，Rust 工作台插件 test.13、SDK／执行后端 test.11。本轮是本地开发进度，未推送、打标签或发布 test.19；test.14 已发布附件保持不变。

## 改动与行为

默认 Windows 工作台通过 Session 持有内容库、系统账户保护的随机密钥及会话锁。首次打开未绑定的实验库会验证并保留原内容后绑定；已绑定库必须沿用原身份。保护文件为数据库旁的 `workbench.db.audit-key`，密钥丢失或不匹配不生成替代身份，恢复原文件／原账户后才可继续。缺少插件时仍能读取已有内容。

启动时恢复待封存记录；创建、修改、偏好保存和附件导入前，检查待封存数量与字节数，达到 64 个事件或 8 MiB 时执行最多 16 批维护。正常关闭通过标准输入结束触发尾部封存；强制终止留下已持久化的待封存记录，重开后继续。核心 1024 条／64 MiB 的队列硬上限不变；已封存历史与原始操作保留。

维护失败单独通过私有 Cap’n Proto 响应字段传递；读取成功和维护提示可以同时存在。后续修改须先成功维护，不把本次已经成功提交的结果改判为封存失败。Flutter 启动时显示维护提示，宿主启动失败时保留有界错误文本并显示对应原因。协议新增字段并重新生成摘要／Dart 绑定，旧摘要组合拒绝。

## 实际验证

- 宿主严格 Clippy（含故障注入）通过，9 项宿主测试通过，其中包含故障子进程入口。

- 宿主实际子进程在内容提交后、封存批次后直接退出，重新打开后读回已提交内容并清空待封存余量。模拟维护失败时已有内容仍可读，新修改被拒绝；读取响应携带维护提示但没有业务错误。
- 原未绑定实验库绑定后保留内容；并发会话被拒绝；密钥缺失不改数据库、不补建身份，恢复原文件后读取成功。

## 继续推进

自动封存不代表 M4 或插件系统完成。原保护文件恢复尚无专用界面；跨账户迁移、密钥轮换、其他平台保护后端、封存历史容量管理、完整宿主审计事实、独立见证和重放继续推进。当前 Windows 宿主不在其他平台静默退回无保护存储；Web／移动应用仍保留此前路径。
