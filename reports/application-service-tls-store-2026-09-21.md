# TLS 原资料库存储、修订与撤销依赖

2026-09-21，基线 `28d8650`。本轮把已实现的受保护 TLS 封装接入原 Store；私有管理命令、界面和应用服务的受保护引用启动仍待接通。

## 完成的存储边界

数据库 Schema 从 20 升到 21，新增 `tls_identities` 严格表（引用、修订、Protobuf＋LZ4 密文封装）。迁移前后都执行完整性验证，保留既有 `service_authority_identity`、内容、审计和事件；旧 Schema 中提前出现该表视为损坏，不猜测修复。Schema 20 客户端不能打开升级后的库。测试均使用隔离临时库，没有迁移用户实际资料库。

保存读取原库身份，要求封装绑定一致；期望修订 0 只创建修订 1，替换/禁用必须精确加一，不能删除并复用引用。每库最多 128 条，密文计入原共享逻辑字节额度；替换按删除旧行后的真实用量计费。失败事务回滚数据，不产生另一数据库或明文密钥文件。

`ServiceAuthorityResource::TlsIdentity` 独立于 Configuration/Inbound/Outbound。相同原拥有者在写入前精确撤销该 TLS 引用；事务回滚或提交结果未知不能恢复已经失效的 lease。CAS 检查不通过则不撤销；其它引用及其它命名空间仍有效。独立 Store 写入被原原生授权锁拒绝。这验证的是依赖基础设施，不代表应用 TLS 监听器已经绑定该新资源。

分页按引用排序，每页 1–16 条，最多扫描 129 条检测超限；快照摘要绑定原库身份及所有记录，变更后拒绝旧游标继续。行解码核对索引与封装；列表、精确加载和完整性检查均限制密文返回大小。SQLite 一致快照保留同一身份与原始密文字节；另有真实 Windows DPAPI 解封验证，原库/快照不包含测试私钥明文。
