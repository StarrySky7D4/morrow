## 已交付

1. **原生单库事务**：卡片、操作结果、待封存事件在同一 SQLite 事务写入。固定 rusqlite 0.40.2 和 bundled SQLite，使用 WAL、synchronous=FULL、BEGIN IMMEDIATE。写锁冲突返回 StorageBusy，SQLite 容量耗尽返回 StorageFull，其他执行错误返回 Storage；COMMIT 的错误保守返回 CommitUnknown，调用方必须保留操作 ID 并查询／重试。[SQLite 同步设置](https://sqlite.org/pragma.html#pragma_synchronous)、[rusqlite 事务行为](https://docs.rs/rusqlite/0.40.2/rusqlite/enum.TransactionBehavior.html)。
2. **固定操作与去重**：保存 schema 中定义的 Protobuf 命令，重试比较完整命令字节。相同操作 ID／相同命令返回首次结果；不同命令复用 ID 拒绝。即使卡片已有后续修订、队列容量已满，首次结果仍可查得。预期修订检查禁止旧写入覆盖新内容，UInt64 修订不落入 SQLite 有符号整数列。
3. **提交前权限核对**：HostPolicy.commit_rename 消费固定请求的任务许可，在事务内及 COMMIT 前重新核对实例、对象范围、撤权、单调时钟期限和排空期限。整个调用独占同一宿主；最后核对是授权线性化点。提交同步期间的自然到期不追溯撤销已经线性化的操作，已提交内容不因后续撤权回滚。
4. **耐久待封存记录**：新增 transaction.proto 与 MORROWT1 容器；操作 ID、事件 ID、固定命令、命令摘要、结果修订与内容摘要使用 Protobuf＋LZ4。卡片继续使用 MORROWC1；SQLite 页和索引由引擎管理，Cap’n Proto 不作为业务持久化格式。命令与事件解码有长度／摘要／关联检查。
5. **容量与恢复保护**：默认待封存队列 1024 条／64 MiB，不能承接必要事件时拒绝新操作。完整性检查在同一读快照核对数据库、操作与事件原字节、当前卡片修订和内容摘要；打开时拒绝不一致、无关或未来版本数据库。查询缺失数据库不创建文件。
6. **独立 CLI**：init、create-local、rename-local、query、import-container-local、export、check；导出拒绝覆盖已有文件。无需 Flutter 可完成创建、修改、重启查询与容器导入导出。这里的 local 是可信本地操作者入口，不得直接暴露给插件。

合计 **56 项 Rust 测试**。故障向量覆盖：事务开始后、卡片写入后、操作结果写入后、事件写入后、提交前、提交后。测试版子进程通过显式 fault-injection 特性直接退出，不执行 Rust 连接析构；随后由新子进程恢复／查询／检查，再以同一操作 ID 重试两次。提交前无半笔结果，提交后可查得首次结果，不重复递增修订或追加事件。

其他测试证明事件 INSERT 故障回滚全部三类记录；SQLite max_page_count 实际触发 SQLITE_FULL 并分类为 StorageFull；并发同修订写入只有一方成功；最后授权核对发生在 SQL 写入之后时，到期／排空截止仍回滚；未知 Card 字段和 UInt64 最大修订保留。此处的进程退出、SQLite 页容量限制与错误注入，不等于真实断电、磁盘硬件故障或移动设备证据。

日志保留在 build/core-test.4/：verification.log、client-verification.log、flutter-analysis.log、flutter-tests.log。测试使用临时目录和合成内容。最终验证脚本会将存储 CLI 重建为默认特性，生产默认构建不包含故障注入行为。

## 复现

```powershell
pwsh -File tool/verify_core.ps1 -Web
pwsh -File tool/verify_core_client.ps1 -Web -Python python
```

## 未完成的边界与下一步

- **M2-03 附件事务**：暂存、哈希验证、原子引用、崩溃恢复、延迟回收尚未实现；新存储主动拒绝带附件引用的新卡片，避免接受悬挂引用。真实旧资料迁移继续等待 M5 门槛。
- **Web 持久化**：本轮 SQLite 后端只在原生编译；浏览器只验证协议往返。普通 Dart JavaScript 的生成器精确整数问题仍存在，应继续验证 Wasm 协议适配与浏览器存储的同语义故障向量。
- **传输与宿主**：现有 FFI／Worker 缓冲区入口仍仅做协议校验和往返，未开放数据库句柄或命令分派。单宿主独占保证不代替跨进程权限同步、插件隔离、操作 ID 的跨调用方作用域或读取授权。
- **其他内容操作**：工作区、草稿、视图位置及关系的正式事务尚未实现。当前查询 Absent 仅是快照，不提供耐久的“确定未执行”结论。
- **M3–M5**：插件后端、共享对象、不可变输入证据、审计封存、见证、依赖和隔离重放尚未贯通。当前 outbox 没有确认／删除入口，满后阻止新提交，不能用清空队列代替封存。
- **验收**：其他原生平台、真实断电、规模性能、完整应用接入仍待独立验证；当前打开数据库执行完整扫描，不宣称大规模启动性能已经合格。

下一阶段继续附件与浏览器事务，再推进运行期分派和插件执行；目标仍是 A→B→受控提交→审计封存→独立验证／隔离重放贯通，以及声明平台的实际验收。
