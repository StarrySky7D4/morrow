# 插件 P-02 接口审计反馈：后续宿主合同需求

日期：2026-09-28。来源：插件会话 `01a0e7b0-2b5c-7e61-a9cb-6a296054bfb1`
发来的新批次 P-02 接口审计交接。本文是宿主侧需求记录，不是实现、运行验证或
新版本合同。当前 003、唯一 Schema、原交接报告与已通过测试均保持不变。

## 当前接收边界

`host-kit-003` 可用于受限真实上游调用点到 fake 字节流、事件追加和工具 Claim
的拦截资格探针；这些局部路径不能证明完整 upstream HTTP、ThreadStore 或
ExecBackend 已适配。缺失能力必须返回结构化拒绝/Unavailable 并记录实际被
截获的调用，不得静默回退到上游原有网络、第二存储或原生执行路径。

003 的既有 14 项测试、向量和 G0-C04 最小 kit 结果继续保留；它们不填补本文缺口，
也不升级为完整 M-01/G0/生产资格。本轮只读核对 manifest 仍为
`5555751ab1cf590d68e9610dae396677b79422999ec61b7c3d3d7183e8ed4a01`。
Schema 仍为 `da0ac7a42e4b0f6aec0cfbdd2358cf86688b08e862626186bb9de4914f355a7f`。

## 后续扩展需求与验收证据

| 责任 | 插件反馈的实际缺口 | 宿主侧待设计/实现的合同 | 后续需要的证据 |
|---|---|---|---|
| M-03（关联 M-08） | Stream 无 HTTP status、headers、通用 URL 元数据 | 在固定请求与已授权目的地约束内描述 method/URL/必要请求元数据；返回响应状态、受限响应头、可信实际目的地和传输阶段；保留正文有界读取、取消、Inspect 与请求不可重复发送边界 | 真实上游 HTTP 调用被截获；正常/错误状态、Content-Type、重定向与断流可区分；收到响应头与 EOF 前片段；缺失能力时拒绝且无直接 HTTP fallback |
| M-04（关联 M-05） | Event 无 thread create/list/fork/archive/checkpoint/durable fence | 把上游 ThreadStore 需求映射为宿主通用会话/记录、受限枚举、分支来源关系、归档状态和检查点能力；定义提交/封存的持久确认点、writer 交接、游标/gap 与恢复语义；保持宿主唯一可写权威 | 每个真实上游存储调用有明确映射或拒绝；持久确认后关闭重开、重复追加、writer 替换与检查点失败的结果可核对；未持久不得报告已保存；不得创建另一份可独立继续写的上游历史 |
| M-06（关联 M-02） | Tool 无 argv 载荷获取、stdin/PTY/signal/terminate/输出字节流 | 固定意图中包含可由获准 B 领取的输入引用/字节、argv/cwd/环境及摘要；定义有界输入输出、PTY 单控制者、受控 resize/signal/terminate、独立控制额度、进程退出与输出关闭事实；始终绑定原 operation、许可和执行域 | 真实 ExecBackend 入口被截获；B 只领取已批准固定输入；重复 Claim 不启动第二次；输入变更/失效许可拒绝；输出与控制限额独立；回执丢失、未知结果、Exited 与 OutputClosed 分开核对 |

这些是候选需求，不是已有字段名、方法名或完整 API 承诺。特别是 ThreadStore
的上游名称不直接变成宿主模型专属 Schema；Morrow 存通用关系和 opaque 业务
材料，插件负责模型语义。HTTP 的认证头/秘密不进入普通事件与诊断；SSE、
Responses/Chat 解析仍归插件。Tool 的参数或 `approved` 字段不得自证权限，
A 不能因为宿主能力缺失而自行执行。Net/IO 不增加自有 DLL。

## 交接与版本策略

1. 插件提供固定源码位置、实际调用签名、最小必要输入/输出及明确拒绝回执；
   区分静态接口审计、真实调用拦截和完整适配三种证据。
2. 宿主在后续获授权实现切片中细化通用合同和错误/资源界限，仍只有
   `contracts/experimental/agent_host_v1/` 一处权威；插件不得另造相近 Schema。
3. 新增或改变 wire/语义按既定实验修订策略产生新 revision、摘要、向量和新 kit
   目录；不得原地修改 003，也不得把新增接口伪装成已协商能力。
4. 新批次源码/构建/探针证据与原插件已验收 handoff 隔离。插件所述“完整固定
   源码归档接收中”是其交接状态，本宿主会话没有据此宣布完整源码可构建或 P-02
   已运行通过。最终新批次状态交由插件和联合验收以实际回执更新。

本轮只增加本文；不重跑既有测试，不开始 M-03/M-04/M-06 后端实现，不修改
003、canonical crate、插件仓库或联合验收目录。
