## 本轮实现

生产 host 增加 `--sdk-capabilities`：在 owner、DB、worker 或监听之前返回只读 descriptor，包含实际编译的 ABI/合同版本与 SHA、字节上限、默认预算及路线约束。普通 Runtime 的 content/transform/依赖能力与 Workbench external_transform/external_ui 的限制分别呈现。当前 Workbench 不支持外部 content task、dependency calls 或 required dependencies；descriptor 不是权限授予或包准入。

开发工具增加 `morrow_plugin.py profiles --host EXE`，只执行显式可信程序，绑定可执行文件与原响应 SHA，拒绝坏字段/类型/摘要/重复 JSON 键，限制 stdout/stderr 各64KiB及等待。没有 guest 内动态 discovery 或多版本自动回退。生产修改位于 `workbench_host/src/sdk_profiles.rs`、`lib.rs`、`main.rs`、`tool/sdk_profiles.py`、`tool/morrow_plugin.py`。

测试修改独立列出：runtime owner test fixture 补齐已有 `mutation_history:false`；新增 `sdk_future_extensions.rs` 三项真实 Package/Runner 准入与隔离测试；新增 profile 工具测试；修正 Windows SDK lock CLI test fixture 的子进程/捕获 UTF8，并要求成功 stdout 包含实际 locked/verified。这些不改变生产授权、业务 gate、预算或清理证明。

## 未来扩展与冻结条件

[26项能力矩阵](../../docs/PLUGIN_SDK_CAPABILITY_MATRIX.md)与[接口扩展规则](../../docs/PLUGIN_SDK_EXTENSION_CONTRACT.md)逐项区分真实API、authority/call path、证据和缺口。当前 ABI2/runtime7/task3/UI1/dependency1 可分别保持原字节与语义；新 mandatory feature、独立schema/import及decoder/Runner/host route可在旁增加。旧host显式拒绝新必需功能，未知可选元数据保留不赋权；当前无法从任意业务bytes自动检测漏报需求。未来设计必须在实际受限route强制feature/schema匹配。

基础 ABI 的兼容资格与完整目标 SDK 的充分性是不同门槛。公共 stream/SSE/WS、event subscription/Cloud cursor、blob transfer、async dependency/组合profile、native exec的对应共享授权与生命周期合同尚需真实实现、三语言codec/所有权、broker/Runner、生产接入和故障回归；Markdown字段要求和negative fixture不能替代这些。私有M03监督证明和private content_api也不能宣称公开SDK已支持。无需先获取Codex/CC原源码才能开发这些共享能力，当前无新系统组件/权限架构批准阻塞。

## 仍未验收

跨平台实现/恶意同用户隔离/实际断电/成功的真实OS非零部分write completion没有本机证明；原Windows Unsupported/Unavailable保持。ABI1执行路径存在但无冻结旧ABI1原件；不承诺Rust源级SemVer或native C/C++ DLL/STL ABI。原始ZIPdelivery-receipt只记录relay timeout，未证明Drive备份交付，未重复上传。具体供应商/CC/Codex实现仍暂停。全产品G0/人工系统选择器与所有用户旅程未完成，focused checks不称全面验收。
