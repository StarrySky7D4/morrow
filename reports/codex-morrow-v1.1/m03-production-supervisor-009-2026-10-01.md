The supervisor owns Job/process/thread/stdin/stdout/stderr handles. Only the child's three stdio handles are inherited. The ordinary untrusted guest retains the existing three-key SystemRoot/WINDIR/COMSPEC environment allowlist. The trusted production business host additionally receives LOCALAPPDATA from native SHGetKnownFolderPath for the current user, rather than trusting a caller-supplied environment override; its existing Core service authority store requires that path. This grants no new token, credential or security permission. The native output allocation is guarded immediately and freed with CoTaskMemFree on both success and failure, as required by [Microsoft's API contract](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderpath). Flutter holds its original private Capnp business channel inside a bounded multiplexed transport, validates profile/incarnation/generation/actual supervisor PID and both artifact hashes, and reports the independently typed supervision status. Heartbeats support controller liveness only and never renew a business grant.

## Gate, shutdown and owner contract

A process-independent irreversible native revocation event and held UI/supervisor process watches close the host's business gate. The original IO/service worker receives a stop request without transferring or dropping its original join/Storage ownership. Admission racing revocation stores the real worker in its task before returning an error. New protocol business frames check the gate; an operation already admitted, including initialization, may finish. The startup mutex does not eliminate every signal-latch-to-resume race, so this qualification does not assert that no admitted initialization can resume after first loss.

GracefulClose is serialized after accepted data; child stdin is closed while Flutter keeps supervisor input/heartbeats alive. It waits for the original `WorkerExit<Storage>` under the existing service/IO shutdown contract, with no five-second normal drain/kill deadline. The independent five-second post-loss ceiling applies to actual controller loss; a best-effort earlier Job termination can be delayed by blocked output. Native termination avoids blocked Rust stdio cleanup.

The sidecar marker and SQLite WAL/FULL ledger bind immutable profile, incarnation, generation, supervisor PID, host/package bytes and actual child. Claims, updates and release use transaction-local full-record comparison/CAS, readback and commit; deleted rows, one missing marker/ledger, digest/binding drift, triggers and invalid proof fail closed. Direct host and in-place library/key maintenance cannot bypass a retained owner. This is not hostile same-user protection; removal of all supervision evidence is not distinguishable from first legacy-library adoption by these sidecars alone.

Normal Released requires original host exit 0 after real drain, actual Job-empty, child exit, dual EOF, completed output readers, finished/reaped stdin, a closed gate and committed owner proof. `protocol_ack=not_applicable` records the workbench protocol boundary; it is not the M03 Close/ACK. Complete normal resource proof is admitted exactly once by a CAS competing with first controller loss. Loss winning first forbids normal release even when the async loop has not yet observed it. A complete proof winning first linearizes the already-finished original normal shutdown; later UI loss still starts its independent deadline and forbids a successful supervisor transport exit, but does not falsify that prior resource proof. No mutex covers SQLite commit, and commit failure remains unconfirmed. Business Unknown is not promoted to success by resource reclamation. Flutter's verified recovery future differs from actual transport exit: ClosingUnconfirmed or missing proof prevents recovery/unlock, while the window may close after actual transport exit.

| Fault | Actual resource behavior | Persistent/UI behavior |
| --- | --- | --- |
| Normal explicit close | Original host drains, tree empty and handles/tasks completed | Only full committed proof becomes Released; next generation allowed |
| Business host crash | Supervisor observes its held handle, gates/reaps resources | Closing/Retained, Unknown; no business replay or automatic repair |
| Flutter UI crash | Process watch/transport loss revokes; kernel Job cleanup stays bounded | Dead UI output is discarded after loss and terminal diagnostics are bounded; surviving supervisor continues actual cleanup and persists resource-only proof, retaining the original owner. Missing proof still stays retained |
| Supervisor crash | Sole Job handle closes in kernel and original host exits | Active/Closing without durable completion remains retained; restart refuses takeover |

No post-crash owner-repair command is implemented. A missing trusted proof is an explicit blocker to reopening that same library, not evidence of failed cleanup and not a reason to clear the database. A future repair must bind the original identity/generation and attest complete resources without manufacturing the original WorkerExit or replaying Unknown. A surviving supervisor's resource-only proof remains separate from business/normal proof.

The next recovery work must define an explicit management operation backed by a trusted retained identity/generation and complete resource proof. In particular, after the supervisor itself dies, this anonymous Job design deliberately leaves no surviving Job-query owner or original WorkerExit: PID disappearance or outside direct-host exit cannot justify automatic library unlock. That missing trusted proof is a real same-library recovery blocker, and requires a designed and reviewed proof source before implementation; current UI keeps the original library and refuses takeover. Neither normal proof nor Unknown is manufactured.

Non-Windows product tests require those OS environments. Hostile same-user isolation requires a separate approved security identity/permission boundary. Successful nonzero OS short completion needs an actual qualifying Windows completion; current real pending/cancel/error tests do not provide it. Power-loss durability, full G0/system picker/manual settings interactions and a cross-platform SDK freeze remain unqualified. Backup delivery receipt/independent Python packager delivery are not certified by this production qualification and have not been reuploaded.
