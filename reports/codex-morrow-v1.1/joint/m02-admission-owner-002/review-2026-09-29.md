## 源码审查与实际权威边界

新公开入口为 `HostAuthority`；直接 `Admission`、`NativeHost`、`Session` 已改为 crate-private。既有 Core `service_authority::Record` 只表达网络 Authentication/Publication，不能当作原生启动批准。本片的唯一原生批准/owner 记录存于 `profile/native-admissions.sqlite`，使用有界、版本化的 Protobuf+LZ4 `MRNADM01` envelope。`coordination.sqlite` 只复用 Core 持久 store identity 与实际 OS 文件锁，不保存第二份同义 native 批准。

`approve` 来自可信宿主嵌入调用，创建一次不可反序列化的 LiveApproval，保存首次 Instant 和完整原批准副本。摘要绑定 profile/slot/plugin/role/operation/grant/issuer/generation、artifact/schema/capability1、首次 TTL 与固定 argv/cwd/平台/允许环境。claim 在事务内对完整记录匹配；持久数据或 grant_id 本身不能恢复 live authority。这里的 plugin/role/operation 是可信调用方给定并固定的标签，未完成安装包身份认证或真实用户审批 UI。

claim 先取得按 Core 持久 identity 协调的 pin，再以 IMMEDIATE 事务原子提交 Consumed+LaunchPending，之后才能启动。第二短事务再次核对完整 Consumed 记录和原 deadline，覆盖同步 spawn 与 PID 登记。退出及双 EOF 都得到确认后，提交 Released，随后才释放 pin。非终态记录在宿主崩溃、OS 锁自然释放后仍阻止接替；没有 clear、steal、TTL 回收或自动重新领取接口。

范围是同用户、同一个可信固定 canonical profile、同一 LOCALAPPDATA namespace、每 profile 一个 slot。新增 canonical_root 绑定拒绝 profile 复制/迁移到另一位置；不把任意 profile、分叉 ledger、回滚备份、任意同用户替换或全机器所有权纳入保证。checksum 检测损坏，不证明写入者身份。

冻结前联合指出的两项问题已经从最终源核对修正：`Revoked` 被纳入合法持久 owner 状态；claim 与 spawn 前复查从局部摘要比较改为完整原记录比较。联合随后实际执行了跨宿主撤权，以及 plugin_id/role/operation 三种“有效 Protobuf/LZ4 重编码、保留原 config 摘要”的受控变更，均拒绝启动。原发现保留在 `pre-ready-findings-001.md`。

## 失败尝试与观察来源

首批 `independent-001` 完成前7组后，在第一次 crash 尝试中错误地用同一等待条件要求“宿主 OS 退出且宿主诊断管道 EOF”。3秒内未同时满足，脚本失败并停止后续场景。该失败完整保留；host25500、child14348不计入通过范围。没有修改绑定脚本或候选来覆盖记录。

新的 `run_remaining_owner_002.py` 先单独确认宿主 OS 句柄退出与 child 仍活，再验证接替拒绝，最后等待管道 EOF。只补跑 crash/artifact-drift/profile-copy；旧 issuer 检查在独立003批次追加，没有重复前7组。正式补跑仍观察到宿主诊断 stdout/stderr EOF约在 OS 退出7.74秒后才返回，接近旧child自然退出时段。具体句柄持有来源未做额外取证，不据此断言完整继承机制；继承句柄封闭性仍未验收。

所有接受的17个serve宿主、10个直接child和1个holder均有独立持有的已知PID OS句柄，核对image路径、文件摘要、创建时间和最终退出。没有Toolhelp、全机进程枚举或未知进程清理。PID由己方Popen或经审核的host/peer记录提供；未独立核验OS父PID，不把peer的holder.json当身份凭据。文件摘要也不等于已加载内存镜像认证。

实际 child IPC字节与child双EOF由审核过的宿主记录；联合独立读取宿主输出、观察其EOF并解码所有完整帧。原stdout逐行与观察事件相符，正常完整会话的最终快照与native事件一致。没有接受场景的审查器强制清理、日志截断、队列丢失或未捕获child句柄。

authority_observation 的 at_us 从 authority open 起算；host_observation 的 at_us 从首次 Admission 起算。验证分别检查各自时钟顺序，跨host用审查器单调时间与事务/ACK来源解释，**没有把两个起点直接相减**。持久撤权提交与运行时应用分开；没有在 application_pending 时宣称所有在途交付已经禁止。

新运行、原始帧、派生解码和临时数据库均位于本批 current-user/SYSTEM 私有目录。插件原ACL工具固定写插件目录，联合未执行它；联合新增同等ACL检查的 `prepare_private_run.ps1`，仅在获准的新joint目录创建新目录，保留工具哈希与实际ACL回执，未修改已有目录权限。

## 未闭合项与门禁

本片没有生产审批UI、完整CLI/安装插件身份认证、可信安装和防换包、全机器owner、任意profile迁移/回滚、强攻击者防篡改、OS沙箱或完整进程树封闭性。独立claim/revoke精细竞态窗口、所有commit失败与spawn/登记中间崩溃点没有逐个强制注入；producer的并发案也只观察到revoke先赢，不外推所有调度。

跨host撤权轮询不提供硬实时界限；在途部分写入、控制/输出饱和、operator stdout背压仍未验证。崩溃后的持久核对、人工安全解除与自动恢复尚未实现；旧child后来退出仍拒绝，不能直接推进成可恢复业务执行。本片仅read-own-session，没有成功网络、任意命令或用户内容写入，也未完成其他平台或旧UI运行兼容回归。

`runs/semantic-001/result.json` 保存501项检查；`decoded-frames.json`、`approval-bindings.json`是受限派生证据。新的 `diagnostic-results.json` 只追加14项诊断进展，不改准备matrix或旧产品账本。`runs/final-preflight-001/result.json` 的exit0只证明2,033旧输入及矩阵身份；其中runtime_pending是冻结准备检查器的固定范围，不覆盖新独立验收结论。
