## 本轮修复

1. `network_node_stream_001/src/stream.rs`：worker 已发送至 oneshot 的响应块，在调用方取消或原始期限到期后仍可能被 `next_chunk()` 返回。新增回归在原实现上出现两项真实失败（返回 `Ok(Some(...))`，预期 Cancelled / Timeout），修复后通过。现在在提交 demand 前及取得成功结果后检查取消、原始 deadline 和授权 guard；失败释放待交付 payload 并取消 worker。撤权为粘性终止。成功返回 response head 前也重新检查。已经观察到的 EOF 保持幂等。
2. `native_session_stream_001/src/write_state.rs`：新增并接入真实 pipe driver 的逐帧写入记账。以 operation ID 追踪每次尾部写入；仅成功完成的字节增加已确认前缀；验证零进度、超长、重复/错误 ID、请求长度和整数边界；部分成功只推进前缀，全部完成才发 `WriteCompleted`。
3. 取消期间部分成功或 `ERROR_OPERATION_ABORTED` 不重发尾部、不声明整帧完成；取消与完整成功竞争时保留真实成功事实一次，不把已经写出的数据当作回滚。取消期间其他 OS 错误仍记为失败。新增 `write_frame_state` 观测，区分 OS 回收、确认前缀和整帧完成。
4. 新增两个真实 Windows 测试入口：对端读到 1024 B 前缀后停止读取，取消 8192 B 原帧并验证不重发、无整帧完成和 owner join；128 B 写入被对端读完后发起取消，验证原操作只成功回收一次。前者验证真实前缀暴露，不预设 OS 必须在错误 completion 中返回非零字节；后者是平台 facade 测试，不冒充完整 host 的竞态证明。

检查存在时间边界：最后一次 guard 检查不能撤回已经返回调用方或已被对端读取的字节，最终效果仍须遵守上层 gate。既有 `Completion.delivered_bytes` 是 worker 交付到内部响应通道的累计值，不是新增的应用消费确认。本轮没有扩展网络协议或冻结 SDK。

## 复跑

需安装 Python 3.10+、Rust 1.95.0 或兼容工具链并将 `cargo`、`rustc` 加入 PATH；首次构建需要取得锁定依赖。Windows 使用本机 Rust 工具链和所需构建工具。脚本无 Git 写入或 CI 操作；每次必须使用新的 evidence 目录，不自动重试、不覆盖旧候选。

在仓库根目录，便携测试与 Windows 编译检查：

```sh
rustup target add x86_64-pc-windows-gnu
python tool/m03_partial_write_003.py --mode portable --cross-check --output ../m03-evidence-new --target-dir ../m03-target
```

在真实 Windows 机器执行（PowerShell）：

```powershell
python tool/m03_partial_write_003.py --mode windows --output ..\m03-win-new --target-dir ..\m03-target
```

`tool/qualification/m03-pipe-driver-check` 直接引用生产文件，避免为检查此边界拉入 Core/SQLite 完整栈；通过它不代表完整 host 构建通过。它可在本源码包内运行，无须修改生产依赖。测试超时将判失败，且不声称进程/owner 已确认回收。
