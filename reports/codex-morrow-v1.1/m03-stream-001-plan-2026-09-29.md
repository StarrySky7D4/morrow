## 必须明确的接口语义

- Open/WriteChunk 不发送；CommitRequest 固定方法、目标、头、正文长度和摘要，重新核对授权并完成持久发送边界之后才允许 HTTP 副作用。
- 重复 Commit、连接中断、取消或进程重启不得隐式再次 POST。无法证明未发送的结果保留可核对状态；Inspect 只读。
- Read 按序号与消费确认交付有界片段；队列字节及批次数分别限额。慢消费者或填满正文队列不能阻断撤权、取消、期限与关闭控制。
- 并发许可、取消对象与原始单调期限覆盖完整流生命周期，不能在收到响应头时提前释放或重新开始计时。
- HTTP 状态、头和 EOF 是传输事实。非成功状态、错误 Content-Type 和模型终态由插件正确处理；EOF 不等于模型成功完成。
- 不把 no_proxy / no_redirect 的既有策略描述为支持了代理/重定向。真实凭据使用、更多模型路径与平台支持继续列缺口。

## 首轮接口审查决定

主协调已读取宿主 `host/m03-stream-001/IMPLEMENTATION-PROPOSAL-001.md` 与插件 `receipts/m03-stream-001/integration-design-001.md`。M-02 第二片随后已限定签收，详情见其阶段记录。

采用三项设计：原生网络批准使用独立封闭类型，复用 Core 的唯一 io_intent/io_evidence 权威；从已有 HTTP 客户端提取共用校验与流式出口；控制通道与经过实际子进程身份绑定的数据通道分离。旧只读会话能力不隐式获得网络权限，也不伪造 Wasm ManagedInstance。

首片统一限额为请求 32 KiB、响应 64 KiB、头 8 KiB、错误诊断正文 4 KiB、最大正文块 8 KiB、未消费额度 16 KiB。客户端可请求 1 KiB 小块核验解析边界。固定上游已观察请求为 22,025 字节，不能采用低于它的 16 KiB 请求限额；新请求仍需实际检查。

请求顺序修正为：已准入客户端通过真实 Core 生成请求 → Prepare 提案且不发网 → 可信宿主核对并明确批准固定原字节 → Commit 单次发送。等待网络审批不续 native 原始期限。两侧在追加方案中对齐动态请求、撤权与发送归属、OS 管道真实写阻塞观察，然后固定唯一权威 Schema。

真实上游 SSE parser 可能在模型 Completed 后提前丢弃字节流。插件需将 ParserDetached、模型 Completed、业务 Cancel 和网络 EOF 分开；收尾任务仍受原授权、总期限、累计预算约束，必要时消费并确认尾部字节。用户取消优先，模型完成不能代替 HTTP 完整响应的持久化条件。
