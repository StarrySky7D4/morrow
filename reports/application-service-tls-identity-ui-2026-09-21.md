# TLS 身份管理界面与 Windows 阶段验收

2026-09-21，基线 `70efc6f`，版本保持 `0.1.9-test.52+56`。本轮将已保存身份的客户端能力接入工作台，并完成完整 Windows 窗口与 Release 构建；没有推送或发布。

## 行为

工作台服务面板新增身份列表、证书摘要和修订，支持明确选择用于下次启动、保存为新身份、用已检查文件替换和禁用。继续使用现有边框/按钮/文字风格；中英文资源同步生成。身份管理可在服务运行中使用，文件检查草稿与用于启动的选择分开；原文件式启动保留。

`TlsIdentitySession` 按后端实例保存草稿、选择、变更回执、待处理操作及 Unknown 身份。视图卸载不取消或重发已发送的修改，重新挂载不会追加修改；切换资料库使用各自状态，返回原库恢复原草稿。保存/刷新不替换旧选择，最新引用/修订/摘要必须与显式选择完全匹配，且未禁用，才能进入启动请求。

分页在稳定快照下最多读 128 条，每页最多 16 条，校验严格顺序、非零摘要、游标与末行；恰好 16 条且无下一页是合法结束。失败保留已有记录作展示但取消可信状态，不发布部分结果。Unknown 后刷新只读记录，必须明确确认核对才重新开放写入；原失败命令身份保留，不把确认解释为回滚或成功。

替换当前身份会让原服务进入停止/回收；首次完整窗口测试在回收后立即尝试选择新修订时停住，暴露了测试遗漏的记录刷新步骤。最终流程明确确认原拥有者回收，再刷新身份并选择新修订。没有放宽服务准入或将陈旧记录直接标记可信。

还修正了外部草稿在后端切换时被错误清空的问题；返回原资料库保留自己的文件选择，同时不把它复制到另一资料库。

## 协作与下一阶段

本轮使用 GLM max 辅助分页实现、DeepSeek max 辅助测试和独立审阅。主代理修正候选中的快照非零校验、页面/总量边界、末页规则及测试 API/断言；本地测试覆盖这些错误。独立审阅建议在确认 Unknown 时直接恢复 trusted，与“必须先成功只读刷新”的约束冲突，未采用；测试确认不会绕过这道门槛。

下一项推进跨重启 Unknown 持久核对，再完成文件系统、C/C++/Rust IO SDK 和全平台资格。当前会话 Unknown 保留仅限进程内；TLS 保护后端以 Windows 当前用户为已验范围。没有自动续期/ACME/客户端证书认证，不声明通用证书管理或公共 SDK 已稳定。
