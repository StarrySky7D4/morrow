# 版本化编辑的未提交判定与草稿恢复

本轮修补既有 V2 主工作台中的确定性拒绝恢复，应用仍为 `0.1.9-test.54+58`，第一方插件仍为 `0.1.9-test.54.3`。未提交、推送或发布；所有真实写入测试使用临时内容库。

## 判定边界

- 私有宿主响应沿用现有 `uiCode` 字段，新增内部值 `1001`，仅适用于直接 `editTasks` / `editCard`；没有修改 Schema、公共 guest ABI 或旧 V1 解释。
- 仅在进入 `commit_task_edit` / `commit_card_edit` **之前**失败，且当场按 Card + operation 查询得到 Absent 时，包装专用 `VersionedNoCommit`。覆盖命令载荷解码、写入准备、源修订检查、业务校验、附件验证和提交前捕获。
- 历史操作已存在、查询失败、进入提交后的任意错误、撤权失败、回执编码/交付失败均不通过该分类解除待核对状态。协议还核验错误包装中的 Card / operation 与外层直接编辑请求相同；外层分段命令错误不自动获得此分类。
- Absent 是当前单 owner 串行请求中的局部观察：它只证明指定卡片/操作没有已知提交，不证明整个系统无该 operation，不允许借此跨卡复用操作 ID，也不表示撤销远端效果。
- 客户端先校验响应版本与摘要，再仅在原编辑调用的串行响应中接受 `1001 + 空 payload + revision=0`。矛盾载荷、非零修订、其他动作及普通错误字符串不能转换为未提交。

## 界面行为

匹配卡片、原 operation 和原源修订的宿主 NoCommit 才释放冻结的原意图。详情页只读刷新到当前内容，保留待办输入草稿；后续修改由用户明确发送新操作，不自动重放。

普通传输错误继续保留原意图。本地验证只能证明本次尚未发送：若它发生于之前结果未知的重试，不能清除那次未知操作，界面继续提示结果待核对。已知源修订过期时等待只读刷新，再重新绑定打开的详情页，避免主列表更新而弹窗继续持有旧卡片。

成功提交后的任务按钮还需等待父页面交付更新视图；既覆盖延迟刷新，也覆盖回调完成前已刷新，以及历史重试返回相同当前修订。新增待办完成时核对组件仍挂载且卡片未切换，避免访问已释放控制器或清空另一张卡的草稿。这是界面交互保护，提交安全仍由原修订/操作与宿主校验承担。
