# test.38：设置批量证据与历史保存重试

日期：2026-09-13。应用 `0.1.9-test.38+43`，审计／工作台宿主 test.38，内容库格式 9；核心 crate 仍为 test.22，运行时／SDK test.11，默认工作台 guest test.13。第一方 AGPL-3.0-only。本轮仅本地开发与提交，未推送、打标签、发布 Release 或上传。

## 实现

默认 Windows 工作台的一次设置保存现在形成一份有序批次证据。证据共用一份实际插件包，记录规范保存意图、各页完整 Invocation／completion、原预算及实际消耗。全部页成功并由宿主核对输出后，设置内容、原件关联、回执与待封存事件一次原子提交；任一页失败不产生部分设置或可提交的部分证据。

固定 Protobuf 新增可选 batch 字段，schema 1 保留旧观察语义和原始字节上限，schema 2 只接受成功 Output 批次。观察最多1024条、意图最多4 MiB、批次原PB最多24 MiB；预先检查嵌套长度、重复字段、wire、数量和版本。逐页按实际消耗扣总fuel，默认设置1B，通用契约上限10B；总预算不会在下一页重置。

历史操作重试核对原意图、页数与顺序、输入输出以及原提交正文，重新核验当前权限后交付原回执，不运行升级后的插件，也不覆盖后续设置。无变化保存不产生操作或占用操作ID；旧的无批次设置操作不冒充受支持的历史重试。

数据库8→9在事务内先校验旧状态，再更新版本并复验，沿用32 KiB物理共享块；原配方容量扩到64 KiB以容纳大批次。旧格式拒绝schema 2。历史单次证据、Commit、签名和块载荷不重编码，不新增unsafe。设计见[批量证据](../docs/PLUGIN_BATCH_EVIDENCE.md)。

### 独立命令行回放

`morrow-transform-replay` 现在按schema 1／2分派，仍要求外部原PB摘要pin。CLI采用默认逐页Limits和固定1B总燃料政策，不由证据自身放宽额度；匹配退出0、拒绝退出1、不匹配退出2，并报告实际执行／总观察数。

新增6项实际CLI进程测试全部通过：v1／v2匹配、两版本错误pin及容器损坏、超总政策拒绝、两版本不匹配退出2；批次首个不匹配只执行1/2页。测试先使用合成Wasm通过实例池捕获，再关闭并删除原合成宿主DB／catalog，只将完整证据及外部pin交给CLI。该组验证入口与隔离性，实际工作台649页由上方真实SDK测试验证。日志 `build/test38-replay-cli.log`、`build/test38-replay-cli-strict.log`；最终全目标严格检查 `build/test38-runtime-final-clippy.log`。

### 实际容量样本

649页样本由1头页、512条目页、8完成状态页、128组件页组成。81页样本使用80个条目、每项49152字节歌词，规范完整输入接近4 MiB。后者实际fuel消耗327,874,820，证据原PB 12,739,069字节、压缩容器854,264字节；两样本均由真实Rust Wasm执行并独立回放。数值仅适用于合成样本，不能把页数上限与每页容量上限相乘当作完整设置容量保证。

三名子代理分别负责核心批次契约与文档、默认设置集成及独立审查／CLI、独立格式与真实SDK／迁移测试。主代理负责运行时批次捕获和回放、DB9门禁与存储集成、全量检查、版本及Windows产物。所有测试使用临时或build下合成资料库，未访问用户资料库。
