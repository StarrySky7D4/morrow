# Windows 审计密钥发布与安全执行状态（2026-10-12）

本说明记录开发候选的限定结果。**SDK 与 namespace 验收仍为 OPEN，`release_eligible=false`；不构成 SDK 冻结、完整应用验收或 Release 声明。**

## 已完成的限定工作

- Windows 审计密钥发布候选使用保留的父目录句柄创建独占临时文件，并通过原文件句柄执行同目录、不覆盖已有目标的发布。原目录共享约束保持；发布后同步、清理或关闭结果不确定时继续返回 `PublishUnknown`，不得自动重试。非 Windows 发布分支及锁名称、持久身份格式保持原契约。
- 本地普通合成文件回归覆盖正常发布、已有目标不覆盖、非法父目录拒绝、未发布对象的 Drop／unwind 清理，以及已发布对象未完成关闭时保留目标并阻断后续发布。此结果限定于发布 helper，不包含真实密钥保护、完整业务或虚拟机安全资格。
- Stage338 的 Windows x64 受限构建通过：一次离线、锁定依赖的真实构建产出宿主与 supervisor 两个非测试二进制。该构建没有执行这两个产物；依赖守卫中的 vendor 核验限于绑定元数据，不能解释为全量依赖载荷重新审计。
- Stage341 的控制与会话流程已物理闭合，但业务结果为 **NOT_ACCEPTED**。 stop 未报告 `Stopping`，所需 `Stopping → Reclaimed` 序列未完成；后续物理关闭或 `Released` 观察不能补成该业务序列。进程退出、日志 EOF 或连接释放不等同于业务启动成功，也不能单独证明失败启动后的全部资源隔离与策略恢复。

## 尚未闭合的门槛

| 门槛 | 当前状态与必要后续 |
| --- | --- |
| 同句柄加载 | OPEN。发布后的路径重新加载仍需消除对象替换窗口；应验证加载使用被绑定的同一对象，而非把路径再次打开等同于原对象。 |
| 祖先目录与 reparse | OPEN。目录句柄共享约束不能被描述为持续阻止 reparse 修改。合成实验已显示，在具备相应写属性能力时仍可能设置 reparse；该结果也不等于已证明突破所有受限执行边界。后续须区分入口拒绝、事后检测与真正防止竞态。 |
| 失败启动隔离 | OPEN。诊断快照只提供观察，不授予清理、重放或接管原 owner 的能力。失败启动的资源、持久 owner 与策略恢复须分别取得实际证据。 |
| sealed-basic 验收 | OPEN。发布 helper、受限构建及会话物理闭合不能替代账户、目录权限、网络隔离与生命周期的完整验收。 |
| SDK26／G04 与 namespace | OPEN。当前候选不可据此标记 release eligible，也不继承其他平台或 profile 的资格。 |

本轮运行范围限于所选 Rust 工作台的 IPC 路径；不据此宣称 Flutter GUI 的旧 FFI 路径或整个应用已统一采用本候选。既有失败、Unknown 和未运行项继续保留，不以本说明覆盖历史记录。
