# 原存储所有权与 IO 执行验证

结论：`PASS_SCOPED`，网络作业的可恢复所有权底座。泛型 IoWorker 可以接管完整受保护存储容器，并在实际退出后归还原容器及执行、断连、维护结果；Windows Storage 适配已接入并通过真实受管 Wasm 与本机 HTTP 测试。CLI／Flutter 主应用任务循环尚未使用此入口，不代表主应用网络任务或完整插件系统已经可用。版本保持 `0.1.9-test.52+56`。

## 实现与边界

- `HostOwner` 提供原 HostRuntime 的借用和准备／结束维护钩子。Windows Storage 将审计 Session、签名身份、数据库锁、身份租约和活动库 Registry 整体移交，没有另一份数据库或替代运行时。
- 新 `spawn_managed_owned` 仍使用原 Manager、IoBinding 与明确准入的 ManagedInstance。既有 Pool 保留其根及依赖，不拆取借用实例。每次执行、Store 修改及断连检查原 HostBinding；维护前后也检查身份，错误替换会拒绝维护或报告失败。
- 创建验证或线程启动失败返回装箱的 `SpawnFailure<O>`，保留完整原容器及实例。线程启动用暂存槽保留唯一所有者，操作系统拒绝创建线程时不会随失败闭包一起丢失。
- `try_reclaim` 等实际线程结束后返回原所有者。执行／准备 panic 或失败先撤权，再尝试原连接清理和维护；断连失败保留确切 ManagedInstance，供调用方修复后明确清理。若发现运行时已被替换，跳过结束维护，避免写入替代库。
- 执行结果、断连结果与维护结果分开记录。维护失败不能撤销已经 Observed 的 HTTP 效果；原 Storage 保留警告，取回后可重试封存。只读恢复查询跳过写入前维护，退出生命周期维护仍单独执行。
- `Drop` 请求停止后立即返回，同步路由实际退出前仍保留原容器和锁。最终交付继续受原撤权和取消约束。默认 HostRuntime 执行器的旧构造与 `try_finish` 形式保持兼容。

## 真实保护存储验证

新增 4 项 Windows 宿主测试使用合成内容库和受管 Wasm，调用真实 network_node HTTP 适配器及本机服务器；没有真实账号或公网请求。网络节点、Tokio 和 WAT 仅作为该宿主测试的开发依赖加入，未把它们接入主应用命令循环。

1. 实际 HTTP 返回 `owned`，原 Store 保留 Observed 与原审计身份，退出封存后的签名可验证，关闭重开仍保留原结果；取回对象的 HostBinding 不变，既有 Pool 根仍可使用并正常关闭。
2. 分别验证活动库 Registry、直接数据库 Session 和原签名身份租约都拒绝竞争打开；取回所有者后仍持有这些锁。
3. 注入准备维护失败时，没有 HTTP 外发，也没有对应操作意图；线程归还原所有者。注入结束封存失败时，已完成请求仍为 Observed，取回原对象后可完成封存，不重发请求。
4. 阻塞路由期间丢弃执行器，Drop 立即返回但锁仍被持有；释放回调后撤权阻止外发，线程真正结束才释放锁，原库可重新打开。

运行时另新增 12 项测试，覆盖准确对象身份与线程钩子、原 Store 修改、准备／执行／维护 panic、迟到结果拒绝、清理失败后保留实例、HostRuntime 替换拒绝、启动失败取回和只读拒绝路径不调用写入钩子。线程创建失败通过测试专用注入覆盖，不宣称实际耗尽操作系统线程；合法恢复查询另由既有默认所有者测试覆盖。
