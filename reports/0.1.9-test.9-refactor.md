## 实际交付

1. **精确附件能力**：ReadAttachment 与摘要读取、重命名、操作结果查询分开授权，作用域同时包含卡片和逻辑附件。即使两个附件共享同一个原件，也不能借用彼此的授权。原生 C／Dart 与 Web 提供相应可信管理入口；业务消息不能自报权限。
2. **绑定修订的二进制读取**：运行期 Cap’n Proto v5 新增 ReadAttachment／AttachmentChunk。每包读取最多 32 KiB，包含身份、修订、偏移、总长度、整件 SHA-256 和原字节。一次 SQLite 读事务解析当前卡片及附件引用；修订变化拒绝后续旧请求，查询前及交付前复核能力与期限。
3. **原子分块索引**：64 KiB 存储块的摘要使用固定 Chunk Protobuf＋LZ4 保存，与原始附件一起暂存提交、去重、回收。范围读取仅校验覆盖的一到两个存储块，避免每包重复扫描完整原件。原件保持原字节；启动、发布及完整导出继续执行整件校验。
4. **原生／Web 共用接收校验器**：AttachmentPart 持有独立不可变副本，AttachmentTransferVerifier 增量核对身份、修订、偏移、总长和摘要，不保存完整文件。缺包、乱序、混合修订或摘要不符不能完成校验。调用者须先写私有临时目标，仅在 finish 成功后发布；本轮不提供生产导出 UI。
5. **中断边界补充**：新增原始块已写入、块索引尚未插入的故障点，证明字节与索引不会以半提交状态恢复。去重与回收测试检查索引同步保留／删除。

撤权阻止后续授权交付，不能收回已复制的字节；当前同步独占宿主的检查不是跨进程权限同步。分块及整件摘要用于损坏检测，不是来源认证、签名或审计封存。没有跨包长期读会话；卡片修订变化后必须由调用者重新开始，不能默默拼接不同修订。

## 验证结果

| 范围 | 结果 |
| --- | --- |
| Rust fmt／Clippy | 原生与 Web 均通过，Clippy 使用 -D warnings |
| Rust 默认测试 | 88 项，包括新增 6 项附件读取／范围／损坏／回收检查 |
| Rust 故障测试 | 6 项，32 个子进程退出场景；合计 94 项 Rust 测试 |
| Dart 单元／绑定 | 10 项通过，生成绑定一致性与分析通过 |
| 原生 DLL 协议 | 既有精确 UInt64、错误输入和释放验证通过 |
| 原生 DLL 附件读取 | 5 MiB＋17 字节，161 包；逐字节与整件 SHA-256 校验通过 |
| Chrome 152.0.7977.83 | 普通 Dart JS 读取 100000 字节，4 包，用相同 Dart 校验器完成整件校验 |
| Chrome 故障／恢复 | 29 个 Worker 中断点：7 重命名、5 暂存、14 附件变更、3 回收；独立页面重开通过 |
| 原生→Web→原生 | 最大 UInt64、未知字段与原正文保留通过；既有 Dart/Wasm 协议探针通过 |
| Flutter | 分析无问题，71 项既有测试通过 |

原生与普通 Dart JS 的实际链路均验证无授权、相邻附件、撤权、期限届满与修订变化。Rust 另行验证读取期间授权到期时不交付结果、跨存储块与末尾／空文件范围、损坏索引及损坏原字节拒绝、去重及回收索引一致性。Dart 单元验证乱序、混合元数据、不完整文件、整件摘要错误以及不可变副本。

所有测试仅使用隔离的合成资料。DLL 附件探针证明本机 5 MiB 连续读取，不代表最大 200 MiB、后台调度或规模性能合格；Web 仅证明上述 100000 字节，暂存／完整导出复制入口仍限 4 MiB。Worker 终止不等于浏览器进程退出或断电测试。
