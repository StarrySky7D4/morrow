# ROAD-07 / IO-C：持久意图与审计验收

结果：**PASS_SCOPED**。IO 修订历史已接入同一 Store 写事务、既有 outbox、签名封存和快照验证，数据库版本由 14 显式迁移到 15。此增量不开放真实网络或文件副作用，不代表 IO-C 全部完成。

## 已实现

- 每个稳定命令保留最多三个不可变修订，使用独立事件 ID；原件、历史关联和全局事件序号同事务提交，不覆盖旧签名事件。
- 完整命令匹配及准确前驱比较；同一修订精确重试返回保存的原件，不新增事件，也不成为发送许可。
- 命令 ID 和修订事件 ID 与普通内容／配置／读取准备相互排他，当前授权拒绝或当次 outbox 容量不足均回滚。
- 历史读取、完整性检查、待签名队列、卡片快照、全库快照、审计封存及独立 CLI 验证接入种类 5 事件。
- 旧库迁移保留内容和 pending 原字节；读取未知结果仍是 ReconcileOnly。旧历史版本的测试夹具移除新表后才模拟旧版本，没有放宽生产验证。

完整默认特性套不启用 fault-injection，不能将被条件编译排除的崩溃项算作通过；上述崩溃专项单独启用该特性。所有测试使用隔离临时库和合成请求，没有访问用户现有内容库。

七次子进程强制退出覆盖 Unknown 提交中的 operation 写入、history 写入、事件写入、commit 前、commit 后，以及 v14→15 迁移提交前后。恢复结果只能是旧完整事务或新完整事务；没有半条历史／事件，原 outbox 字节保留，重开不生成新请求或新记录。它们不是进程内编码往返测试，但也不证明真实 HTTP／外部文件效果的恢复或断电持久性。

独立审计专项通过实际 Session 分别封存三个修订，Archive 保存与重复保存验证，然后移除该测试自身的源库和凭据；独立 CLI 仍能根据固定公钥核验 3 段／3 事件，恢复快照及其原件也核验通过，错误日志身份被拒绝。

宿主专项首次执行因缺少 MORROW_WORKBENCH_WASM 环境变量而失败，原日志保留在 `build/io-intent-host-query-regression.log`。指定已有真实 Rust guest 后重新运行通过；没有修改测试来跳过该要求。
