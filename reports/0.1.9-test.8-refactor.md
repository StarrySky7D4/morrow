## 实际交付

1. **原生宿主 FFI**：新增 morrow_host_open／close／connect／disconnect／grant／revoke／dispatch。仅打开已存在的绝对 UTF-8 实验数据库路径，不导出创建、导入和迁移入口。每进程最多 8 个宿主、每宿主 128 个连接；同一规范路径重复打开拒绝。宿主与连接 ID 不复用，关闭宿主后全部旧连接失效。
2. **原生 Dart 封装**：NativeHostSession、NativeHostConnection 显式管理生命周期，控制方法不进入业务消息。请求和响应缓冲区在正常与异常路径都释放；RuntimeReply 解码完整提交回执、摘要与查询结果，并验证请求关联和精确 UInt64。
3. **提交前响应预留**：原生 dispatch 持有缓冲区注册表锁，先预留返回槽位再执行命令。缓冲区耗尽时拒绝请求且不写入。它解决可预见的槽位耗尽，不代表所有系统故障都可避免；丢失响应仍可能对应已提交操作。
4. **Rust 自有时钟**：原生授权接受相对 TTL，绝对时刻来自 Rust Instant；调用者不能通过业务请求指定时钟、实例或权限。
5. **独立的结果查询能力**：QueryOperation 与 Rename／ReadSummary 分别授权。SQL 在读取载荷前同时筛选 card_id、operation_id，交付前重新检查授权。其他卡片的操作在当前卡片范围内表现为 absentSnapshot，不返回跨范围回执。
6. **协议 v4**：结果明确为 locallyCommitted 或 absentSnapshot，包含目标卡片、操作 ID 和提交回执。缺少授权为 rejected，不能把 absentSnapshot 解释成没有在途提交或确定未提交。固定 Dart 绑定已更新，Web 使用同一 Rust 分派、授权和查询实现。

原生 FFI 是同进程可信宿主接口。整数句柄不能作为插件可以自选的身份或能力凭据；本轮不构成跨进程通道、内存隔离或动态插件执行证据。原生缓冲区指针仍要求调用者独占，不能并发写入或在释放后使用。

| Chrome 152.0.7977.83 | 新操作查询、既有 28 个 Worker 中断点、跨页面恢复通过；原有 Dart/Wasm 协议探针通过 |

原生宿主探针实际使用中文及含空格路径、独立合成 SQLite 数据库，验证：

- 缺失文件被拒绝且不被创建；同一规范路径重复宿主被拒绝。
- 预先占用 15 个缓冲区，再发起需要输入和输出的写请求；返回容量失败。释放占用后查询操作为 absentSnapshot，证明写入未执行。
- 成功写入后故意丢弃响应，独立查询得到 locallyCommitted；用相同操作 ID 重试仍得到原修订与同一事件 ID。
- 只有写权限不能查结果；另一个连接不能借用授权；针对当前卡片查询其他卡片的操作不返回回执。撤权和期限届满后查询被拒绝。
- UInt64 最大值减一的卡片经 Dart FFI 修改到最大值，提交与后续查询均精确保留。
- 连续畸形请求不泄漏缓冲区；8 个宿主和 128 个连接的上限被实际触发；跨宿主连接、已断开的连接和已关闭宿主都被拒绝，替代连接不复用旧 ID。
- 正常关闭后存活宿主与缓冲区为零；重开能查回既有提交，但必须重新授权。

以上“丢失响应”由测试主动丢弃已返回字节模拟，不是网络故障或进程崩溃；进程退出恢复和浏览器 Worker 终止证据分别来自原有故障矩阵，不互相替代。
