# 新建卡片的独立草稿来源

日期：2026-09-23。基于 `ddd9cc8eec224af51f4e58654c9b297332147d96` 的本地工作树，应用 `0.1.9-test.54+58`、第一方插件 `0.1.9-test.54.3` 不变。未提交、推送或发布。

## 本轮完成

持久 WriteRequest 新增显式 source_kind，0 为已有卡片（缺省兼容），1 为尚未创建的卡片；对应私有 Cap’n Proto 新增 sourceKind，更新契约摘要和 Dart 绑定，不改变插件公开 ABI。已有 protobuf 草稿缺省为原来源类型。

新卡草稿要求源修订为 0，无源卡片正文、摘要或前驱证据，不伪造业务 CardRecord。首次保存只在目标 ID 尚不存在时接纳；当前删除卡片保留内容记录，同样拒绝占用该 ID。私有草稿不出现在普通内容列表，也不提前触发正式卡片创建。

已有草稿的来源类型、基线及前驱固定。若另一操作后来创建了目标正式卡片，仍可保存原草稿的新输入，正式内容不被覆盖；后续产品恢复/提交必须显示冲突并重新核对。历史原操作重试只交付旧代次和当前状态，明确放弃后不会复活身份。该检查依赖现有单 owner 串行写入，不声称提供额外的跨进程跨对象原子排他能力。

新卡附件不能认领不存在的源卡片或前驱附件。先显式保存活动草稿，再按同一草稿及代次导入，选择并保存后固定引用；之后可继承自身上一代附件。无草稿的缺失卡片不能被自动推断为新卡导入权限。正式卡片后来出现也不改变这些来源。

Dart 会话传播来源类型，冻结请求和回执比较包含它；新卡恢复严格要求空源描述。首次空白新卡可通过显式 flush 建立草稿，构造本身不写库、不启动初始化计时器；确认后未修改的 flush 不重复写，恢复也不自动提交。这样附件导入无需为了获得草稿代次伪造一次文字编辑。

## 仍需推进

本轮补齐的是新卡草稿来源及底层通路，主编辑器尚未默认创建持久草稿会话，不能宣传已上线自动保存。接下来仍需：

1. 同一编辑器从新卡到正式卡、从在途 S1 到后续 S2 的来源交接及身份退休；旧回执不能关闭仍有新输入的草稿。
2. 私有附件暂存的持久归属和失败回收、草稿历史维护及配额界面；活动配额并不限制全库历史磁盘增长。
3. 富剪贴板捕获及转换来源的完整恢复，不复活失效票据、不自动重跑插件，也不降格为普通文字来假称恢复完整。
4. 只读恢复列表、冲突/容量提示和显式恢复后当前授权下的新编辑会话，再接主编辑器自动保存。

非配对 UTF-16 仍仅能在本地会话保留，不能静默替换后声称已持久化。语言/字体在途提案、正式迁移入口、统一错误协议、远端 Unknown、SDK 及其他平台资格继续保持开放。
