# test.23：同身份内容库副本的并发占用

日期：2026-09-12。应用 `0.1.9-test.23+28`，审计／宿主 test.23；核心 test.22（格式 6），业务插件 test.13，SDK／执行后端 test.11。仅本地开发与验证，未推送、打标签或发布；已发布 test.14 保持不变。

## 问题与实现

test.22 的恢复副本保留原日志身份，但原有数据库路径锁无法阻止源库与另一目录中的副本同时拥有封存服务。test.23 将额外的身份占用放入 Windows `Sealer::new`：同一日志 ID 与公钥对应一个真实独占文件锁，在 Sealer 的整个生命周期持有。`Session` 和旧式独立封存 CLI 都先取得身份锁，再打开可写审计库、迁移或绑定已有身份。

冲突时 Session 返回 `IdentityBusy`，工作台提示另一份副本正在使用；拒绝打开不会修改副本数据库。关闭原宿主后允许重新打开副本。独立只读核验与不同身份并行仍可用。Sealer 构造现在可能失败，调用方须处理 `identity::LeaseError`。

通过当前进程账户令牌与 `GetUserProfileDirectoryW` 定位实际用户配置目录，锁文件位于其 `AppData/Local/Morrow/audit-identities-v1` 下，名称是带域标识的身份摘要。文件为空，不包含资料、私钥或 PID；文件存在不代表被占用。Windows 打开共享模式排除删除／重命名，避免使用中的锁文件被删除重建。正常关闭或进程结束时系统释放文件锁，生产代码保留空文件；持有者可转移到另一线程并在该线程释放。

开发中，最初的系统已知目录查询受到子进程环境变量覆盖影响，身份占用绕过用例失败。改为账户令牌查询后，覆盖 `USERPROFILE` 与 `LOCALAPPDATA` 的独立进程仍命中同一把锁，该用例已通过并保留。

## 剩余边界

此机制只协调遵守当前 Sealer／Session 接口的同账户、同设备 Windows 实例。旧版本、直接调用可信 Store 或原始签名 API、控制该账户的其他程序都不属于强制隔离范围；没有跨设备仲裁。生产代码不依赖删除旧锁文件来解锁。

先关闭源库再打开较旧副本仍会成功；当前不检测这种顺序历史分叉或回滚。恢复选择、活动库登记／切换、独立检查点、跨账户迁移与密钥轮换仍需完成。此次没有宣称备份的完整激活协议、恶意宿主防护、设备断电恢复或其他平台验收。
