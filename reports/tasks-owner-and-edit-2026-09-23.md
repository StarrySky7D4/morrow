# TaskId：真实宿主读写与版本化编辑证据

当前工作树的应用版本保持 `0.1.9-test.54+58`，第一方插件包保持 `0.1.9-test.54.1`。本轮没有修改已经冻结的 `tasks.capnp`、V1/V2 插件算法、旧内容投影或核心命令语义。

## 本轮接通

`Workbench` 库新增 `plan_tasks_migration`、`migrate_tasks`、`edit_tasks` 和 `read_versioned` / `page_versioned`。它们复用当前拥有者、原内容库、真实 Pool 和当前包审批，不另建数据库或插件进程所有权系统。迁移计划绑定原 Card 与修订和确定 operation；源内容变更后不能拿原计划重新定基。

七种任务编辑通过实际归档 Rust Wasm 执行：按 ID 完成/取消、改名、重排、切换阶段、显式全部完成并切阶段、新增、移除。同名任务保留各自 ID；待确认项按指定 ID 处理，阶段改变不隐式修改任何完成状态，删除后的 ID 不可复用。

独立 `tasks-edit.v1` 证据固定完整源 Card、operation、包摘要及规范化命令。解析在分配前限制字段与长度，拒绝重复、未知、非规范和与动作无关的参数。宿主核对精确请求及冻结输出，再推导唯一 `SetVersionedContent` 命令；源基线、结果记录与证据仍在现有核心事务中原子提交。

历史重试先读取指定 Card 的原始操作证据，核对完整命令、源修订、原包及回执，不重新执行 guest。重开库仍保留此边界；持有旧证据不会自动获得新权限。`TaskCommit.committed` 明确表示当时的提交快照，`repeated` 表示同操作历史重试；它不冒充当前内容，UI 接入时必须再读当前版本。

只读接口明确返回 `Legacy` 或 `Tasks`，不会把 V2 再包装为 V1 文字待办。阶段及三类计数来自插件库的既有纯投影，保留任务来源与 common fields；附件的数量、顺序、ID、名称和字节数须与外层 Card 一致。禁用或缺失插件时，已有 V1/V2 内容仍可通过此可信本地接口读取；不代表 guest 获得读权限。

## 验证

- 读取适配 3 项：格式分流、同名歧义与独立阶段、未知字段、未来格式/畸形正文拒绝、附件错配。
- 编辑纯投影 3 项：严格事实边界、非法参数/版本/operation、规范意图匹配，固定请求、输出与持久命令 SHA-256。合成观察只证明投影，不能冒充真实执行。
- 真实执行与证据 3 项：归档 Rust Wasm、受保护库、七种命令、CAS、撤权、错误包、缺少授权、管理器禁用、不同意图/证据不能复用 operation、重开历史重试及独立 CLI。
- 真实 Workbench 拥有者 4 项：V1 创建→固定计划→迁移→七种编辑→历史重试；混合版本分页；禁用/缺包只读；原计划遇到 V1 后续变更拒绝；跨重启迁移回执；带附件迁移、编辑后导出字节一致。
- 编辑路由独立 CLI：正常归档 MATCH；错误外部摘要拒绝；篡改 fuel 观察并重算容器及关联后，纯 derive/verify_commit 仍可通过，但实际重放返回 MISMATCH（退出码 2）。
- 既有迁移、固定历史样本、V1 内容投影及 CLI 兼容组合 17 项通过，不能与此前报告重复累计。
- Windows x64 Release 完整重建成功；新宿主与既有 Flutter 编辑、保存、重开库组合 7 项通过。主应用 UI 与插件 Wasm 本轮没有修改。

## 尚未接入应用的部分

本轮入口是 Rust `Workbench` 库的真实拥有者 API；**私有客户端协议、常规查询、普通卡片动作和 Flutter 仍未使用这些入口**。没有新增迁移按钮，也没有把整项 T31–T34 标为完成。

下一步必须一起补齐：

1. 显式的版本化读取/编辑控制协议和 Dart 类型，区分当前快照、历史回执、来源和三类任务计数。
2. V2 普通正文编辑、收藏、删除/恢复和类别变换的独立规则与证据；不能交给旧 V1 编辑器回写，也不能只支持任务勾选。
3. 混合格式查询与对应版本化证据路径。旧查询历史继续走冻结规则，不可因支持 V2 而改变旧重放含义。
4. Flutter 任务 ID 操作、歧义确认与明确迁移入口，验证原件、草稿、选区及卡片身份保留后再开放迁移。

本轮没有浏览器/Android/其他原生平台运行资格，也没有强制断电测试；纯投影不能证明来源权威或替代当前授权。低层 `ProjectedEdit::commit` 属于可信宿主接口，外层附件业务一致性由当前 Workbench owner 在提交前补验。未提交、推送或发布。
