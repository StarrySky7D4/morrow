# Morrow shared localization

The language registry is externalized in `languages.json`: language codes, native names, source locale, explicit fallback locale and system fallback locale. The authoritative message sources are Flutter ARB fragments: root `l10n/parts/{main,visual,plugins,imports,recovery}.{code}.arb` and this package's small `l10n/parts/common.{code}.arb`. `zh` is Simplified Chinese; there is no separate Traditional Chinese translation. Each fragment owns its prefix. All configured languages must have identical keys and typed placeholder contracts. Flutter's official `gen-l10n` and `intl` compile ICU; single-quote escaping follows `use-escaping: true`.

To add a language, append its code and native name to `languages.json`, supply all six corresponding ARB fragments, then run the generator and checks below from the repository root. The generator derives Dart language names, the Rust host locale allowlist, `l10n.yaml`, merged ARB files and language packs from this registry. No manual changes to those allowlists or generated files are needed. Codes currently support two or three lowercase letters; regional/script variants require additional locale-resolution work. Choose a locale supported by Flutter's Material/Widgets/Cupertino delegates, or supply the corresponding platform localization delegates separately. Rebuild the Flutter application and matching native host after generation. This is a build-time extension mechanism; copying a language file next to an already built executable does not install it.

From the repository root, run `python tool/build_i18n.py --generate` after changing sources. This compiles ARB inputs into merged ARB files, generated typed Flutter messages and versioned PB/LZ4 assets. `--check` verifies the merged ARB, binary resources and compile-time pins against the authoritative fragments; run `--generate` to also regenerate official Dart messages. Never edit those outputs by hand. Run `flutter pub get` inside this package first if dependencies are not resolved.

Consumers import `package:morrow_i18n/morrow_i18n.dart`, call `L10n.of(context)` or independent `L10n.forLocale(locale)`, and install **`L10n.delegate`** with the standard Flutter Material/Widgets/Cupertino delegates. `L10n.supportedLocales` equals the generated supported locales. The generated `AppLocalizations.delegate` is exported for Flutter interoperability but bypasses resource verification if used directly. Missing delegates and unsupported explicit `forLocale` values use the configured fallback (currently Simplified Chinese). The generated preferred locale provides the system fallback (currently English). App locale selection is the host's responsibility.

The verified delegate loads the actual bundled language asset before using the generated implementation. The `MROWLNG1` envelope stores container version 1, explicit raw/compressed lengths, SHA-256 of the original Protobuf, and an LZ4 block. Protobuf schema 1 stores locale, complete canonical ARB digest and sorted message/ICU/metadata entries. Both hashes are pinned in generated Dart from the same inputs; modified packs, missing keys, unknown versions, wrong locale and stale resource content fail explicitly. The raw limit is 4 MiB, at most 4096 messages and 64 KiB per message. Pins establish correspondence to the bundled compiled catalog; they are not signatures or permission to install external code or translations. This stage supports bundled language packs only, not arbitrary dynamic language installation or an ICU interpreter in Dart.

The deterministic build writer emits a valid final-literal LZ4 block and claims no compression ratio; the bounded reader supports literal and match sequences. File formats and headers are fixed in `schemas/language_pack.proto` and `lib/src/language_pack.dart`. Protobuf Dart bindings are produced by the official `protoc_plugin` (25.0.0), not a handwritten object decoder. The resource validation runs before allocating a Protobuf message and before locale delivery; startup error presentation remains the host's responsibility. No runtime plugin contract is changed.

Verification: `python -m unittest tool.tests.test_i18n_catalog`; in this package, `flutter test --no-pub` and `flutter analyze --no-pub`. Tests cover actual binary asset loading, typed integer/string calls and English/Russian plurals, no-delegate fallback, tampering/rehashed missing entries, source/placeholder mismatches and deterministic temporary-repository builds.
