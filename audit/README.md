# Morrow 审计封存底座 · test.21

本模块提供宿主提交事件的原始字节签名、事务式归档、分段封装和独立核验。它是 M4 的前置实现，**Windows test.19 开发版已将系统保护密钥、身份绑定与分批封存接入默认工作台**。启动恢复待封存队列，每次写入前检查压力，正常关闭封存余量；队列上限仍生效，已封存历史的存储配额尚待实现。

## 契约与保证

- `../core/schemas/audit.proto` 固定结构；原始段包含日志身份、公钥、段号、前段摘要和有序事件。卡片和工作区等提交均保存核心产生的原始 Protobuf＋LZ4 容器，不重建提交记录。
- Ed25519 签名对象为固定域标识、原始段字节长度及原始段字节。签名之后才用 Protobuf 外框和 LZ4 压缩。验证先解压并检查上限，再对原始段验证签名，之后才解析其内容；保留未知字段，不重新序列化后验证。
- 调用方必须独立指定日志 ID 和可信公钥。段内公钥不能自我确立信任。采用 `ed25519-dalek 3.0.0` 的 `verify_strict`，保留密钥释放清零功能，不启用 legacy compatibility 或 hazmat。
- 每段最多 128 个事件、原始段最多 32 MiB；外框和文件读取均有上限，解析前限定字段预算与事件数量。事件原始容器通过核心校验，并匹配操作身份。验证器流式处理段，不一次读入全部历史。
- 链核验从创世段开始，检查段号、事件序号和前段摘要。重复、缺段、乱序或验签失败不推进核验状态。
- 可使用独立保存的已签名段作为检查点，要求待验证历史包含该段的相同摘要；较旧或分叉的历史会拒绝。只有检查点确实来自独立保存副本时，才能据此主张相应范围的回滚检测。此实现不自动获得外部见证。

签名不证明插件结论正确，不恢复历史权限，不抵御控制全部宿主、签名密钥及所有检查点的攻击者。当前仅覆盖提交事实；授权、交付、调用、故障等完整宿主审计事实仍待接入。

## API 与验证器

`from_pending` 从核心只读待封存记录构造段；`sign` / `sign_raw` 只接受宿主提供的签名密钥；`verify` 返回已验证段与原始字节；`ChainVerifier` 核验整条历史及可选检查点。没有向插件开放签名或清理接口。

Windows 独立验证器：

```text
morrow-audit-check PUBLIC_KEY_HEX LOG_ID --checkpoint INDEPENDENT_SEGMENT SEGMENT_1 SEGMENT_2
```

不传检查点时仅声明当前给定链的签名与连续性，不声明没有历史截断。工具只读输入文件，不需要 Flutter 或工作台数据库。

运行 `tool/verify_audit.ps1` 完成原生测试、严格检查、Release 验证器真实运行、历史截断拒绝与 Wasm 库编译。`examples/qualify.rs` 创建全新合成数据库和固定测试密钥的演示段，拒绝已存在目录；测试密钥不得用于用户资料或生产签名。

## 原生事务归档（test.15）

`archive::Archive` 是独立的原生 SQLite 存储适配层，业务载荷仍为签名后的原始 Protobuf＋LZ4 容器。签名段和稳定事件 ID 索引在同一事务提交；不会修改核心工作台数据库。归档只提供追加与查询，封存内容不能通过本 API 更新或删除。

- `append` 先验证签名、链头和事件顺序，然后提交段与事件索引。同一签名段的重复提交返回 `AlreadyStored`；相同段号内容冲突、重复操作身份、缺段、错误公钥拒绝。
- 每次写入都在写事务中重新读取尾段，避免两个宿主连接使用过期链头。锁竞争返回 `Busy`；提交结果不明返回 `CommitUnknown`，调用方必须重开查询或重试，不能当成已回滚。
- `open` 会核验完整链、原始字节和索引对应关系。`open_read_only` 与 `check` 支持可选独立检查点，`segment` 返回最初保存的容器字节。SQL 索引不替代签名原件。
- 数据库使用回滚日志与同步配置；当前验证覆盖 Windows 实际进程中断，不声称已经验证设备断电、文件系统损坏或六平台持久性。
- `Receipt` 是宿主侧查询结果，不是可交给插件的权限，也不是核心队列的清理凭证。没有独立见证时不宣称已经获得见证。

独立工具也支持只读数据库核验：

```text
morrow-audit-check PUBLIC_KEY_HEX LOG_ID --checkpoint INDEPENDENT_SEGMENT --archive ARCHIVE_DB
```

`fault-injection` 是显式测试特性，应用和默认 Release 工具不启用。测试会在空链首次封存、已有链追加两种状态下，于段写入后、首个事件索引写入后、提交前、提交后直接退出子进程；重开归档检查恢复及幂等重试。Wasm 检查仅覆盖可移植签名与链验证库，未提供浏览器归档存储适配器。

## 核心原子确认（test.16）

共享验签代码已移至 `core::audit`。核心 `Store::seal_pending` 会自行验证固定公钥、签名链与本库原始提交字节，再将原始签名段、永久事件关联和待处理队列确认一并提交。外部 `archive::Receipt` 本身不能触发核心确认；核心保留签名原件后才移除队列副本，operations 和历史附件关系不清理。

默认打开方式会拒绝已经封存而没有宿主可信身份的库。独立验证器可读取核心库并核对签名原件、事件关联及内容完整性：

```text
morrow-audit-check PUBLIC_KEY_HEX LOG_ID --checkpoint INDEPENDENT_SEGMENT --core-store CORE_DB
```

`examples/qualify.rs` 在新建合成库内完成外部归档、核心本地封存确认、重启核验和幂等重试；待处理队列归零，原始操作保留。测试密钥不用于用户数据库。当前 Windows 应用仍未安装生产密钥和自动确认服务。

## Windows 受保护密钥与分批封存（test.17）

`keys::Key::create` 使用 Windows 系统随机源产生独立私钥和日志身份，通过当前用户 DPAPI 保护，仅将密文写入文件。`schemas/keys.proto` 固定内外消息；外层使用 Protobuf＋LZ4 和完整文件校验，内层私钥与对应公钥在 OS 保护范围内。受控明文缓冲执行清零；这不宣称对完全控制宿主进程的攻击者隐藏密钥。

- 创建与加载分开。创建拒绝已有目标；加载遇到缺失、损坏、格式／平台不符或解密失败直接报错，不重新生成身份。
- 密文临时文件同步后，以不覆盖目标的方式发布，再读取最终文件验证。发布后的同步或验证失败不能当成“未创建”，重试必须加载／核对，不能替换。
- 无机器范围标志、无交互提示；当前用户保护的语义参考 [CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。随机源使用 [BCryptGenRandom](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptgenrandom)。同一账户内的恶意程序不在此隔离保证范围。
- `Sealer::flush` 读取已封存链尾，顺序处理最多 16 批，每批最多 128 个事件；超过段大小上限则缩小批次，不能跳过大事件。返回是否还有待处理内容。一次调用后续批次失败时，先前批次可能已经提交；重新加载链尾和队列后继续，不推断整次回滚。
- 缺失生产密钥的恢复、跨账户迁移、轮换、硬件保护、归档配额和自动重试状态仍待实现。当前只提供 Windows 后端；其他平台不会回退为明文文件。

显式工具入口：

```text
morrow-audit-seal --new-key NEW_KEY_FILE
morrow-audit-seal EXISTING_KEY_FILE EXISTING_CORE_DB
```

第二条命令不会创建密钥或数据库。第一条命令仅输出公开日志身份和公钥，不输出私钥；目标已存在时拒绝。以上描述 test.17 独立工具入口；test.19 工作台通过 Session API 自动初始化／加载，不调用命令行工具。

`qualify_keys` 仅在新建目录生成随机保护密钥及合成库，随后由真正的 Release 工具跨进程加载、封存和独立核验。保护文件依赖当前系统账户恢复条件；请勿把测试保护文件当成可跨账户恢复的备份机制。

## Windows 显式初始化与身份绑定（test.18）

`session::Session` 将核心库与同目录的 `.audit-key` 保护文件关联，持有合作式文件锁直至会话关闭。只读检查已有绑定后才加载密钥；显式初始化允许创建新库和密钥，普通打开不会自动补建。已绑定空库、已签名旧库缺失密钥时均拒绝重新生成；数据库丢失而密钥仍在时也拒绝创建空库替代。恢复原保护文件后可重开，跨账户恢复与密钥轮换尚未实现。

```text
morrow-audit-seal --initialize DATABASE
morrow-audit-seal --open-bound DATABASE
```

以上为独立工具入口，均显式封存最多 16 批。核心格式 6 持久保存公开绑定，但信任来源仍为宿主独立持有的身份。首次初始化五个进程崩溃边界、空库密钥丢失、错误密钥、签名旧库升级和并发会话锁均有回归测试。test.19 默认 Windows 工作台开始调用此接口：首次打开未绑定的实验库会验证、保留原内容并绑定身份。已绑定库沿用原身份。自动验证仅使用合成目录，不读取实际用户资料。

## Windows 工作台接入（test.19）

`workbench_host::Storage` 在整个宿主生命周期持有 Session。启动封存遗留队列，后续写入前达到 64 个事件或 8 MiB 时封存最多 16 批，标准输入关闭后再封存余量。强制终止不依赖析构保存，下一次打开沿原链继续。

维护失败单独返回提示，已保存内容仍可查询／导出；后续修改必须先成功维护。封存放在新写入之前，不将已经提交的操作误报为维护失败。缺密钥、错误密钥、并发占用仍拒绝打开，Flutter 显示对应原因。test.19 仅支持手动恢复原保护文件和原系统账户；test.20 已添加下述恢复界面。密钥轮换、跨平台保护后端、独立见证和重放尚未完成。

## Windows 原保护文件恢复（test.20）

`recovery::restore_key` 在与工作台相同的合作式会话锁下执行。一次读取并固定所选保护文件，使用当前系统账户解密，验证原身份以及内容库完整历史后发布这些相同字节。恢复不创建／迁移／修改数据库，也不生成新签名身份。未绑定库、错误文件、损坏历史和被占用的库均拒绝。

目标缺失时禁止覆盖并发出现的文件；目标已经有效且匹配时幂等返回。若目标已损坏或属于另一身份，先将原字节写入同目录 `morrow-audit-key-before-restore-*.backup` 并同步，再原子替换；恢复中断可以重新核对并重试。选定备份保留原位。保护文件读取上限为 64 KiB，异常超大目标文件不会自动替换。

Windows 工作台启动失败页提供「选择恢复文件」和「重试打开」。选择取消不会更改内容，处理中禁用重复操作；原保护文件恢复成功后重新打开工作台。此入口只恢复现有身份，不能替代丢失的原备份、跨账户恢复或密钥轮换，也不修复损坏数据库。不会把保护文件或私钥交给插件。

可信桌面控制入口：`morrow-workbench-host --restore-key DATABASE ORIGINAL_PROTECTED_FILE`。该入口在插件加载前完成，插件运行期契约没有新增恢复权限。实际验证范围见 [test.20 恢复记录](../reports/test.20-key-recovery.md)。

## 运行中导出保护文件备份（test.21）

`Session::backup_key` 使用现有会话锁与固定身份核验当前内容库和源保护文件，一次读取固定的受保护容器字节，经验证后写入目标目录临时文件、同步、禁止覆盖地发布，再读取最终文件核对原字节和身份。备份不修改内容库、不清空待封存队列、不重新生成身份或导出明文私钥。源文件丢失、损坏或被换成另一身份时均拒绝。

已有目标不会覆盖，选择新文件名后可重试；发布后未获确认按结果待核对处理，不宣称文件不存在。备份仅能在原系统账户保护条件下使用，不包含内容库和附件，不能替代完整资料备份或跨账户迁移。实际恢复仍通过 test.20 的原身份核验流程。

Windows 设置增加独立「内容保护」玻璃卡片及「备份保护文件」按钮，继承主题并进入组件独立材质列表。此能力属于可信宿主，插件缺席时仍可导出保护文件。Flutter 通过私有 Cap’n Proto 命令传递用户选择的保存路径，响应不包含保护文件字节；插件协议未获得密钥或文件系统权限。验证见 [test.21 记录](../reports/test.21-protection-backup.md)。
