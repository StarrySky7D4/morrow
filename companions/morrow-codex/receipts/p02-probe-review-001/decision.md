## Decision

Do not start Codex CLI, App Server or a new imitation loop. Build a native qualification harness against original upstream crates. The first deliverable may contain real endpoint and LiveThread callsite probes plus a core execution dispatch probe. Those are three bounded callsite receipts, not full-loop integration or G0 closure. Preserve an unmodified complete source snapshot and apply a reviewed, separately hashed patch only in the new batch's working copy. Never fill missing upstream modules with empty implementations.

Execution is currently blocked until complete required source/modules/assets, fixed registry/git dependencies and a real locked build are available. A successful cargo metadata --no-deps is only a manifest-resolution observation. It cannot establish that source compiled or a probe ran.

## NET: fastest original upstream entry

The real chain is codex-api::ResponsesClient::stream_request (endpoint/responses.rs:70) -> stream_encoded (line 123) -> EndpointSession::stream_encoded_json_with (endpoint/session.rs:122) -> auth.apply_auth -> HttpTransport::stream (session.rs:148). The endpoint serializes the request, prepares the final body, sends POST /responses, then passes the supplied StreamResponse bytes to the original SSE parser. The public stream(Value, ...) entry (responses.rs:110) is a smaller preliminary request-shape probe; prefer stream_request for the final endpoint receipt.

Implement a qualification-only MorrowHttpTransport using the original HttpTransport trait and kit exchange_checked. It records the actual received method/URL/final headers/prepared-body digest, accepts only an explicit credential-free fixture destination, sends the prepared body through Open/WriteChunk/CommitRequest, and supplies Read chunks to the upstream parser. Use a no-auth AuthProvider, no telemetry exporter, Compression::None and an explicit zero-retry policy. Validate the exact request and number of commit/send attempts. Do not use a loopback HTTP server or ReqwestTransport: the real endpoint can already accept the injected transport.

Required evidence: (1) valid fixture SSE parsed into original upstream events; (2) disconnection before CommitRequest gives a real returned error and no committed request; (3) disconnection after the first Read produces upstream stream error without synthesized Completed and without a second POST; (4) truncated EOF cannot be promoted to completion; (5) destination/method mismatch rejected. Preserve request/attempt/frame correlation and bounded chunk counts. A transport wrapper should log both received Requests and kit frames so the test proves that the original endpoint actually invoked it.

Minimum crates are codex-api, codex-client, codex-http-client, the kit, and the upstream declared type/runtime dependency closure. The existing P-01 audit counted 17 normal/build path packages for codex-api conservatively, not a resolved feature minimum. codex-api still includes WebSocket and filesystem dependencies; linking a crate does not mean those paths ran. No upstream algorithm patch is needed for this endpoint seam.

Full core still constructs ReqwestTransport in core/src/client.rs:1181-1197, consumes it at 1758, opens WebSockets at 1233 and selects WebSocket/HTTP at 2218. A second, separately qualified patch must inject a transport factory into ModelClient, then invoke the real ModelClientSession::stream. HttpTransport uses RPITIT and is not directly usable as Arc<dyn HttpTransport>; use a concrete forwarding adapter with boxed futures/object-safe internal service, or a concrete enum, without copying the host schema. In a host-only profile, missing injection and WebSocket/prewarm selection must return unavailable, never select the default HTTP client. Auth refresh, models, compaction, uploads, analytics and other initializers remain separate paths to audit/disable or replace. Endpoint success does not cover them.

## STORE: real LiveThread, with a newly confirmed pre-store bypass

ThreadStore is a real interface (thread-store/src/store.rs:93). LiveThread::resume calls resume_thread and, when history=None, load_history (live_thread.rs:181-226); append_items reaches append_items at 280; persist/flush/shutdown call through at 290-331. Custom store implementations do not match LocalThreadStore's downcast. A small MorrowQualificationThreadStore can map opaque serialized RolloutItem and metadata records into kit AgentEvent payloads; use only bounded fixtures <=4096 bytes per payload, <=8 events per batch and <=128 total. Reconstruct reads from the host event stream, not a second durable local map. Unsupported list/fork/archive/attachments/checkpoint operations must return ThreadStoreError::Unsupported, not Ok with fabricated data.

Start with a fixture-seeded host, then invoke the original LiveThread::resume with history=None and rollout_path=None, append, persist(Standard), load_history and disconnect. Exercise open-writer/tail CAS/append/read frames through the real upstream caller. The adapter may keep ephemeral correlation and pending frames; it must not retain an independent recoverable rollout. A disconnected persist/flush must not return success from a cached receipt. All success is qualification-only simulated persistence, never disk durability or P-08 completion. Metadata updates from LiveThread must be routed or explicitly rejected, not silently dropped.

New mandatory finding: LiveThread::create calls ThreadMetadataSync::for_create before ThreadStore::create_thread (live_thread.rs:142-143). Supplemental thread_metadata_sync.rs:54-66 calls get_git_repo_root and collect_git_info on cwd. Thus injecting ThreadStore alone does not prevent filesystem/Git activity, and cwd=None is converted into an empty path rather than bypassing discovery. Before claiming create interception with no OS path, add a small reviewed patch making Git metadata observation explicitly injectable/disabled in the qualification profile. Do not merely choose a directory that happens not to be a Git repo. Preserve the original LiveThread lifecycle and call; do not copy it into a new fake loop.

The real ThreadManager::new accepts Arc<dyn ThreadStore> at core/src/thread_manager.rs:521-532, but also initializes skills/plugins/MCP/code-mode. Never invoke thread_store_from_config (449-502) as a convenient default: it constructs local storage and may start migration/compression. SessionServices also carries state_db, image_store, extension data, upload clients and local agent runtime. The P-01 conservative closure is 35 path packages for thread-store, versus 90 for core. Full-session storage integration remains blocked until these additional authorities are addressed.

## EXEC: the actual caller needs a small upstream patch

Calling a newly written fake.start(params) only proves that fake's implementation. The required actual caller is core/src/unified_exec/process_manager.rs:1309 open_session_with_prepared_exec_env. Its 1322 branch selects ExecBackend only for remote or shell-snapshot requests; it calls start/start_with_network_policy_decider at 1349/1352. The alternative at 1413 directly calls codex_sandboxing::spawn_process. core/src/exec.rs:959 separately calls spawn_child_async. These are not covered by a standalone ExecBackend test.

Environment's exec_backend/filesystem/http_client fields are private (exec-server/src/environment.rs:667-678). default_for_tests (685) installs LocalProcess, unsandboxed LocalFileSystem and a direct-capable HTTP factory; it is unsafe as the base of an isolation fixture. Add a constructor/mode that requires explicit ExecBackend, ExecutorFileSystem and HTTP implementations with no implicit local defaults. Use a distinct host-managed mode, not fake remote URL/state or a shell-snapshot flag to force the branch. In the qualification profile, route the original dispatch through that backend and reject every direct local spawn path. Do not modify the upstream CODEX_SANDBOX_NETWORK_DISABLED/CODEX_SANDBOX environment mechanisms.

The smallest dynamic dispatch test belongs inside core or a narrowly feature-gated access point calling that original pub(crate) function. Use UnifiedExecProcessManager::default, tool_ctx=None and the real NoopSpawnLifecycle (core/src/unified_exec/process.rs:55-59); construct a real ExecRequest with explicit argv/cwd/empty allowed environment. The injected backend records ExecParams, issues kit Tool Propose/Claim through a trusted fixture approval, then can deliberately return an identifiable ExecServerError::Protocol sentinel. That proves the original caller reached the fake backend and propagated its refusal. Label it intercepted_then_refused, not process execution success. Test disconnection and the formerly local/no-shell-snapshot input separately; both must reject without local spawn.

If a successful synthetic process lifecycle is required, the adapter must deliver actual ExecProcessEvent values. ExecProcessEventReceiver::empty never emits events; core/src/unified_exec/process.rs:466-487 waits on recv and does not poll read by itself. Returning an empty receiver with a made-up completed read result will hang or falsely leave execution running. A minimal additional event-channel constructor or fixture internal to exec-server is needed, followed by Output/Exited/Closed order assertions. Do not claim PTY/process-tree acceptance from synthetic events.

The execution graph is core's conservative 90-path closure plus the actual declared external dependencies; exec-server alone (39 paths) is not the core caller. Record the patch digest, feature set, exact test selector, original callsite, fake receipt and direct-spawn rejection observation. A deny wrapper/counter must run on deliberately selected bypass inputs; zero output from an unexecuted local path is not evidence.

## What host-kit-003 can and cannot support

| Family | Available for a bounded callsite probe | Missing for a production/general replacement |
|---|---|---|
| Stream | Opaque request bytes fixed by digest; bounded fixture response chunks; attempt/cancel/close | HTTP status/headers/redirect metadata, general destination resolution/authorization, control channel. A fixture may explicitly supply static 200 + SSE headers, but those are not observed host HTTP facts. |
| Event | One fixture session's writer epoch, append CAS/idempotency, read-after | Thread create/list/resume/fork/archive/delete semantics, checkpoints, retained history/gaps, durable fence, general multi-thread namespace. Opaque plugin event types are allowed; this does not create those host capabilities. |
| Tool | Proposal digest, exact source fixture, trusted fixture approval, single effective claim, report/inspect | argv/cwd/env input retrieval, process ID/lifecycle observation, stdout/stderr bytes, stdin/PTY/signal/terminate, filesystem operations. ToolReport is a plugin claim and no OS process is spawned. |
| NativeSession | Hello, drain, fixture identity binding, structured unconfirmed exit | Actual A/B launch/attach identity, authenticated connection, OS exit proof. |

Transport::exchange is synchronous and returns the kit's small Error enum; the wire ErrorCode has Unavailable but transport-level I/O failure classification is not fully modeled. Keep disconnection evidence explicit in the adapter receipt. Do not alter the consumer copy of the authoritative schema to make any mapping appear complete. Ask the host owner for a future contract revision only where the next claimed behavior genuinely requires new generic transport/store/execution semantics.

For the limited fake-callsite probes, the above gaps need not prevent all progress: static fixture HTTP metadata and explicit Unsupported branches are legitimate if labeled. They do block claiming all three general replacements, A/B isolation, complete loop behavior, durable storage or G0. Hooks, Skills/AGENTS lookup, MCP auto-start, shell snapshots, Git helpers and background networking/storage still require reachability and dynamic no-bypass evidence.

## Build and evidence discipline

Use a new native qualification workspace/lock/target under the plugin repository. Keep Wasm absent from this probe graph; no empty Wasm crate is needed. Do not make the upstream workspace a product workspace member. Path dependency inheritance still requires the complete upstream workspace manifests/source. Cargo patch sections are selected by the root workspace: preserve the upstream exact crossterm/tokio-tungstenite/tungstenite git revs in the harness where needed, otherwise the build can silently use different dependency code. Retain the original upstream lock and generate a separate explicitly recorded probe lock; do not modify the frozen P-00/P-01 lock/receipts.

Review applicable upstream AGENTS before patching. Scoped qualification checks do not authorize the full upstream suite, broad formatting or default upstream runtime. Missing dependency/source errors remain blocked. Build success, test process exit, individual callsite interception and full G0 acceptance are separate facts and must be reported separately.
