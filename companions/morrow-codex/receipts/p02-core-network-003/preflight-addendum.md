# Host pre-review incorporated before compilation

The host identified an additional natural branch at original `core/src/client.rs:1451`: `preconnect_websocket` handles426 at1507 independently of prewarm. The scope now includes a sixth case entering that real method, observing its setup-only Ok and subsequent HTTP refusal. The bridge never calls fallback helpers or writes the persistent disabled flag.

`ModelClient::new:503` unconditionally collects auth environment telemetry even without AuthManager. The new runner copies only individually looked-up allowlisted OS/build environment fields (it does not enumerate credential values), starts a fresh child profile, and never forwards API-key or refresh-URL variables. The bridge checks their absence before ModelClient construction. It also checks auth, gateway_oauth, aws, experimental_bearer_token, env_key and env_http_headers are None and requires_openai_auth is false. Retries are fixed to Some(0). These guards are prerequisites, not claims that production auth recovery was exercised.

This is an explicit ModelClient backend override, not a replacement HttpClientFactory. It covers the shared `build_api_transport` HTTP construction helper and `connect_websocket` connection helper used by the six cases. The default factory remains concrete; its unavailable policy is an additional local refusal backstop. Core routing and timeout/telemetry/error handling are retained, while proxy/TLS and the API client's downstream WebSocket header merge/auth/upgrade/frame processing are not reached by the refusing override. The two other HTTP-helper callers (Realtime setup/session) and direct methods outside those helpers remain untested. Only the qualification bridge is feature-gated; the backend API and Core injection routing patch are not gated and are not connected to production session startup.
