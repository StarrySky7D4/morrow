## Restricted feature and normal mode

The qualification package explicitly enables `codex-core/morrow-p02-restricted-qualification`. Core propagates this to both qualification bridges and `codex-thread-store/morrow-p02-restricted-qualification`. Neither source crate enables it by default. Compiler-artifact and resolved metadata features are checked in `build-graph-evidence.json` after the build. There is one Codex source root and one executable, including the host-kit 003 dependency.

The new refusal conditions are `cfg!(feature = ...)` checks. In the normal build they evaluate false; original default branches remain in source. The merged reviewed Environment and ModelClient injection APIs remain available as in 002/003. Normal-mode compilation and execution have NOT been performed in 004. No claim of normal product semantics, runtime authorization, Bazel support or global isolation follows from the restricted build.

## Explicit remaining paths: G0 blocked

- `exec-server/src/environment.rs:Environment::get_exec_backend` / `exec-server/src/local_process.rs` (spawn at 424): directly obtaining/using a LocalProcess bypasses the guarded Core dispatcher. Arbitrary injected implementations are caller-owned code, not a trustworthy authorization token. Lower codex-sandboxing spawn functions remain callable. These require production authority/backend ownership design, not another qualification feature.
- `core/src/shell_snapshot.rs:1070,1089` and `core/src/context/world_state/environment.rs:427`: shell/environment capture can spawn before prepared dispatch. The current qualification does not request shell snapshots. No global syscall confinement exists.
- `thread-store/src/local/mod.rs:482,526,530,534,555,585,598,741`: direct create/resume/append/persist/shutdown/read/list/update methods are untouched. `core/src/thread_manager.rs:462,728` still constructs LocalThreadStore. This slice guards LiveThread acquisition only; it does not wire a production ThreadManager to the adapter.
- `thread-store/src/live_thread.rs:304,326,372,395`: background persistence, shutdown and metadata updates can apply pending metadata before another operation. They retain the same thread_store Arc, but nonempty pending-state ordering/transactions and all PersistContext variants are unqualified. The fixture adapter refuses metadata methods; no durable receipt is fabricated. Standard persist and append failure evidence must not be generalized to these contexts.
- `thread-store/src/live_thread.rs:LiveThreadInitGuard::Drop`: asynchronous cancellation cleanup can finish acquisition and then discard. This batch explicitly awaits `discard()` on an already acquired bounded fixture; it does not test cancellation during acquisition or infer successful host writer release from owner counts/runtime shutdown.
- `core/src/realtime_conversation.rs:691,745`: separate RealtimeWebsocketClient creation/connect bypasses the ModelClient seam. Direct API clients, exec-server HttpClient, proxy/TLS/connectors and other network consumers are not globally redirected or confined.
- ModelClient construction/current_client_setup auth work precedes these transport guards. The runner removes personal auth/config access through isolated profile plus individually allowlisted environment keys; the bridge separately checks credential variables absent and provider auth fields empty. This fixture isolation is not a production credential/recovery policy.
- HTTP injection still returns before the original account-routing redirect rejection and does not pass redirect_policy to the injected capability (inherited 003 gap). All actual requests in this qualification refuse; production redirect/authorization parity remains unproved. WebSocket observations precede final API auth/header merge and wire upgrade. Build errors called `qualification-disconnected` are local Build errors, not observed socket disconnects.
