## Implemented behavior

- Audio/video attachment rows open a bounded preview with play/pause, seek, current/total time and fullscreen. The source is the exact selected business record/revision or confirmed draft pin generation, read through the existing native whole-file hash/length path. Playback opens paused; there is no autoplay or automatic foreground resume.
- AVPlayer receives only the verified private file, opened read-only with NOFOLLOW, stat-checked against the exact confirmed length, and supplied as a bounded `fdSrc`. Video waits for its actual XComponent surface before prepare and uses aspect fit. Accepted commands are serialized; token/session guards reject old callbacks and disappearing old surfaces. Close waits for native player release and descriptor close before releasing the file lease. Rejected release retains the same resources for explicit close retry.
- Fullscreen captures layout, requested immersive state, orientation and the known app-owned system-bar policy for the same prepared window before any SDK mutation. It requests landscape and hidden bars, retaining the same player/surface identity. Back, close, background and media failure request exit. Every independent restore is attempted; a failed restore retains the original snapshot and exit action instead of recapturing the altered window. API 26 has no system-bar-enable getter, so EntryAbility first establishes the app baseline and records its exact window ID. This does not prove arbitrary prior policy or split/floating/2-in-1 behavior.
- Generic file “打开” uses PreviewKit system preview, preserving a bounded safe basename/suffix in the generated private directory. Flutter's guarded executable/script families remain export-only. An unknown dispatch result retains the immutable original lease and does not replay opening. Window close, foreground return and UI destruction do not delete the file. The product's explicit “已结束查看，清理临时文件” action checks the observable preview is absent, then releases the original token; this cannot independently prove downstream applications have finished reading.
- Same-cache budgets allow one dialog file and one system-preview file, each at most 200 MiB, separately from eight inline images/64 MiB. Existing import/pin 64 MiB limits remain unchanged. Named preview cleanup validates the exact immutable filename and directory before removal and refuses foreign entries. Cleanup rejection retains registered ownership/quota and explicit retry; pre-registration read-failure cleanup remains best-effort.
