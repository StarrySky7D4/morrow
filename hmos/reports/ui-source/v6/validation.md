# HMOS dev.6 布局与页面位置验证（2026-09-27）

本轮继续按真实 Flutter `main.dart`、`workspace_viewport.dart` 和 `little_tips.dart` 对齐。整体追平目标未完成；本次只证明下述实际实现和设备行为。

## 修复和接入

- 工作区、编辑正文及桌面外观栏 Scroll 显式顶部对齐，解决短内容默认居中造成的大片垂直空白。
- 两列卡片按 `(内容宽度 - 14) / 2` 计算宽度，保持 Flutter 的 14 vp 列间距，替换原 48.8% 估算。
- 增加宽屏侧栏收起/展开入口；原右侧外观栏仍可独立收起。变化后实际重新测量内容和公共描边尺寸。
- 保留最多五个页面的滚动位置；切换到新分类从顶部开始，返回时恢复；打开/关闭设置也保留工作区位置。仅保存位置，不保存隐藏卡片节点或持久草稿。
- 界面风格选择器移到语言和字体之前，与 Flutter 顺序一致。
- 默认底部提示区不绘制玻璃描边或阴影；只在其独立材质启用时绘制，匹配 Flutter FooterOverlay。以前误继承全局液体边缘会形成额外底框。
- 主窗口选择 AUTO_ROTATION_RESTRICTED，支持系统允许的传感器旋转，保留系统旋转锁定语义。模块声明增加 tablet；不等于平板真机资格。

`dev6-hap.log` 构建成功，最终包在 Pura X View / API 26 x64 安装启动。`release/` 是最终包证据目录，其余本地诊断截图、accepted/、verified/、final/ 是中间构建或未完成的复测，不作为最终包验收。

`dev6-layout-release.log` 完整设备检查通过，实际使用已观察到的 UI 节点：

1. 概览首张卡片顶部由 857 px 滚到 582 px，证明实际发生滚动。
2. 转到小项目，页首引导顶部为 129 px，紧跟页头，不继承概览偏移。
3. 返回概览，卡片回到 582 px（允许 4 px 内布局取整）。
4. 进入完整设置页再返回，保持同一概览位置。
5. 收起侧栏后正文向左扩展、导航消失；展开后位置恢复。
6. 收起/展开右侧外观栏，面板存在性与正文重排均符合操作。

人工查看 `release/wide-final.png`、`wide-projects.png` 和 `portrait-home.png`：页首顶部排列，短分类页不再居中；末端没有默认页脚玻璃框。右侧外观/左侧导航在横屏正确显示，边缘随面板尺寸变化。

实际屏幕分别为 1320×2232、2232×1320，密度 1.5，即 880/1488 vp 宽。CLI rotate 没有改变实际屏幕，第二模拟器缺少系统镜像；最终通过显示服务传感器事件验证横屏。测试期间临时固定横屏，结束后已恢复 0 度竖屏和原旋转锁定设置。一次中间测试因方向变化导致截图失败；驱动现先断言屏幕尺寸，尺寸不符时不执行手势，并仅对截图未生成的瞬时错误重试。失败不计为通过。

## Flutter 参照

`flutter_layout_reference_test.dart` 使用活跃 MorrowApp 和内存样例数据，1 项 widget test 通过；在 440×676、880×1408、1488×832 导出 `flutter-{phone,tablet,wide}.png` 和 `flutter-layout.json`。源实现的标题顶部为 104/104/116 logical px，证明页首不会随短内容居中。

## 尚未追平

本轮未在 440 vp 的 HMOS 窄屏环境重验；Flutter 的 440 vp 渲染不能替代该验证。HMOS 当前仍为 Flex 行布局，稳定虚拟瀑布流、键盘快捷键、原按压/过渡动画及全窗口生命周期矩阵尚未接齐。Rust 和存储未改动，正式 HUKS 会话、持久草稿/Unknown 恢复、附件/媒体、查询分页和插件运行期等仍按 ALIGNMENT_PLAN 继续推进。不是签名包或 ARM64 真机验收。
