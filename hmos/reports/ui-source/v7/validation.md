# HMOS dev.7 原生瀑布流验证（2026-09-27）

按实际 Flutter `workspace_viewport.dart`、`stable_masonry_grid.dart`、`render_stable_masonry_grid.dart` 对齐：一个滚动视口、概览 460 vp / 项目 660 vp 双列阈值、14 vp 行列间距、按身份保留卡片并在顺序改变时使位置失效。原 Flutter 文件未修改，共享 Rust 快照未刷新。

## 实现

- 使用 API 26 `LazyVWaterFlowLayout` / `LazyForEach`，页首与快速记录作为同一布局的 header/footer。移除原 Flex 普通行布局；现有 Scroller 和五页位置缓存继续使用。
- `CardDataSource` 以页面 + 卡片 ID 标识数据，保留对应观察对象。`WorkspaceCardSlot` 观察修订变化，只重建改变卡片的内容，确保按钮回调也使用当前 CAS 数据。
- 原生布局还按位置缓存高度；只调用 reload 会留下旧高度，造成部分卡片重叠。因此对身份移动的索引和修订变化的索引同时发出 change 通知。没有用全局更换所有 key 隐藏问题。
- 瀑布流仅负责 UI 懒加载，数据仍来自现有 Rust 开发宿主，没有替代查询分页、正式会话或授权。

## 过程中发现并修复

首个 Repeat 方案能编译但未渲染卡片，已替换；只通知数据变化不足以刷新捕获旧数据的按钮，已加观察对象和修订内容；BuilderParam 绑定上下文错误曾导致启动崩溃，已显式绑定；只 reload 曾保留部分旧位置，已为移动索引补齐失效并增加全列间距断言。`device/`、`release/`、`verified/`、`placement/` 是中间证据，不能作为最终包验收。仓库只保留部分最终 PNG 及全部最终坐标树，其余本地中间材料未删除。
