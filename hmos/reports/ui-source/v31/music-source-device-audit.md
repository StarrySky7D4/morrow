# v31 Music source and device-admission review

Audited published baseline: `4c04f97e6beb580d33f14f9540db98129fc50180` (`codex/ArkTsUI`, v30). Scope: read-only source, actual local API26 SDK declarations, actual font cmap, and the existing v30 product compile inventory. No device operation, model-test rerun, build rerun, signing, install, Git mutation, or audible qualification was performed. Exact baseline and reference hashes are in [music-source-device-audit.json](music-source-device-audit.json).

Result: **CHANGES_REQUIRED_BASELINE**. Three defects or alignment gaps changed the next implementation/device action. The ongoing v31 working tree is not qualified by this baseline review.

| Finding | Actual baseline source | Consequence and required evidence |
| --- | --- | --- |
| Picker owner epoch | `Index.ets:484-488`, `MusicWorkbench.ets:264-272,341-347`, `EntryAbility.ets:80-89` | Index advances `musicEpoch` on both foreground transitions. The controller captures the old owner before opening `DocumentViewPicker`, then rejects that owner immediately after selection returns. If the real picker takes the Ability away and back, normal music import is rejected and its URI registry is discarded. Lyrics have already been fully read and their temporary file closed/deleted by `pickLyrics`, but are rejected before assignment to `unsavedLyrics`. A picker ticket must preserve the current page instance, wait for current foreground if needed, bind the returned explicit result to a fresh owner, and leave ordinary stale requests invalid. Actual lifecycle ordering requires a device run. |
| Missing four style insets | `MusicPanel.ets:40`, Flutter `music_panel.dart:274-276,516-518`, `experimental_controls.dart:226-328` | HMOS paints only neumorphism/clay and returns for paper/fluent/brutalist/industrial. Flutter defines a distinct recessed edge for every one of these styles. Current track and selected row therefore do not reproduce those four styles. |
| Forced inset fill | `MusicPanel.ets:299,377`, Flutter `neumorphic_controls.dart:23,118-159` | HMOS always fills the current track and selected row with ink alpha. Flutter `NeumorphicSurface` defaults to `fill=false`; flat paints neither edge nor fill. The extra HMOS gray block changes flat/custom-transparent music material. Remove the forced fill and keep actual style-specific edges. This is source evidence of an additional painted block, not proof of the reported universal runtime frame. |

The local SDK `@ohos.file.picker.d.ts:666-679` says that `select` starts a documentPicker page and returns selected URIs through a Promise. It does not specify whether this app's foreground callback runs before or after that Promise. Both orders matter. The durability agent was notified and started exact picker-ticket/current-run-owner rebinding; Root was notified of the inset/fill gaps. Those edits and their tests remain separate evidence.

The actual bundled `materialicons.otf` is byte-for-byte equal to the current local Flutter original, SHA256 `D9865B671A09D683D13A863089D8825E0F61A37696CE5D7D448BC8023AA62453`, 1,645,184 bytes. Its cmap has both format 4 and format 12. All twelve MusicPanel/Footer icon codepoints have nonzero glyph IDs and match Flutter's codepoints. The handle is correctly `drag_indicator_rounded` (`f6e3`), not `drag_handle_rounded`. This rules out a missing bundled glyph for these icons; actual device font registration/rendering still needs inspection.

The existing v30 `dev30-music-ui-a2` product `filesInfo.txt` lists all eight music modules: Library, Files, Playback, PlatformMusicPlayer, Workbench, Ui, Panel, Footer. This establishes that the modules are in that compile graph. It is not proof that their picker/player/UI paths have run.

No new deterministic AVPlayer ownership/EOF defect was identified in the reviewed baseline. The platform adapter admits the exact registered source/descriptor, validates descriptor length, and gives AVPlayer the FD only after validation. Release waits for AVPlayer release before descriptor close, and the coordinator releases the source afterward. Callback ownership and lifecycle fences preserve the old resource across background stop and reject late playback selection. Local SDK `@ohos.multimedia.media.d.ts:3284-3299` explicitly reports `completed` through `stateChange` when loop is false; the coordinator's completed handler is therefore a supported EOF route.

The API26 SDK declares `AVPlayer.seek(...): void` (`2330-2350`), while `play/pause` return Promises. The existing platform seek wrapper only acknowledges dispatch and does not invent a new UI position. Actual `timeUpdate` supplies position. SDK `3433-3451` says that a successful seek immediately reports this event, including its pause-state behavior. Absence of a `seekDone` listener alone is not a proven UI defect. A device check must seek while paused and while playing and verify actual elapsed position, rather than treating the wrapper's resolved Promise as seek completion.

Default footer source matches Flutter's transparent dock: horizontal 14/vertical 4 padding, top 8 margin, playing icon 15 or dot 6, text 11 with 18.7 line height and up to three lines, lyrics icon 17, and no default footer relief/blur/shadow. Custom material receives separate decoration. Current glyphs, fixed dimensions, and source styles are not enough to qualify narrow/wide/dark/custom-font or all-style rendered output.

Recommended real-device sequence, after Root preserves existing unsaved editor and recovery state:

1. Install only a hash-bound candidate, preserve the Store, and verify initial load restores selection without opening/autoplaying a source.
2. Invoke MusicPanel add through the actual visible button. Record Ability foreground/background callbacks, picker URI-result order, normal selection, cancellation, and a return where Promise arrives before foreground. Import a standard generated WAV through the actual system picker, not a synthetic URI.
3. Choose LRC/TXT through the actual picker. Verify original track identity after return, complete source text, timed footer after actual position updates, full-text dialog, and explicit oversized rejection with raw text still available.
4. Confirm `prepared → playing → paused` actual AVPlayer state and duration/position; pause then seek, seek while playing, and observe EOF to next source. Audible output remains unqualified unless actually observed.
5. While playing, reorder another row and collapse/reopen the playlist; exact current source/position should persist. Remove another row; then remove the current row and verify successor and prior actual play-state rule.
6. Exercise background during prepare/play/seek and return without auto-resume; late old callbacks must not start sound. Verify attachment audio/video exclusivity and that failed release preserves the original lease for explicit retry.
7. Inspect all seven styles in light/dark and narrow/wide dimensions, including transparent/custom music and footer materials. Glyphs must render as icons; inset edges should match their styles; default footer must have no independent frame. Report screenshots as actual render evidence, separately from source-model checks.

Online lyrics, metadata/cover import, protected storage, and the broader Windows feature set are outside this narrow source review and remain separate application parity work. This review does not close full HMOS/Windows UI parity or the user's universal-frame complaint.
