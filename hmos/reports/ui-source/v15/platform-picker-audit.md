`AttachmentFiles.ets:314–342` validates the bounded import quota, creates `DocumentSelectOptions`, sets `maxSelectNumber=1` and `selectMode=FILE`, then awaits `new DocumentViewPicker(this.context).select(options)`. It sets no suffix filter, merge mode, default URI or authorization mode. An empty URI list returns `undefined` before creating a spool. It does not terminate the external picker, inject Back, time out selection or request an automatic retry.

The API 26 installed declaration `@ohos.file.picker.d.ts:420–480` documents no default suffix filtering, `FILE=0`, and optional default URI. Official [Huawei picker reference](https://developer.huawei.com/consumer/en/doc/harmonyos-references/js-apis-file-picker) and [OpenHarmony selection guide](https://github.com/openharmony/docs/blob/master/en/application-dev/file-management/select-user-file.md) describe the same route: ordinary documents may have any extension; the selected URI carries temporary read permission. An audio filename does not by itself require changing this import route to AudioViewPicker. The [API 26 merge-mode FAQ](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-local-file-manager-50) concerns non-default aggregation with suffix filters, which this application does not configure. It is not evidence for this observed return.

`EntryAbility.ets` changes foreground storage state; `Index.foregroundChanged()` pauses a current media session/exits its fullscreen on background and reconciles a generic preview on foreground. No media or generic lease was present in the stopped zero-asset fixture. The reviewed handler does not directly cancel DocumentViewPicker. This source inspection does not exclude an indirect lifecycle/window issue on the runtime.

## Dev.15 selection path and verification boundary

The delivered implementation now separates `selectUris(maximum)` and `prepareUri(uri)` instead of eagerly copying the first picker result. `AttachmentImportSelection` sets the maximum to the smaller remaining draft selected-asset and import-record capacity, capped at 20, and validates the entire result before beginning an item. The FS adapter and coordinator reject malformed, duplicate, oversized and **sparse** lists without granting a valid prefix. Selected URIs are helper-owned, ephemeral and consumed once; other helpers, unselected/reused/discarded URIs cannot prepare. Each item recalculates shared spool count/bytes. The remainder can be stopped or forgotten while admitted per-item requests and their exact journal/receipt recovery remain intact. Blank titles may be filled from the confirmed imported name before the existing pin update. No suffix filter, default file path URI, AudioViewPicker workaround, broad grant or direct path bypass was added.
