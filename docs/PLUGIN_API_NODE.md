# 双向网络：外部 API 客户端与 Morrow API 节点

2026-09-14。用户要求两种能力同时存在：调用他人的网络 API，以及 Morrow 自己作为 API 节点提供服务。本文补充 [完整网络 API](PLUGIN_NETWORK_API.md)与 [IO 设计](PLUGIN_IO_DESIGN.md)。原先仅规划客户端、将入站服务排除的范围在此修正。公开 HTTP API、webhook 接收、节点协作属于明确的目标；不能以客户端 GET 或本机 echo 通过宣布完成。

## 1. 两端的职责

| 方向 | 目标 | 授权与身份 |
| --- | --- | --- |
| 出站调用 | 插件访问其他服务的 REST/GraphQL/流式/实时接口 | 包声明、用户批准、实际实例和目标/账户绑定；不把外部响应当作权限 |
| 入站服务 | 外部程序、其他节点或用户调用 Morrow 中明确发布的插件服务 | 独立监听批准、路由发布批准及远端主体认证；远端主体不等于插件实例 |
| 节点组合 | 入站请求触发已授权的本地计算、外部 API 调用，返回结果或任务身份 | 每条边单独授权；入站调用不能自行选择上游 URL、凭据、插件 ID 或扩大内容范围 |

网络层必须有独立 inbound/outbound 能力：例如 `network.client`、`network.listen`、`service.publish`、`credential.use`、`service.stream`（名称为待定契约）。批准调用第三方不等于批准开放端口；批准监听不等于能发布任何内容操作；发布路由不自动让所有网络调用者拥有内容库权限。插件声明只是上限，实际授权由宿主与核心统一管理。

## 2. 提供服务的完整目标

- 路由：明确服务 ID、版本、方法、路径、请求/响应类型与预算；同路径冲突拒绝，先准备成功再原子发布路由快照，更新/卸载撤销旧路由与实例。命名空间由宿主分配，不能覆盖其他插件或宿主管理接口。
- 认证：节点 API token、限定作用域的服务账户、适用 OAuth/OIDC/mTLS；每个远端主体独立映射角色与内容范围。token 的创建/撤销/轮换、过期、失败速率和远端会话不混入 guest 内容能力枚举。
- 接收：校验 URI、方法、header、媒体类型与正文大小；支持 JSON/form/multipart/raw、上传资源、逐块输入。非法或未认证请求在 guest 执行和内容读取之前拒绝。
- 分派：宿主将已认证请求转换为固定 Cap’n Proto 服务调用，附宿主绑定的受限调用上下文；插件不能自报调用者、改回调目标、获取原始监听 socket。输出由宿主验证后再编码成第三方需要的 HTTP 载荷。
- 内容访问：远端 principal 的范围、已发布服务范围、包批准与真实实例当前授权取交集。正式读写仍经核心命令；不得开放直接 SQL、文件目录或 UI 内部 RPC。
- 响应：HTTP status、多值 header、媒体类型、二进制/结构化 body、流式事件；业务错误与 HTTP/传输错误分层。长期任务返回不透明 task ID，查询/取消/下载结果都重新鉴权，任务 ID 本身不是授权。
- 实时服务：SSE 发布、WebSocket 协商与双向消息、连接配额/背压/心跳/关闭；插件停用后关闭该插件连接而不关闭无关服务。断线重连不自动重做外部变更。
- webhook：明确注册接收路由、签名/时间窗/nonce 去重、正文原字节校验、接受与已处理的状态区分；事件确认后崩溃的恢复需持久记录。不能仅凭来源 header 相信发送方。
- 生命周期：启动、暂停接单、排空、取消、停止、证书/凭据轮换和重启恢复；未完成请求可返回取消/未知结果，已发生外部效果不宣称回滚。发布状态与实际监听状态分开显示。
- 暴露方式：本机、局域网、公开网络均为可配置独立 profile；非本机服务需要经过验证的 TLS 终止及鉴权策略。支持直接 TLS 或用户明确配置的反向代理，禁止隐式公网监听、自动改防火墙/路由或强制云中转。
- 服务描述：可导出实际发布路由的 OpenAPI/健康与版本信息，敏感管理接口独立授权；协议生成不得泄露私有对象或凭据。自动发现/节点配对是后续独立策略，不采用未认证广播自动互信。

## 3. 客户端与服务端的协同

完整用例是：外部客户端认证→本节点服务路由→实际插件→获准调用第三方 API→接收普通/流式结果→必要的核心内容提交→返回响应或异步任务。每一步绑定请求身份、实例代次、调用预算和取消；保留请求/响应关联与实际效果观察。

自有节点间正式业务交换仍 Protobuf＋LZ4，内部服务分派为 Cap’n Proto；对接不可控第三方 API 可以使用 JSON 等原始载荷。提供 HTTP 服务不要求所有外部调用者使用内部 UI 协议，也不将 JSON 变成自有配置/日志/权威存储格式。

远端请求的超时与断连不能证明任务没执行。内容提交走已有稳定 operationId 与查询规则；调用第三方造成的副作用采用持久意图与未知结果。入站幂等键绑定调用者、服务、规范化输入和有效期，同 key 不同输入拒绝；不能仅缓存一条 HTTP 200 来替代核心提交记录。

## 4. 本轮原生代码的准确范围

新增独立 `network_node/` 实验库与 `morrow-api-node` 命令入口，版本为 `0.1.9-test.51` 的开发组件；主应用仍 test.50，尚未发布新的应用测试版。实际实现与验证见 [原生节点说明](../network_node/README.md)。

代码新增受信任宿主 HTTP/HTTPS 客户端和 Bearer API 路由服务，支持原始正文、常用方法、限额、取消、超时，以及显式三语言纯转换插件适配。它是共享传输底座；不是完整入站服务权限、通用 guest 网络调用、网络审计或 UI 管理完成证明。

旧原型 `PluginService` 只允许明确选择的无内容能力、无依赖、bytes→bytes 处理器，使用新建隔离内容库。网络认证头不会传入 guest，包/处理器由启动方固定。它不打开现有用户内容库，不允许远端注册任意路由或改变包，不将它冒充未来正式的 service manifest/Manager 授权实现。

新增 [IO-D2 受管服务](PLUGIN_MANAGED_SERVICE.md) 已通过 Windows 本机限定验证：独立类型化 service Request/Reply 与声明 tag 7，原 Manager 批准的 HttpListen／HttpPublish、同 worker 的发布与监听租约、Bearer Principal service scopes 及零 IO 合法服务计算；有出站 IO 时继续走已批准 Broker。它是可信原生宿主显式发布，不是 guest 动态注册，也不代表持久发布、主应用 UI 或新版三语言 SDK 已完成。

普通 HTTP listener 只支持 loopback，TLS listener 接收显式证书/私钥与监听地址；出站以精确 origin 和方法校验，本机 HTTP/HTTPS profile 必须显式选择，自定义根不关闭证书验证。实际资格测试均限定本机合成证书，没有公开部署验收。OAuth、服务持久发布、证书在线轮换、SSE/WS、异步持久任务、完整网络证据与全部平台尚待实现。客户端取消/传输失败仍可能在远端产生效果，原生错误码没有提供持久结果查询。

## 5. 双向验收任务

| 任务 | 实施要求与退出证据 |
| --- | --- |
| NODE-1 共享传输与原生原型 | 真 HTTP 两节点往返、常用方法/原始body/status、入站认证/路由/并发/关闭、C/C++/Rust 实际执行；拒绝原库/未授权包/目标，不以模拟后端代替 |
| NODE-2 正式服务契约与权限 | service manifest、Registry发布批准、远端principal与插件连接交集、固定Cap’n Proto请求/响应、版本冲突、启停/更新/撤权、旧原件兼容；无私有绕过 |
| NODE-3 客户端和服务 UI | 账户/监听/服务发布/授权scope/状态/调用日志/停止管理；外部调用通过真实插件触发获准上游API，完整内容提交与取消 |
| NODE-4 对外运行 | Windows/macOS/Linux等原生 TLS/证书配置与反向代理边界，局域网/公网暴露审批范围、速率/连接/字节/长期任务/认证攻击测试；不自动开放本机环境 |
| NODE-5 连续与异步服务 | 入站上传、SSE/WS、异步任务查询取消、webhook签名/去重和恢复；断连/慢消费/多实例关闭不影响无关服务 |
| NODE-6 审计与节点协作 | 入站身份/发布变更/调用链/上游请求/核心提交因果闭合，崩溃Unknown查询、备份恢复、断网录制重放、无真实外部副作用 |
| NODE-7 跨平台与 SDK | C/C++/Rust 发布服务示例/工具/固定原包、平台矩阵与业务验收；Web不能直接开放原生监听端口，应由用户选择的原生节点/网关承载；不能声称浏览器本身已提供同等公网服务 |

上述任务与 NET-1–NET-8 共同构成完整目标，按 test.x 逐步完成；目前不能将整个插件网络系统标为可用或稳定。

内容型受管路由现可通过实际 Wasm exchange 读写原 Store，并在事务边界、缓存重放和交付时复验远端主体及逐对象权限；范围与限制见 [内容权限合同](PLUGIN_SERVICE_CONTENT.md)。这没有替代持久发布、主应用授权 UI 和完整因果审计的后续任务。
