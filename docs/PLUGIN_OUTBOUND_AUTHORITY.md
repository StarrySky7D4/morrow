# 持久出站批准与系统保护凭据

本合同对应原生出站宿主底座，沿用现有受管 HTTP 与原 worker。主应用已接通 Windows 凭据管理；端点授权页面、OAuth／账号管理与全平台凭据提供者另行验收；应用版本保持 `0.1.9-test.52+56`。

Windows 主应用的元数据分页、录入、替换和停用使用同一 Store 与 DPAPI 边界，详见[管理接口](PLUGIN_IO_MANAGEMENT.md)及[验证报告](../reports/credential-admin-web-2026-09-20.md)。保存凭据不自动授予插件使用权或恢复网络端点。

## 数据与系统保护

原 Store v20 的 `outbound_authorities` 保存两种严格 Protobuf＋LZ4 记录：

- Endpoint：插件包身份与摘要、固定规范 origin、网络 profile、允许方法、请求／响应／头／并发／超时／帧额度、可选凭据引用及 TLS 信任根。
- Credential：系统提供者标识和不透明密文。普通配置、请求原件和 guest 只包含凭据引用。

共同元数据包含非零32字节引用、递增修订、创建／到期UTC毫秒及禁用标记。最多512条记录，单条原文最多64KiB、密文及证书各最多32KiB；期限最多30天。引用种类与 provider／package ID 不可原地替换，使用新修订轮换或禁用，不删除复用身份。容量与原事件、请求材料、入站批准及配置共享。

Windows提供者使用当前用户 DPAPI，域与审计签名密钥分离。加密内部是 Protobuf＋LZ4，绑定引用、修订、创建和到期时间，并保存头名称和值；外层元数据失配、损坏或错误提供者都会拒绝解密。没有创建另一份明文配置、环境变量备份或独立密钥文件。旧审计密钥继续使用原有保护域。

秘密对象不实现 Debug。解密／编码／压缩缓冲区及长期保存的宿主凭据在释放时尽力清零；调用者输入和 HTTP 库内部副本不在这一保证内。提供者只接受有界 ASCII 头值，拒绝控制字符、分帧头和代理头。密码保险库与安全硬件能力不因使用 DPAPI 而自动获得。

## 恢复和实际使用

`StoredHttpEndpoint::resolve` 在原数据库固定授权锁下读取端点和凭据，检查原种类、引用、禁用标记及时间。`approve` 在调用提供者前核对原 Store、实际 Manager／Host／ManagedInstance／IoBinding、包摘要、HttpRequest 和 CredentialUse、规范 origin、网络 profile、TLS根及额度。

Windows使用 `approve_windows` 调用系统提供者；其他平台没有自动明文降级。自定义提供者回调是可信宿主边界，返回的引用必须与被批准的记录完全一致，不向 guest 开放。

每次会话仍须提供新生成的宿主秘密，重新签发不可预测的活动端点引用；持久记录引用与活动端点引用不等价。凭据引用转换为固定小写十六进制，匹配现有 IO 文本字段。凭据仅在通过授权后注入请求头，guest 不能覆盖；传输继续保持 DNS／TLS校验、禁重定向及禁自动重试。

DPAPI保护和记录校验不能防止已授权的远端服务回显密钥；返回材料仍可能包含远端提供的敏感内容。本接口不承诺任意响应自动脱敏。

## 撤销、更新与恢复边界

与入站服务共用原 Store 的稳定身份、协调锁和撤销代次。原生数据库副本、独占模式及显式原生 VFS 同样参与协调；Web和内存存储不恢复原生活动批准。

`ServiceUpdate::Outbound` 通过原 worker 提交修订。入队接受即保守撤销全部已恢复的入站／出站授权，实际 CAS 在原 Store 串行进行。前置拒绝不执行修改；接受后冲突或失败不恢复旧活动权限。缺少回执不是回滚证明，需要读取当前修订判断，不能盲目重复外部请求。

活动 HTTP 授权保留原数据库租约和共享 UTC／单调时间检查，贯穿路由、外部效果、后端等待、Ready/read交付。凭据或端点最早到期决定当前活动期限，时间倒退后不恢复。已发送效果仍可能存在，撤销不能撤回远端副作用；未知结果继续保持 Unknown，重启或重新批准不会自动重发。

v19→v20迁移保留原数据库身份、入站批准、配置、内容和证据。已升级库不能由旧程序打开。跨进程可信时间高水位、持久配置审计链、热替换及身份分叉仍为后续工作。
