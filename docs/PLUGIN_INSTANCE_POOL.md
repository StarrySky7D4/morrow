# 自动激活与共享实例池：test.33

实例池把已批准依赖计划接入真实PreparedPackage和HostRuntime连接。它准备代码并建立Ready连接，不启动独立操作系统进程、后台Worker或任意插件初始化回调。test.33起默认Windows工作台根使用此池；默认多包协作流程尚未接入，同步多层执行沿用test.31。

## 激活计划

`Manager::activation_plan(root, optionals, revision)`先核对当前revision，再只读解析根必需闭包和宿主明确选入的可选slot。每个可选项必须已批准且caller最终从根可达；无关、重复、缺锁、错摘要、未启用或不兼容的项拒绝。最多64个包，必需提供者排在消费者之前；可选边不构成启动排序约束，运行时仍拒绝实际调用环。

计划不可由外部代码直接构造，保存根ID、revision、具体包摘要、必需闭包、必需边和显式可选项。它不保存对象授权或产生运行实例身份。开始使用时仍通过当前Manager重新解析并建立实际连接，不从旧计划恢复权限。

## 共享与释放

Pool绑定一个实际HostRuntime，并在首次成功start时固定实际Manager身份。不同注册表即使选择同名同摘要包，也不能混用该池。每个Session有独立根实例，非根提供者按当前选定包在池内共享；停止一个根只释放它自己的占用，不停止仍被其他活跃会话需要的提供者。

Session是不可复制的持有者。Drop立即撤销其根权限并取消根任务；`maintain`进一步清理HostRuntime记录和不再被其他活跃会话需要的提供者。显式close/close_all可立即完成清理。Pool Drop撤销它持有的实例，但因HostRuntime由外部持有，不能在析构时替外部宿主断开记录；结束宿主前应调用close_all。

默认最多16个会话记录和64个共享提供者，也分别是本实现硬上限。失效但仍被用户持有、可供恢复的会话记录仍占会话额度；drop后维护或close才能释放。外部HostRuntime已有连接可能提前耗尽总容量，启动失败会关闭本次新建连接，不破坏其他会话的健康共享实例。

## 故障与显式恢复

maintain核对实际连接与当前Manager状态，先撤销失效实例及实际必需消费者，再清理连接。共享提供者失效不等于同名包所有实例都失效：另一个以该包为根的独立连接不会仅因名称相同被误停。可选子树失效不直接停止不依赖其必需闭包的根，但请求失效slot仍会失败。

Pool.run在调用前后维护状态。多层执行器仅向内部监督路径报告第一个实际出错节点的ConnectionBinding，Wasm trap、任务协议故障或guest执行限额触发该实际实例停止；不依据guest自报ID决定故障归属。业务失败、外部取消、图策略超限不因此停止健康实例。执行期间直接观察到的撤权也会在返回时传播和清理。

restart是可信宿主显式恢复操作，只能用于失效根；重新核对revision和当前批准计划，建立新的会话／连接。旧句柄和旧结果不能因恢复而重新有效；新根不继承旧对象grant，需要宿主重新授予实际目标权限。恢复不重放或重试任何Invocation，不自动提交内容。

默认每条会话恢复链最多3次尝试，硬上限8次；默认相邻尝试间隔1个宿主时钟单位，宿主可明确配置。准备失败也消耗已接纳的尝试；stale revision不消耗。成功恢复后继续沿用原恢复计数，而不是获得全新预算。时钟必须单调。这不是跨进程重启的持久故障预算，也不把新建独立会话当作原恢复链。

## 当前边界

真实Wasm资格覆盖共享、关闭、撤权、显式恢复和重新授权；独立测试涵盖真实陷阱、部分启动失败、容量及冷却上限。OS进程崩溃检测、异步多Worker调度、完整等待图、后台重启调度、默认多包协作UI、持久恢复预算和完整审计／隔离重放仍待实现。见 [test.32验证记录](../reports/test.32-instance-pool.md)。

## 普通任务与默认工作台

`Pool.run_task`承载现有普通命令和纯转换，无须依赖声明，也不会自动开放依赖导入。执行前后维护实际实例；错误handler或超输入注册限额先拒绝，不把宿主请求错误归为guest故障。实际trap、任务协议故障和执行限额停止根；业务失败不隔离健康实例。失效后不交付纯转换结果，已有真实命令响应仍保留，不因之后停止而伪称已提交操作回滚。此结果不是多层调用的RoutedOutput证明。

`grant_root`／`revoke_root`仅操作对应实际根的对象范围，调用者不能取出可变连接替换身份。默认工作台内容／服务任务使用run_task；InlineUi保持既有受限执行路径，由宿主根据实际故障停止同一根并维护。显式启用重新建立根，原表单代次不复活，任务不自动重试。结束时关闭UI和池后仍尝试持久审计封存，Drop只尽力清理实例，不替代finish的封存结果。

每次维护仍会重新读取并验证已选包及必需闭包。test.33只消除了同次resolve_enabled遍历末尾的根包重复加载，没有跨调用缓存；大包或高频任务的校验开销仍须继续量化与优化。
