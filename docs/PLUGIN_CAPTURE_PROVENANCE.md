# test.40：粘贴采用记录与编辑保存

Windows Rust 工作台的编辑器使用独立 capture scope，将实际插件转换、采用的片段、粘贴替换位置和最终编辑字段随内容操作原子保存。运行期采用预编译 Cap’n Proto；持久化使用预编译 Protobuf＋LZ4，意图类型为 `morrow.workbench.content-projection.v2`。内容库继续使用格式10，v1投影及旧证据解释路径保留。

## 编辑器与票据

打开编辑器时固定目标ID、创建／编辑基准修订、完整prior摘要、宿主、连接和插件包摘要。随机nonce和计数器产生scope／ticket标识；标识仅作关联，不是权限。停用、连接更换、包更新、关闭或闲置30分钟都会使旧scope失效，旧票据不能转给另一个编辑器。

每次实际 `capture.convert` 保留原观察，成功结果返回票据。RTF输出再次交给plain转换时，子调用必须使用父结果原Markdown，且父先于子执行。编辑器只登记实际采用的部分；被Office替换的早期富文本不进入最终批次。文字、分隔换行、附件链接可作为显式literal；plain来源也可选择原输入文字。重复采用同票据只保存一份观察。保存时保留采用票据及必要祖先，按原执行顺序排列，最后是一次真实 `workbench.command`。

每次粘贴记录字段、替换前后文字、UTF-16起止位置和有序片段。宿主按字符边界重建替换结果，拒绝切开代理对、越界位置、跨scope票据、身份复用但内容不同的事件及错误结果。Flutter先等待登记成功再修改控件。元数据通过独立有界分块通道传递：单次4MiB、每块32KiB、校验总长／SHA／偏移，避免完整编辑快照塞进普通64KiB请求。

## 保存、重试与固定投影

Flutter提交原始title／description／hypothesis／conclusion／todos快照，同时提交规范化草稿和选定附件别名。v2固定规则核对Dart trim（包括BOM及Unicode空白）、空描述默认值、清单去空及保持顺序去重、附件URI编码与别名替换。最终Card仍由原v1内容规则导出，完整prior／未知字段保留和Commit绑定检查沿用原实现。

编辑器在保存时冻结操作身份、草稿与字段；保存中禁止关闭。保存请求尚未发出时的确定性准备失败会解冻草稿，允许修正容量或附件输入；一旦发出保存请求，失败后保留原操作与输入，重试同一请求。宿主在取得最终实际观察后保存原始pending Evidence；提交错误不会换一个观察补写，另一个操作或修改后的意图被拒绝。成功提交后关闭scope。已经提交的历史重试可以在旧scope消失后核对原scope、原快照、操作和基准修订，以当前权限返回原结果，不覆盖最新内容。

附件缓存路径失效会从核心重新导出，完整读取成功后才推进界面使用的修订号。关闭未确认的编辑器后重新读取权威内容；读取失败明确提示状态未确认，不能将关闭理解成撤销。

scope只存在于当前进程内。关闭／进程退出会丢失未提交的scope，尚无崩溃后的未提交意图恢复队列。提交结果未知时必须先核对原操作，不能把取消当作撤销已提交事务。

## 容量

最多8个scope，单scope记账上限64MiB、总记账128MiB；每scope保留一份共享插件包，票据只保留观察。每scope最多1023次转换、1024个采用事件，最终批次最多1024条观察。每段字段／粘贴文字最多256KiB；最终工作台业务请求仍遵守原64KiB限制，不能把元数据容量理解为正文容量扩张。

交互期间共用1B燃料预算，所有尝试都计费；缺少可信执行报告时保守扣除预留额度，正常完成按实际消耗扣除。提交证据受既有12MiB意图／24MiB原PB边界约束。容量不足明确失败，不丢弃已采用片段；这些是有界对象记账规则，不是进程RSS硬限额。

## 证明范围

独立 `morrow-content-replay` 能从v2原件重建精确命令／完整结果，核对原Commit并逐观察实际重放。它不需要原资料库、目录或凭据。原件必须与固定的原Commit结合校验；一份自洽的新事实不是凭摘要就能认作伪造。

这里记录的是宿主观察到的转换输入、采用事件和最终编辑端点。HTML／Office节点由平台适配器提供，literal和附件别名属于宿主事实；不认证系统剪贴板原来源，不记录每次键入，也不能从最后字段反推完整编辑历史。Web／Android继续旧路径，不宣称已获得本阶段Windows存证能力。查询、依赖图、响应录制、签名提交间连链、未提交恢复与全局证据GC仍需推进。
