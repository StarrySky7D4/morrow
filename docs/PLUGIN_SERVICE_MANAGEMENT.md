# 主应用 API 节点管理接线

应用版本保持 `0.1.9-test.52+56`。已接通可信 Workbench Rust 管理接口、私有 Cap'n Proto 消息、Dart 原生适配及中英文管理表单；工作台监听生命周期仍需接入。配置管理通过不等于常驻API节点完成。

## 配置、认证与发布批准

`service_control` 始终通过原 Storage 和原 Store 工作，没有第二份配置或权限数据库。所有修改经过原存储的写入准备；后台任务独占原 Storage 时管理请求返回 Busy。保存是期望配置或明确批准，不启用插件、不创建实例、不打开监听器。

新配置生成独立随机 ID、稳定 namespace 和一个预留发布引用；后续修改保持 ID、namespace、服务身份和批准引用。调用方提交当前 Registry 修订、包 ID/摘要和明确 handler；保存检查原包可加载、服务协议摘要匹配、handler声明及 Listen/Publish 类别批准。配置保存不要求包已启用；实际运行必须另外重新准入。主体引用必须对应仍有效的认证记录；内容范围只是期望范围，不能代替执行时逐对象内容授权。

认证仅在明确创建或轮换时生成 256 位随机材料，使用 64 个十六进制字符作为 bearer。数据库只保存该 bearer 文本的 SHA-256 验证摘要；一次成功返回携带 `Zeroizing<String>`，普通列表不返回明文或验证摘要。回执丢失不能再次读取原 token，也不能自动重复轮换；应先查修订，再由用户明确发起新的轮换。内存清零覆盖本接口自有缓冲区，不承诺操作系统、不可写运行时缓冲区、未来UI或用户复制内容可清零。

发布批准精确绑定配置修订、完整容器摘要和预留引用，重新核对原包及全部认证；只接受当前服务契约支持的七种方法。路径、查询路径、监听地址及非回环强制 TLS 沿用原契约。`lifetime_days` 表示请求的最长天数；实际到期取请求上限与所有认证到期的最早值，UI必须显示返回的实际时间。这样一天认证也能申请不超过其剩余时间的发布。保存TLS批准不表示已提供证书或可以开始监听。

更新配置会使旧发布批准的摘要失配，必须明确重新批准。停用只核对原记录身份和修订，不依赖包仍存在、认证仍有效或目录可用；保留历史记录，不删除或复用身份。

## 稳定有界列表

原 Store 增加独立只读事务分页：配置每页一条，批准每页最多两条。每次最多检查128条配置或512条批准；全部行校验类型、长度、元数据与规范容器，包括页外记录。SQLite先过滤原始长度，避免将超限BLOB交给业务解码器。

快照摘要覆盖域、完整排序身份、修订及原容器摘要。续页需要精确存在的游标和相同快照；任意位置新增或改变容器均拒绝续页，包含相同修订被外部篡改的情况。历史过期/停用记录仍可读取，读取不刷新期限、不持有授权租约、不撤权。配置和批准是两份独立列表快照，不宣称跨表原子视图。

## 接线顺序与长期服务前置

1. 私有 Cap'n Proto 消息和 Dart 数据模型已接入七个管理动作，保留128 KiB帧、字段与总量限制；最大合法历史配置实测可返回。元数据与一次性令牌使用独立解析路径，修订以BigInt保存；Dart模型与原生编解码分离。中英文配置/认证/批准表单已接原生适配，未知写入只刷新，不自动重发。Web编译保持通过，不据此宣称浏览器支持原生服务管理或监听。
2. **区分监听寿命与单请求预算。** 当前IO声明及实例绑定寿命最多30秒，累计预算也不因请求完成而退款。这只能支持限时执行，不能作为常驻API服务的最终设计。需单独版本化服务运行租约、并发/每请求/累计额度及显式续租规则；禁止后台循环重新绑定来规避期限和累计限制。
3. `ServiceHost`、route和execution已泛型化到 `HostOwner`，真实原 `IoWorker<Storage>` 可用。`new_owned`在构造失败时归还原worker，`request_stop`与`try_reclaim`分离取消和真实join；`shutdown_owned`返回完整 `WorkerExit<Storage>`，无固定成功超时。旧HostRuntime专用构造/关闭与监听bind签名保留兼容，包含Storage的工作台入口必须使用owned接口。尚未接入主应用服务活动状态。
4. 在唯一StorageSlot增加服务活动分支，共用Busy、原实例、恢复和退出状态。原Store解析配置/批准/认证，同Manager与IoBinding重新授权后移交；监听runtime必须活到真实收尾。端口占用、绑定失败也须归还完整原Storage。
5. 停止分别等待监听监督任务结束和worker实际join，再恢复原库。EOF/关闭沿相同路径；不能用超时、强杀或新建runtime伪装回收。管理状态/停止/修复通过Busy门禁，在线修改若支持则必须走原worker更新队列。
6. 真实主应用入站读取/修改、认证隔离、持久请求查询、撤权、端口冲突、阻塞请求停止时的原库锁、封存失败恢复及重启核对。之后接入有证据的Unknown核对、完整因果链、文件系统及三语言IO SDK。

常驻期间原Storage独占使内容界面Busy，属于下一阶段必须解决的产品约束；不能用旁路数据库规避。应明确统一任务调度/访问边界，再作用户路径验收。方案尚未实现的步骤不列为已完成。

具体源码约束、版本化租约和完整WorkbenchState调度的实施顺序见[常驻运行方案](PLUGIN_SERVICE_RUNTIME_PLAN.md)。只有添加消息队列仍可能等待同步guest/broker请求完成，不能把它当作内容界面即时响应的最终实现。

## 私有消息与令牌所有权

新增消息54–60承载配置分页/保存/停用、授权分页、认证签发/轮换、授权停用及发布批准保存。宿主继续使用原Busy门禁；服务错误不携带底层路径。任意失败以全新错误消息编码，避免成功片段或令牌残留在旧消息段内。Rust清理令牌字段与序列化临时缓冲区，CLI在写入和flush期间保持Zeroizing所有权。

Dart先复制为独立模型再清零回复帧、编解码临时令牌副本及可写的接收缓冲区。只有签发动作可返回IssuedToken，调用方使用后必须dispose；普通元数据解析拒绝意外令牌。失败写入封锁整条连接，迟到回执不能交给下一请求；普通请求同样消费失败的pending Future，不留下额外异步错误。不会自动重试有外部效果的操作。

Windows真实进程测试覆盖原库重开、修订冲突、轮换/停用及被占用端口下仍能保存批准；测试包仅提供声明，未执行guest，因此不将此结果视为入站服务运行证明。历史TLS IPv6数值scope地址保留可读性。证据见[消息接线报告](../reports/service-wire-2026-09-20.md)。

## 主应用管理页面

插件库中的服务管理面板支持配置创建、编辑、停用；客户端认证创建、轮换、停用；发布批准录入、更新、停用。配置从当前已声明并获准Listen/Publish的包选择真实handler，主体必须显式选中；每主体逐项编辑七类内容操作及对象/附件ID。编辑保留已有范围，不因认证过期、包缺失或切换语言而悄悄删减。旧配置的包摘要固定，本页不做隐式包升级。

页面展示实际认证/批准到期时间，标识过期、停用与配置摘要失配。保存仍只记录配置/批准；TLS选项没有提供证书或开启监听的含义。停用无需包可用或认证未过期，重复停用按宿主幂等回执处理。页面只对实现原生管理接口的后端出现。

ServiceSession按后端身份保存进行中的操作及未知结果。读取完整的两份有界分页后才允许修改；分页失败不显示部分新列表。两份快照不是跨表原子视图，最终保存仍由原Store复验。已发出的写请求异常或回执身份不匹配会阻断后续写入，刷新不会自动重发或解除；必须由用户核对可信列表并明确确认后才允许新动作。

目录修订变化与中英文切换保留已打开表单的文本、无效输入和范围，目录变化必须明确更新选择才能保存。异步回包按后端身份、挂载代次和表单代次隔离。卸载结束未保存表单；已发出的操作及未知结果仍属于原后端会话。

令牌仅由一次性字节所有者保留，明确复制时才写系统剪贴板，复制期间防重复提交，成功或失败都清理页面持有的令牌。关闭最后一个面板或切换后端会清理；跨卸载的迟到令牌直接销毁，不在重开页面显示。系统剪贴板及UI渲染产生的不可变字符串不在内存擦除保证内。验证见[页面报告](../reports/service-ui-2026-09-20.md)。
