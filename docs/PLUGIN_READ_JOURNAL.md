# test.41：独立读取审计事件

内容查询不是修改卡片。`core::read_journal` 提供版本化的已完成读取观察，使用独立 `MORROWJ1` Protobuf＋LZ4容器，和原内容／工作区事务共用操作身份、证据块存储、待封存队列及签名链。数据库格式11允许明确的读取事件类型，不创建隐藏卡片、不调用空SetContent，也不推进正文修订。

这是默认查询存证的必要存储基础。当前默认 `Workbench::query` 尚未自动使用本接口；候选清单、完整分页与归并观察、权限政策及最终结果投影将在查询适配层接入。本阶段的SDK测试独立记录一次实际Query转换，不代表默认查询已经完整存证。

## 固定原件

`Input` 包含operation_id、subject、request_type／request与response_type／response。`ReadObservation` 在其上固定版本、两段原始数据的SHA-256及有序TaskEvidence摘要。字段在Protobuf分配之前检查类型、长度、数量及重复；未知可选字段保留原字节，未知版本和group拒绝。原件持有原PB、完整容器及原PB摘要；外层头固定原始／压缩长度和原件SHA。

请求和响应各最多4MiB，原事件最多16MiB；这不是工作台128KiB传输帧的容量承诺。最多16份Evidence、原PB与完整容器合计64MiB逻辑限额保持不变，重复位置照常计费；底层32KiB物理分块可共享，不以物理去重放宽逻辑预算。

签名针对包含原容器的审计段，不解析后重编码验签。摘要只固定输入与输出，不证明读取来源、插件执行、语义正确或用户已收到结果。业务适配层仍须把原件与同一次授权读取、实际转换及版本化结果投影绑定。

## 原子提交与重试

`Store::record_read_local_authorized(&Input,&[Evidence],authorize)` 是可信本地核心接口。它在同一BEGIN IMMEDIATE事务校验输入和既有操作，写入object_kind=4的操作、原件引用／块、outbox和永久事件序号，最后调用可信授权检查再COMMIT。它不是可由插件传入任意检查器的公开权限入口；当前分派协议未将其暴露为插件特权。

读取scope用subject表达，数据库沿用operations.card_id列承载该值，通过kind明确区分。subject不意味着用户Card存在。所有已有Card／Workspace／Placement／Draft写入路径保持类型隔离；相同操作ID不能跨类型复用。查询`lookup_read(subject,operation)`及`read_evidence`在同一事务快照核对原件与引用，不存在、非读取操作或不同subject返回None。

同ID重试必须匹配原请求、响应、类型、scope及有序证据；再次执行当前授权检查，返回原回执，不读取最新数据来换掉原结果。真实COMMIT失败返回CommitUnknown，不能据此假定已回滚；调用者应核对原操作。该API不会重新执行查询，也不建立未提交意图恢复队列。

空Evidence允许可信宿主记录不经过插件的直接读取；存在Evidence时存储层核对格式和引用，业务内容与实际观察的因果校验仍由适配层负责。不要把“已存储观察”解释为“所有查询已被记录”或“接收端已确认”。

## 完整性、签名与快照

pending读取、核心审计的operation_id解析、签名段核验、Store完整性、证据孤立项／块引用及快照都显式识别新容器和kind。读取事件不得关联内容附件操作引用；修改subject、kind、原事件或证据关联会被拒绝。既有内容卡片最新修订检查只使用kind=0，不会被读取事件打断。

10→11先校验旧状态、更新版本、再次校验，在同一事务提交；边界为`read-journal-migration-before-commit`和`read-journal-migration-after-commit`。旧格式4～10可按阶段迁移；完整只读审计入口沿用5～11支持范围，格式4需先迁移。旧格式不得夹带新kind4／新读取容器。迁移不重编码历史Commit、Evidence、签名或物理块。快照沿用原协议保存经过完整性校验的数据库，恢复时同样执行格式门禁。

## 查询界面准备

Flutter查询协调器使用结构化条件、内容generation、后端身份和递增serial。快速输入等待200ms，只保留最新待发查询；已发出的宿主查询继续完成，不宣称取消guest。组合输入期间暂缓发送，切换条件、内容变化、插件启停／包变化及dispose都使旧结果失效，A→B→A不能采用第一次A的晚响应。

加载和失败时不把旧投影当作当前已确认结果；失败提供真正的重试入口。最多一个已发请求及一个最新待发条件，避免每个中间字符排队阻塞保存。结果ID仍映射现有本地卡片缓存，尚不证明显示内容与读取修订一致；这需要后续查询投影／按修订刷新。

完整查询接入必须保留原排序语义并记录全部实际调用，不能把多页排序缩成一个观察，或直接套1024观察上限而降低已有容量。当前“最近添加”实际为枚举ID序列反转，标题为UTF-16稳定排序；候选集合完整性、分页终结、错误／取消和结果交付仍需分别设计。验证记录见[test.41阶段报告](../reports/test.41-read-journal.md)。
