## 测试版本推进规则

`0.1.9-test.1+10` 是 `0.1.x` 最后一个兼容现有数据类型的测试版。自 `0.1.9-test.2+11` 起推进大规模重写，后续测试版可能对现有数据类型和存储结构产生破坏性变更，不承诺跨测试版无损升级／回退；参与测试前应备份资料。核心架构、数据模型锚定并通过下述验收后发布 `0.2.0`。后续对外测试版本依次使用 `0.1.9-test.2`、`0.1.9-test.3` 等编号，构建号同步递增。阶段编号与测试版编号分开管理：同一阶段可以跨多个测试版本，一个版本也可以包含多个已验证任务，不预设最终的 test 序号或发布日期。

首个测试版本加入全局主题色彩色罗盘，支持色相、饱和度、明暗和 HEX 输入，统一组件与控件配色；可实时预览、取消还原、应用保存和恢复默认。主题种子与纯色画布色独立保存，组件颜色按深浅主题调整明暗；原有卡片内容颜色不被改写。该界面改进不代表 Rust 核心或插件系统已经实现。

直到插件系统完成以下验收，持续使用 `0.1.9-test.x`，不因最小原型通过而提前转为稳定版：

- M0–M2：内容与视图模型、协议契约、唯一权威存储、原子提交及旧数据迁移保护建立。
- M3–M5：插件 A→B 的授权执行、不可变共享对象、撤权与取消、审计封存、独立验证和隔离重放闭环通过；该闭环是必要条件，不是完整系统的充分条件。
- M6：真实插件接入，安装、启停、升级、依赖与版本冲突、资源限额、故障恢复和卸载保留内容均有测试证据；第一方插件遵守相同边界。
- M7：针对声明支持的平台完成端到端验收，能力矩阵明确可执行、可读取与暂不支持的范围，补齐分发、恢复和兼容性说明。全平台仍是目标，未验证的平台不得标为完整支持。
- 汇总上述证据后作发布评审；MorrowCloud 仍是可选普通插件，其服务是否上线不成为本地插件系统的前置条件。

每个测试版本记录实际完成任务、验证结果、已知限制和剩余验收项；发布编号只表示迭代顺序，不替代验收证据。当前实现与后续迁移任务分开标记，既有 0.1.8 构建和调研记录保留原版本与日期。

## 2. 当前起点与目标边界

当前开发版本为 `0.1.9-test.42+47`；架构调研起点为 `0.1.8+9`。Windows 默认工作台已由 Rust 宿主、受限 Wasm 业务插件和核心格式 11 内容库承载，接入系统账户保护身份、自动封存、原保护文件备份／恢复，库内一致性快照，以及同身份副本并发占用。Flutter 仍负责界面、输入及平台媒体；Web／Android 保留旧路径，旧 test.1 数据没有自动迁移。详细已验范围见 [功能对照](TEST1_RUST_PARITY.md)。

现有工程与构建证据不等于动态插件系统或全平台验收。工作区／视图的完整产品接入、依赖协作、共享内存生命周期、完整宿主审计、独立见证与重放仍按下述任务推进。`test.1` 基线保留在 `a3c1766`；后续验证使用独立合成资料，不能将其作为真实用户资料迁移成功的证据。

固定方向：

- 卡片是内容，插件提供能力，瀑布流是视图；Card、Workspace、ViewPlacement 分开。多视图引用不复制内容、不改变身份。
- 卡片包含类型、格式版本、修订、正文、附件和关系。插件缺席时保留基础信息、已有预览、未知字段与原始附件导出。
- Flutter 保留即时 UI 状态；正式内容、持久草稿、配置和修改由统一核心控制。迁移后 Dart 与 Rust 不得各自保存一套权威数据。
- Flutter＋可移植 Rust 核心＋平台适配＋可替换插件执行后端；独立验证工具复用核心。同进程 Flutter 与 Rust 不宣称强安全隔离。
- 全平台目标覆盖 Windows、macOS、Linux、Android、iOS／iPadOS、Web，并保留其他平台接入边界。统一业务语义，分别验证执行和系统能力。
- 大规模模块化、选择性插件化。随包编译且可禁用的第一方模块不等于动态插件或安全沙箱；正式插件没有官方私有绕过入口。
- MorrowCloud 是按普通规则接入的独立官方服务插件，不成为安装、本地使用、恢复或见证的唯一依赖。

仍待验证的是数据库、桥接库、Wasm 运行时、解释执行等后端、进程数量、插件 UI 表达、内存与超时参数、封存证明结构及性能阈值。不得将某一运行时写成全平台前提。

## 3. 首轮贯通目标与阶段顺序

首轮使用两个受限测试插件：A 请求宿主交付获授权的固定输入；宿主以 Cap’n Proto 和受控共享对象分派给 B；B 执行纯转换或计算，返回结果提案；核心再次核对权限、对象与修订，提交卡片及对应事件；封存后，独立工具核验证据，并在隔离副本中重放。

A、B 仅用于验证宿主接口，不需要先建设插件市场或全部业务 UI。即使是第一方测试插件，也不绕过授权、内容提交与审计。

| 阶段 | 交付 | 退出门槛 |
| --- | --- | --- |
| M0 基线与验证设计 | 数据及修改基线、约束映射、故障矩阵、平台矩阵 | 完整总结的约束均有任务承接；匿名数据可恢复 |
| M1 内容与协议契约 | 内容身份、消息与持久化契约、类型化适配、平台探针 | 正常／旧版／未知／畸形向量有一致结果；公共契约不依赖平台句柄 |
| M2 可靠持久化及提交 | 统一写入入口、修订与去重、附件暂存、原子事务事件、CLI | 创建→提交→重启恢复通过；内容与必要事件同时成立或同时不成立 |
| M3 共享对象与权限原型 | 受限 A/B 宿主、mmap／平台传输、不可变发布、授权、依赖与停止 | 同一固定输入用于检查和执行；越权、陈旧实例、映射未释放等场景通过 |
| M4 审计封存与故障恢复 | 原始字节完整性保护、幂等封存、检查点及恢复状态 | 提交后封存中断可恢复；篡改可检出；审计无法承接时阻断需要该保证的新操作 |
| M5 受限重放与首轮验收 | 历史程序／依赖／输入证据、独立验证器、隔离重放 | A→B→卡片→封存→验证→重放整条流程通过，并通过失败路径矩阵 |
| M6 真实业务插件与迁移 | 旧资料迁移、卡片工作台、项目／实验／音乐等选择性插件化 | 唯一写入权威；插件缺席不丢数据；业务字段通过注册扩展 |
| M7 平台一致性与可选服务 | 分平台运行及发布资格、通用服务接口、Cloud 插件 | 各平台独立证据；Cloud 无核心特权，停用及云端附件提示行为正确 |

主路径为 M0→M1→M2→M3→M4→M5→M6→M7。平台可行性、协议互操作和性能测量从 M1 贯穿后续阶段；M7 不是首次移植。缺少某个平台工具链时，明确该平台阻塞项，其他平台可继续验证，但不标记全平台完成。

迁移样本与 UI 模型提取可提前准备；批量切换用户资料和真实业务插件交付必须经过 M5。M2 是首个可运行中间成果，不能代替首轮贯通验收。

## 5. 必须落入实现与测试的契约

### 5.1 协议、持久化与原始内容

| 用途 | 固定规则 |
| --- | --- |
| 宿主↔插件、插件↔插件 | 预编译 Cap’n Proto；原生 IPC 以受控 mmap 为主要后端，其他平台实现对应传输 |
| Flutter↔Rust、宿主↔Wasm | 可使用 Cap’n Proto 传递结构化数据；FFI／内存适配／消息承载，普通局部函数直接调用 |
| 卡片、配置、插件状态、依赖锁定、持久授权配置 | Protobuf＋LZ4 |
| 审计、诊断日志、检查点、缓存、任务恢复状态 | Protobuf＋LZ4；记录角色和权威性分别管理 |
| 快照、重放证据、备份、导出、自有外部交换 | Protobuf＋LZ4；原始载荷保持原字节 |
| 用户原始内容、旧迁移、不可控第三方接口 | 可保留 JSON 例外；不得成为核心正式格式或双协议转换中间层 |
| 原始图片、音视频、文档、建模文件 | Protobuf 描述与引用，不做无关格式转换；存储引擎页／索引／事务文件由引擎管理 |

所有 schema 版本控制、预编译；运行前确定接口、版本和摘要，运行时继续执行结构、长度、分段、遍历和资源校验。宿主特权协议与独立版本化业务协议分离，新增专业业务不必修改核心；业务载荷不能夹带特权操作。

可读配置和调试输出只能是派生视图，不是第二个正式记录来源。适配器不以 JSON 重建消息；需验证跨语言未知字段及不透明业务正文的保留。解压前后限额，压缩与编码不替代事务或授权。

### 5.2 共享对象与权限

共享对象绑定身份、代次、长度、段信息、内容摘要、授权范围与租约。检查、实际执行、审计摘要、重放材料必须对应同一固定内容。

发布不可变性是硬约束。接收方只读不能证明生产者没有可写别名；无法证明时在可信边界复制固定内容。FFI 指针、mmap 偏移、Wasm 内存偏移和权限句柄不持久化为有效能力，历史证据中的引用也不能直接复活。

退休、租约到期或代次变化不等于现存映射已经失去访问能力。**旧映射尚未确认释放，原页面不得分配到另一权限范围。** 正常释放、异常进程退出和无法确认释放的情形要各有处理；不能仅依赖计时器／代次计数回收。

宿主根据用户授权、工作区策略、平台能力和上下文授予实际权限，清单只是申请。内容、搜索结果、变更日志、附件名、缩略图和网络访问保持同一授权范围；插件创建卡片不产生永久控制权。调用者由宿主绑定，激活产生新实例代次；撤权和旧结果均不能触发新的有效操作。

### 5.3 生命周期、依赖与故障隔离

插件包、启用状态、运行实例、任务、卡片视图分层管理。正常流程为安装校验→静态注册→依赖解析→受限准备→发布就绪→执行→停止接单→限时排空→撤权与回收；安全停止先撤权，再取消与终止，不等待插件配合。

按任务、服务和实例范围隔离故障。自动恢复必须有限额，连续失败进入可解释隔离状态；网络请求失败不能默认升级为整个实例重启。停止不能撤销已提交内容，超时不能认定尚未发生外部效果。

依赖指向版本化接口，宿主锁定提供者、包摘要及服务代次。必需／可选依赖和推荐安装集合分开，依赖不传递权限。强启动依赖环拒绝；运行时处理等待环、事件循环、期限和取消传播。提供者更新或崩溃要重绑定，旧服务句柄无效；停止消费者仅释放自己的租约。

### 5.4 审计、恢复与重放

审计由宿主产生；插件诊断仅解释进度；证据保存历史程序、依赖、输入、状态和必要宿主响应。正式审计原件按固定 Protobuf 字节保护并 LZ4 分段持久化；签名验证使用原始字节，不能解析重编码后验证。具体算法、密钥保护和证明结构通过原型选择，但原字节规则已确定。

本地内容修改与对应事务事件／待封存事件原子关联；封存按稳定事件 ID 幂等进行。状态必须准确区分未提交、已本地提交、已封存、已独立见证、结果待核对。审计无法承接必要事件时，不继续执行需要该保证的新操作；封存积压、容量不足与不可恢复错误的判定策略在实现中明确测试。

保证插件不能修改账本、封存历史可验证、有较新独立检查点时可检测相应回滚。不承诺攻击者控制全部宿主、密钥和副本后仍不可伪造。签名不证明业务结论正确；Cloud 可传输归档或检查点，但无签名权，也不是唯一见证。

首期所有受控业务操作可追溯，内容修改可重建；纯转换和计算优先确定性重放，外部效果使用录制式重放。默认隔离副本执行，不真实上传、不写生产资料库、不用生产凭据。证据过期、删除或环境缺失后必须更新重放状态；摘要不能充当已丢失的证据。用户内容与已经形成的证据不能随插件失效或卸载而消失，证据保留期限另按明确策略执行。

| 正常纯任务／具有外部效果的任务 | 前者复现受支持结果；后者用录制响应，无真实上传或生产副作用 |
| 完整链路性能 | 计量复制、校验、压缩、持久化、重绘和回收；使用固定环境比较，不只测编码速度 |

## 8. 平台与 Cloud 验收

M1 即验证 Windows、Android、Web、macOS、Linux、iOS／iPadOS 的核心、桥接与执行后端风险。公共协议无 Windows 路径、OS 句柄或特定剪贴板格式。原生 mmap、Wasm 内存和浏览器缓冲区分别验证保护及停止能力，不宣称完全等价。

跨平台测试复用命令语义和故障向量，平台各自证明存储、资源释放、密钥保护、强制停止、文件访问、生命周期和分发机制。能力不足明确报告、拒绝或经确认降级；“能够读取卡片”和“能执行该插件”分开报告。平台工具链与设备缺失是该平台验收阻塞，不以编译通过代替实机证据。

MorrowCloud 仅通过通用接口读获授权内容、消费变更、访问附件、提交远端修改。账户、服务协议、映射、检查点和品牌 UI 在插件；核心不含品牌专属账号页、地址、同步业务或收费状态。安装和本地使用不要求 Cloud 登录。

停用／卸载 Cloud 保留已有本地内容。对仅存云端且尚未下载的附件提前明确提示，不能承诺离线可取回未下载数据。Cloud 的归档传输不能获得日志签名权或成为唯一见证。先由非 Cloud 测试服务证明通用接口，再实现官方服务插件。
