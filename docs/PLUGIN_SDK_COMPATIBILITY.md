# SDK guest 兼容候选基线

状态：test.48 开始建立 `guest-v1-rc1`。它是第一份兼容配置，不是 guest ABI v1，也不是整个 SDK 已发布稳定版。实际配置：guest ABI **2**、运行协议 **7**、任务协议 **3**、UI 协议 **1**、依赖调用协议 **1**。SDK 源码包版本、应用版本、包 SemVer 和上述协议版本分别管理。

## 兼容承诺的对象

候选基线要求后续宿主仍可装载并执行已经保存的 C、C++、Rust Wasm 原件及完整 `.mplugin` 包。不得通过重新编译 guest、替换其编解码库或重建 Manifest 来使检查通过。编译进 Wasm 的旧 SDK 和标准库也是这份二进制的一部分。

原件位于 [guest-v1-rc1](../sdk/compat/guest-v1-rc1/)。13 个 Wasm 和 13 个完整包覆盖三种语言的内容任务、纯转换、基础 UI 和依赖调用；另一个 Rust 提供者服务于三语言依赖测试。清单另保存八份契约快照、源码摘要与构建来源，共 36 个受摘要约束的文件。全部原件从 `19fa955d9b7a4eed1cd9b40fb0f787defbe4a33b` 对应的 SDK test.11 源码重新编译一次后固定，并非从此前发行附件提取；这是从现在起可跨宿主版本复验的起点，不补作过去版本的兼容证明。

| 接口范围 | 候选范围 | 未由此承诺 |
| --- | --- | --- |
| 内容命令 | 创建、编辑、重命名、摘要、操作查询、正文及附件片段；关联回执、幂等与当前授权 | 工作区、关系、完整草稿或附件上传 API 已齐全 |
| 任务与纯转换 | 固定导入、任务输入、完成、输出及业务失败；已声明预算下的合法旧模块 | 精确 fuel 消耗、执行耗时、trap 文本或所有资源上限永不变化 |
| 基础声明式 UI | form→当前宿主解码→事件→旧 guest edit→当前宿主解码；旧会话事件拒绝 | Flutter 像素布局、Dart 控件 API、专业编辑器或每类节点的穷举覆盖 |
| 依赖调用 | slot 绑定、批准锁、动态字节输入、关联输出、提供者撤权及提交授权 | 所有异步调度、服务型插件、完整依赖图审计重放已完成 |

本地 C 回调 ABI、跨动态库的 C/C++ ABI、Rust 源码 API 和编译器兼容性不由这组 Wasm 测试证明，继续标为实验。宿主 Manager、实例池、共享对象实现、数据库和 FFI 内部布局也不随 guest 基线冻结。安全缺陷修复可以收紧非法输入或撤权后的行为，必须记录原因及合法旧插件的回归结果，不能把兼容承诺解释为保留绕过校验的漏洞。

## 契约演进规则

当前包加载器精确匹配运行、内容、任务和适用的依赖 Schema 摘要；摘要对 CRLF 归一为 LF 后计算，注释和其他空白仍参与计算。UI 摘要在 UI 文档／事件内检查，不是仅检查 Manifest 即可证明 UI 兼容。

因此，这些旧契约文本不能因“只是补注释”而直接改写。需要演进时，应先设计并验证显式的新契约／能力，以及旧版本解码和路由路径；不得简单接受任意旧摘要、跳过校验或重打包旧样本。新契约使用新的正负样本，与旧基线并存。兼容失败先作为待解决回归，不能自动更新摘要。

弃用前要标明受影响的契约、替代方式、支持边界和迁移验证。当前尚未承诺某个固定年限或完成多版本协商；RC 基线通过仍不代表可立即移除旧接口或对外宣布完整稳定 SDK。

## 每次 SDK／宿主变更的检查

```powershell
pwsh -File tool/verify_plugin_sdk_compat.ps1
```

该入口当前完整执行需要 Windows；其他平台可单独运行只读摘要检查，但不能把跳过 Windows 依赖测试报告为完整通过。它先检查清单根摘要、固定条目集合、全部文件及负面夹具，再编译当前宿主的集成测试，直接执行旧原件，最后再次校验摘要。它不调用任何 guest 构建或捕获工具。运行时 `cargo test --features packages` 同样包含这些集成测试，具体平台条件见测试文件。

`verify_plugin_sdk.ps1`、`verify_plugin_runtime.ps1`、`verify_plugin_ui_sdk.ps1` 都在重新构建当前示例之前调用此入口。当前 SDK 编译测试与旧插件原件兼容检查是两项不同的证据，二者均须保留。

摘要和根摘要锚定版本控制中的原件，只用于回归一致性；它们不是发布者签名、来源认证或对可修改整个仓库的攻击者的防护。`.gitattributes` 禁止 Git 修改原件行尾。固定包内嵌模块必须与旁边裸 Wasm 完全一致，不能替换成另一个同名 profile。

## 新增基线的显式流程

本轮使用现有三语言构建脚本，Rust 五个示例独立构建，随后调用 `core/examples/capture_sdk_baseline.rs`，最后调用 `tool/seal_plugin_sdk_baseline.py`。完整命令及工具版本保存在原件的 `provenance.txt`。捕获工具拒绝已有目录，封存工具拒绝已有清单／根摘要；失败后留下的目录用于诊断，不隐式覆盖或修补。

新增版本时先在新目录建立新 ID，审查构建来源、能力声明和用例，再明确新增清单、根摘要及验证覆盖。旧目录和旧验证继续保留。不能在普通验证中加入自动生成／更新原件选项。本轮记录编译来源和产物摘要，未验证跨机器可复现构建。

## test.48 的实现修复与基线关系

完整当前 SDK 检查发现原生 UI 事件解码依赖输入地址的 8 字节对齐：同一固定消息在对齐缓冲可解码，偏移 1 字节返回 UnalignedSegment。test.48 将请求、响应、任务及 UI 四个读取入口统一到安全的 OwnedSegments 读取，接受任意字节偏移；保留原消息长度、分配前总字数预算、嵌套深度和尾随字节拒绝。未启用跨依赖统一的 unaligned feature，没有新增 unsafe，也没有改变 Schema、接口签名或原黄金样本。

该修复改变当前 SDK 的内部解码实现；旧基线的 SDK 实现已经编译在原 Wasm 内，仍保持原件。必须分别验证新 SDK 的非对齐输入和旧插件在新宿主上的运行，不能把修改旧包内部代码称为旧二进制兼容。

## 仍需完成的 SDK 稳定化工作

基础 guest 候选还需后续真实宿主变更持续复验、独立第三方插件接入、开发模板与分发说明，以及平台支持矩阵。扩展 UI、完整内容 API、异步长期任务分别按能力推进。SDK 可分层稳定，不等待全部产品功能完成；也不能把这一基线当作安装管理、数据迁移或全平台验收已完成。
