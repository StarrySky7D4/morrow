# S013 未来插件需求 → 当前 SDK 能力审计

本轮仅只读核对当前源码、固定契约、已有测试源和已有资格记录，未获取依赖、编译、执行插件或运行测试。Codex acquisition继续暂停，不作为Windows SDK冻结阻塞。JSON逐项保存API/权限链/验证门槛/缺口及所有引用源SHA256；测试源存在不计本轮测试通过。

当前SDK能支持有界内容操作、纯Transform、批准slot纯依赖调用和六节点表单；有界HTTP/服务、Create/Delete是分别版本化的实验扩展。公开实验 channel 已支持 host 显式交付的有限本地 bytes/events；未来 Responses 网络流、授权 Cloud 变更订阅、完整 Cloud 同步、Codex 常规 exec/session、大对象与专业 UI 仍缺公共 SDK 闭包。宿主stream/监督/私有Workbench协议不能填成公开三语言接口。

## 冻结判断

未发现未来共用能力必然要求破坏现有Wasm ABI的证据。纯业务格式适配可复用既有Transform；新的共用能力可以沿当前独立opt-in/profile机制演进，但仍要实现其真实授权、数据、生命周期与版本路由。Package静态feature白名单不是一般运行时能力协商。旧schema精确SHA是门禁：即使新增字段或改注释，也不能直接覆盖旧冻结schema/原件。

冻结是否被未来功能阻塞取决于明确宣称范围：若仅冻结现有有界Windows guest profile，未来缺功能本身不必阻止；若宣称开发者现在能完成本矩阵完整Codex/Cloud/流式网络，这些缺口就是实质阻塞，不能用样例数量或重新编译旧包掩盖。本审计不把范围自动缩小，最终范围及本轮兼容回归由父线程确定。
