# 应用服务 TLS 接入

2026-09-21：可信 Rust 启动入口、私有协议及 Flutter 选择界面已接通。最新有效期阶段基于 `75d69e1`，版本仍为 `0.1.9-test.52+56`。原生边界见[原生报告](../reports/application-service-tls-native-2026-09-21.md)，界面与真实 Windows 验证见[接入报告](../reports/application-service-tls-ui-2026-09-21.md)。

## 已实现的契约

- `TlsSelection::inspect` 接收明确选择的本地证书链 PEM 和私钥 PEM 路径。每个文件 1–65,536 字节，实际读取也有上限。校验 PEM 与证书/密钥配对，返回选择对象；对象保存路径、完整证书 PEM 的 SHA-256 和证书链共同有效区间，无 Debug，不保存原始私钥。
- 启动调用 `Workbench::start_service_with_network`，同时传入原有服务启动参数、明确出站端点和可选的 `TlsSelection`。原有两个入口继续选择无 TLS，未产生默认升级或降级。
- 已批准 publication 的 `tls_required` 必须与所选身份存在性完全一致。明文 HTTP 仅允许批准的 loopback 地址；TLS 沿用已批准地址。不会修改防火墙或自动扩大监听范围。
- 移交原工作台拥有者之前重新读取文件，核对证书 PEM 摘要，再校验证书/密钥配对。改变、删除、损坏文件导致准入失败，不消耗该启动 submission 或移动原拥有者。
- 运行中的监听器持有内存中的 TLS 身份。磁盘更换文件不会自动更新证书；停止、重新检查选择并显式启动才可采用新身份。正常取消、监听器 join 和原 worker 回收保持原流程。
- 路径要求绝对路径，拒绝可见的 symlink/reparse、父目录回退，以及 Windows UNC、设备与 ADS 拼写。读取前和打开后检查普通文件属性；Windows 打开叶节点时使用 `FILE_FLAG_OPEN_REPARSE_POINT`。读取缓冲区使用 `Zeroizing`，错误不携带路径、PEM 或库内部详情。

这是可信用户选择文件的有界加载器，不是抵抗恶意并发文件替换的文件系统沙箱；检查与打开之间的父目录/普通文件替换并未被消除。现在解析所提供证书链的共同有效期，启动时重验，并将到期限制绑定到原服务授权；域名、签名与信任链政策仍由连接客户端验证。不要将已加载的服务器身份描述为完整证书生命周期管理。

## 下一步

私有 `serviceTlsInspect` 普通业务命令现返回精确路径、证书摘要及共同有效区间（Unix 秒）；运行中沿原拥有者业务通道检查，启动仍通过独立调度通道。`ServiceRunStart.tls` 可选值冻结证书选择，Rust 准入重新加载；仅传路径和摘要，不传私钥内容。路径按 UTF-8 限制 4096 字节并拒绝控制字符。该协议是应用私有通道，不是 guest IO ABI。

Flutter 为 TLS 发布提供本地 PEM 选择、检查和证书摘要展示。未检查、检查失败、改选文件或后端不支持时不能启动 TLS；变更发布/后端会清理旧选择。取消文件选择保留原路径但使检查失效，需要再次检查。普通刷新及语言变化保留当前草稿；启动请求拥有不可变摘要，Unknown/重挂不自动再次启动。实际 Dart→Rust 与 Windows 窗口证据已覆盖 HTTPS、原库写入和回收；窗口测试的文件选择结果是确定性注入，尚不是系统对话框验收。

证书链共同有效区间以 UTC 显示；未来/过期选择不能启动，时钟恢复后须显式重新检查。Rust 重新读取实际证书，不信任 UI 时间数据。到期、原授权撤销或时钟回拨使原 live authority 失效，缓存响应和新请求均重新校验，监听器进入原停止/回收流程；这不承诺强制中断任意同步回调。详见[有效期报告](../reports/application-service-tls-validity-2026-09-21.md)。

受保护密钥的独立封装与原生加载器已完成，见[保护阶段报告](../reports/application-service-tls-protection-2026-09-21.md)。它们还未接入数据库或应用服务启动；现有 UI 仍从明确选择的 PEM 加载。下一步为原 Store 的受保护记录、修订 CAS、活动依赖撤销及显式轮换界面，再继续 Unknown 持久核对、完整文件系统和 C/C++/Rust IO SDK。当前没有自动续期、ACME 或客户端证书认证。

公共 guest ABI 未改变。原生测试通过不代表 C/C++/Rust IO SDK 稳定、公网部署合格或其它平台已验证。
