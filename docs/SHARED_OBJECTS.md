# 受控共享对象与只读租约（test.26）

这是原生可信宿主资源服务：共享对象描述使用固定 [Cap’n Proto 契约](SHARED_OBJECT_DESCRIPTOR.md)，实际页面由 [Windows 私有只读映射](../plugin_runtime/SHARED_MEMORY.md)持有。它不是第三方插件可自行授予的权限，也不是完整跨进程 IPC 或 A→B 依赖系统。

## 生命周期与可信边界

`SharedObjects::new(&host, limits)` 绑定真实 HostRuntime 的不可解析身份；另一个同进程 HostRuntime 的合法连接也不能使用该 broker。发布、批准与撤销均为可信管理调用，scope 必须来自宿主授权策略，不从 guest 自报身份推断，也不因现有内容能力批准而自动获得共享数据权限。

`publish` 先核对生产者连接，再复制到私有原生映射。删除唯一写视图、建立只读视图后，才对固定字节计算 SHA-256 并生成描述。对象不做跨范围去重，编号在 broker 生命周期内单调分配、不复用，当前每个新对象 generation=1；没有原地改写或同 ID 更新 API。

`grant` 精确匹配描述、scope、消费者连接及期限，新授权还要求原生产者就绪。Lease 为不可自行构造的进程内对象，不序列化、不持久化，复制描述或摘要不提供权限。已授予的消费者租约与生产者后续停止分离，仍受对象退休、租约撤销、期限和消费者状态约束；没有隐式权限继承。

`map` 每次检查实际宿主、消费者实例代次、租约和期限，返回只读 Mapping。旧 Mapping 已持有的内容不能“收回”：撤权或退休阻止新映射、新执行及结果交付，原 Mapping 在释放之前仍可读取原字节。`retire` 删除新访问入口并撤销该对象租约，旧对象只以弱引用留作记账，真实 Mapping 持有其页面直到 Drop。

不存在跨范围页面池，也不把退休的分配重新贴上新 scope。只有最后 Mapping 确实释放之后，旧对象预算才不再计入。显式 `collect(now)` 可删除到期授权，但不会据超时强制释放仍有读者的页面。编号、描述和 Lease 只适用于当前进程，历史引用不恢复权限。

## 预算

默认每 broker 最多 64 个尚占用分配、32 MiB 计费额度、256 个租约、128 个活跃 Mapping。对象最多16 MiB，每对象按64 KiB向上计费，退休但仍有 Mapping 的分配继续占额度。这是保守的映射分配额度，不是整个进程的 RSS、插件内存或所有 broker 的全局总量保证。

只读 Mapping 不能 Clone，但可独立映射同一获授权对象，数量受上限约束。租约自身不持有页面。预算不依赖公开描述的伪造长度：实际分配、摘要和长度在发布时从冻结内容产生。

## Wasm 接入

`run_transform` 接受固定 Mapping 和处理器元数据，自行构造 Invocation；调用方不能另传一份待执行正文。最多64 KiB的输入被复制到普通 Wasm 任务，包注册仍校验输入／输出类型和预算。原生映射地址不是 Wasm 线性内存偏移，当前不宣称零复制。

执行前和结果返回前分别读取可信单调时钟并核验消费者、租约、对象。过期、撤权、退休或错误绑定不能交付新的有效结果；无效外来句柄也不能推进 broker 时钟使其他合法调用失效。纯转换仍由既有执行后端禁止宿主内容命令，取消／fuel提供有界执行，不承诺即时终止。

结果只是已授权交付的纯转换输出，尚不是可提交的内容提案或审计证据。未来依赖租约、提供者服务代次、内容修订和最后提交授权必须另行接入。

## 已验与后续

14项独立资源测试覆盖：生产者缓冲变动、描述字段篡改、scope／broker／host／实例错配、期限与撤权、旧 Mapping 保留、预算到最后释放、租约／映射上限、重复退休、Wasm逐字节固定 Invocation、执行后到期及撤权、无效未来时钟副作用拒绝。平台模块另有真实只读页写入故障资格。

`qualify_shared_objects` 使用实际编译的 Rust 工作台 Wasm，零内容能力连接读取固定 abc，原缓冲改成 zzz 后仍返回 ABC，不产生卡片；退休期间拒绝新scope分配，释放 Mapping 后才可分配新对象。这证明固定输入适配，不等于两个不同插件的自主依赖调用。
