## Source-policy refusal

Case039 `cb270f78ca714c37b177b055ec35d56c` passed 355 independent evidence
checks. A one-shot input on the same transferred production factory requires
managed_user to equal caller while the unchanged policy also requires the
managed user to differ from caller. It can only deny. The original password,
account, actual native results and policy validation are not substituted.

The actual typed refusal is reachable only after successful original LogonUser,
complete stable source-token readbacks and an actual TargetPolicy rejection.
The retained native Attempt checks the original token/caller/CWD closures,
original blocking return and its own receipt identity. The actual VM chain
then consumed that original refusal through local and SDK slot retirement,
Worker join, owner finish, factory release and owned setup cleanup. Owned
accounts, directories, firewall/WFP resources and the single temporarily added
privilege were retired by their original owners. No normal terminal ACK or
business-process success was synthesized. This proves one full source-policy
refusal, not more than sixteen full refusals through one shared SDK registry.

The refusal diagnostics intentionally omit absent Win32 errors. The legacy
optional native_start_handles_closed display is also emitted only for reasons
having a Win32 code. Neither omitted field is inferred as a Boolean observation;
handle retirement rests on the source-bound opaque original refusal capability
and the checked downstream consumption. Individual raw startup API values are
not separately claimed as serialized observations.
