# 有界多层依赖执行：test.31

本阶段在已批准slot与固定依赖调用协议上增加`dynamic_dependencies::run_graph`。它是可信宿主显式选择的同步多层执行方式；原`run`继续保持test.30单层入口行为。无需改变guest协议、SDK或包依赖声明，已有C／C++／Rust调用方式均使用同一import。新默认界面和自动图启动尚未接入。

## 深度、工作量与循环

`GraphLimits`默认最大边深度4、全图16次调用；可信宿主可设深度1..8、全图1..64次。根节点深度0，A→M→B需最大深度2。`Context.max_calls`仍是每次guest Invocation的额度，默认8、硬上限16；每个guest的包／Runner host_calls预算也继续生效。调用ID只要求在当前Invocation内唯一，不要求整图唯一。

总调用尝试次数保存在本次图执行对象中，进入下一节点不重置。活动调用栈按包ID记录，在发布共享输入前拒绝对活动包的再次调用，即使换同包另一个真实实例也不能绕过。顺序分支复用同一提供者允许；已经完成的分支会从活动栈移除。任何拒绝、陷阱、取消或超限使整次根任务不产生有效输出。

这是同步调用栈的环检测，不是多个Worker之间的完整等待图或事件循环收敛。异步调度、自动实例启动、故障后重绑定与恢复预算仍需实现。

## 逐层授权与提交

每条边都由其实际父实例申请当前批准slot；处理器、类型、provider摘要、scope和期限来自宿主／锁。每层重新冻结父插件提供的有界字节，现有Dependency完成源授权、provider临时映射、双方存活、期限和输出类型／尺寸检查。

新的执行回调仅限crate内部可信适配。普通公开Dependency.run仍要求零host_calls；内部图执行可包含嵌套dependency计数，但仍不能包含核心内容响应。实际guest必须经过已注册的纯转换入口和相关完成帧校验。caller无法以TaskReport、描述符或自报ID制造结果证明。

根`RoutedOutput`保留所有实际边的route／output及所有节点的取消信号。每条边独立核对它自己的父、子连接与宿主，不能把根Connection错误当成所有中间边的caller。根调用者另行校验。最终提交guard在同一可信时间检查完整集合，最深叶子停止、任何旧连接失效、取消或期限到达均拒绝未提交结果。已成功提交的数据与回执不会因之后的撤权回滚。

临时对象和映射随嵌套作用域回收，失败后不返回部分RoutedOutput。根提案留存的字节和描述关联不等于继续持有原输入访问权；撤权也无法追回已经拷贝给插件的字节。

## 资源与验证范围

输入／输出及帧边界沿用test.30：输入1..64KiB、输出0..64KiB、帧128KiB。最多64条保留结果边，每条最多64KiB；原共享broker总额度继续生效。每个guest使用独立fuel／内存预算，最深可同时保留根及8层provider的执行栈和内存；全图最多根加64次提供者预算，不宣称全链共享单份fuel或已测全局RSS。

Windows真实三Rust包与独立WAT图测试用于当前资格；未新增浏览器、其他原生共享后端、真实跨进程图任务或移动端产品验证。完整宿主事实记录、批准历史、审计封存和隔离重放仍未建立全链闭环。详见 [test.31验证记录](../reports/test.31-dependency-graph.md)。
