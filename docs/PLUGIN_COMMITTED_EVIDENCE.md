# 内容与纯任务证据原子关联：test.35–test.39

当前应用版本 `0.1.9-test.39+44`。本阶段让可信宿主保存“这次内容提交引用了哪些历史纯转换原件”，并从已核验的库或快照重放这些纯任务。test.39 已为默认 create／apply 新操作补齐固定 v1 的原请求／输出到完整结果卡片投影；宿主事实来源本身并不因此被认证。test.36 已将默认 Windows 工作台 create／apply 接入实际捕获和原件提交；test.36 相关测试与实际 Windows 自检已通过；test.38 已增加设置分页的实际批量捕获与原子提交，查询等其他路径尚未存证。

## 一次提交与幂等重试

`Pool::record_transform` 自行执行实际包并返回捕获结果。`HostRuntime::create_content_with_evidence`／`edit_content_with_evidence` 接受有序证据集合，仍要求真实连接的内容种类、对象范围及期限授权；附加 guard 不能代替授权。捕获或读取 Evidence 都不会授予内容写权限。

Store 在同一 SQLite 事务写入内容、证据原容器、有序引用、原始 Commit、永久事件索引和待封存事件。回执由原始 Commit 恢复，不建立第二份权威内容。最后一次授权失败回滚本次所有写入；提交返回结果不明时必须查询核对，不推断已回滚。

同一操作 ID 的重试必须匹配原始命令与有序摘要，同时重新核对原件。新增、删除、换序或替换证据均不能覆盖原操作。按摘要去重仍比较完整原始 Protobuf；相同原件的不同合法压缩表示保留首次容器，不能把孤立或损坏记录静默修复后继续。

## test.36 默认工作台与历史重试

默认 Workbench::create／apply 通过 `Pool::record_transform` 实际执行 `workbench.command`，保留原 Invocation 和 completion，再以 with_evidence 接口提交。范围包括新建、编辑、收藏、清单勾选、阶段、转为项目、删除与恢复等现有 Action；不是新增一个由界面传入任意 TaskReport 的存证按钮。

已提交操作重试先由 `Store::operation_commit(card_id,operation_id)` 读取原 Commit／Receipt，并核对有序原件。该接口固定读取事务，SQL 按卡片及内容种类过滤并预检长度；不存在、其他卡片或非内容操作返回 None，损坏或引用不一致拒绝。宿主从历史 Invocation 解码原请求，比较用户意图与基准修订；历史 current 和 now 是当时的宿主观察，不能用当前状态替换后重新运行插件。

通过核对后，复用原命令、原证据与操作 ID，重新取得当前对象 grant 进入核心幂等路径。不同意图、不同基准修订、缺少受支持的工作台原请求或权限失效都拒绝。返回该次操作的历史 Record；即使内容已被后续操作修改，也不拿最新内容冒充历史结果，不更新 undo 窗口或重复清理暂存附件。没有已提交记录的新操作仍检查当前修订并 CAS 提交。

这是针对已提交结果的重试恢复，不是未提交操作的持久意图队列。CreateCard 原命令可解码完整历史卡；工作台编辑从原 SetContent 正文、标题及原回执修订恢复历史 Record，不据此宣称通用宿主投影或所有历史 Card 状态可重建。

## 固定契约与边界

内容 Commit 的 `task_evidence_sha256` 保存原始证据 Protobuf 的 SHA-256，顺序有意义；它不是压缩文件摘要。空引用继续用 Commit schema 1，有引用用 schema 2，未知版本或非法摘要拒绝。证据自身保持[纯转换格式](PLUGIN_TASK_EVIDENCE.md)：嵌入原包、原调用、预算、后端和原始观察，拒绝依赖图任务，不恢复运行权限。

每操作最多 16 份证据，按每个位置的原始 Protobuf 与容器长度之和累计不超过 64 MiB，重复引用也计数。去重后仍按实际已存容器复核额度。这个限制不是数据库总配额；当前没有证据 GC 或普通历史释放入口。

内容库格式 7 新增 `task_evidence(digest,payload)` 和 `operation_evidence(operation_id,ordinal,digest)`。当前格式 10 接受格式 4～9 经完整性校验后按阶段原子迁移；6→7 在同一事务中建表、更新版本并验证新状态。损坏旧库、旧格式中的新引用或孤立新表均拒绝。格式 3 及更旧库仍不自动迁移。独立只读核验接受 5～10，不创建或迁移文件；这也不是 test.1 资料迁移方案。

`Store::operation_evidence(card_id,operation_id)` 是可信宿主本地查询，核对卡片及内容操作归属。不存在、其他卡片或非内容操作返回 NotFound；合法无证据操作返回空集合。读取证据不等于允许把它交给任意插件或重新执行。

## 签名与快照

证据与内容提交原子关联后，封存仍是既有的后续阶段。签名段包含核心保留的原始 Commit 容器，签名因而覆盖其有序摘要；不会重编码提交再验签。独立固定的日志身份和公钥仍是信任来源。该签名证明宿主签署了这组提交关联，不证明插件结论正确或观察数据必然来自某次真实执行。

完整性检查核对每条 Commit 的引用、全部证据原件及关联，拒绝漏关联、额外关联、错误操作种类和孤立原件。`Store::snapshot_to` 在固定源读取事务中先验证这些关系，再生成 SQLite 一致性快照。已提交证据内嵌的历史包原件随内容库保存；这不等于备份整个插件安装目录。原包卸载后历史任务仍可从原件重放，但不会重新获得原批准、连接或对象授权。

## test.38 批量设置与原意图重试

`Pool::record_transform_batch` 自行执行同一已绑定包的全部页，每页复核会话和当前批准，并将实际观察按顺序写入一份 schema 2 证据。任一页失败不签发部分批次。默认设置保存先固定规范意图、原设置正文的未知字段和基准修订；所有页必须成功且不能改变对应设置值，再以现有 with_evidence 接口提交一次内容事务。

已存在操作要求原卡片归属、单份受支持批次、完整原意图、原页输入／输出以及原内容命令相符。宿主使用当前内容授权重试原命令和原件；不重跑 guest，不将后来设置覆盖为旧值。原操作没有受支持批次时明确拒绝；真正无变化的保存不写回执、不新增证据，也不占用操作 ID。这不是未提交意图恢复或通用投影证明。

test.38 的格式 9 为批次限额建立兼容门槛，8→9 校验前后在同一事务更新版本，不改历史证据原字节或签名；格式 8 中的批次拒绝。32 KiB 物理共享继续使用，每份批次的原 PB 和容器仍完整计入逻辑预算。详见[批量契约与边界](PLUGIN_BATCH_EVIDENCE.md)及[test.38 记录](../reports/test.38-settings-batch-evidence.md)。

## test.39 从宿主事实重建内容投影

新 create／apply 证据在单页 schema 2 批次的 intent 中保存 HostProjection v1，包含完整 prior 原字节、操作／目标、有序附件元数据与摘要及原时刻／撤销观察。固定实现从原请求和真实 completion 重建原命令与完整 CardRecord，`verify_commit` 比对原命令字节、命令摘要、操作／事件／修订、完整结果摘要、附件摘要及唯一证据引用。未读取最新库内容，也不重新编码 Commit 来验证签名。

版本 v1 冻结请求整形、persistence 编码、未知字段保留、Create 空预览和 Edit UTF-8 预览截断规则；未来语义或依赖编码变化必须保留旧实现并新增版本。独立重建不授予内容写权限、不认证附件选择或时钟来源；历史重试仍需当前授权。旧 schema 1 证据不能凭空补齐未记录的 prior，继续保留原兼容路径而不冒称完整投影。

格式 10 将批次 intent 上限从 4 MiB 扩至 12 MiB，以容纳原本合法的完整 8 MiB CardRecord。9→10 只改变容量门槛，事务前后核验但不重编码旧原件；格式 9 中超 4 MiB 意图拒绝。设置保持 test.38 专用批次，尚无该投影。它是捕捉到新建因果链的必要基础，来源／编辑关系仍待补齐。详见[投影契约](PLUGIN_CONTENT_PROJECTION.md)和[test.39 记录](../reports/test.39-content-projection.md)。
