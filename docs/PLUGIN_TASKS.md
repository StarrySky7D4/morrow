# 原生插件后台任务与生命周期

基于 0.1.9-test.10。原生 `packages` feature 增加 `Worker`：一个后台线程独占已准备插件包、连接和 HostRuntime，调用方通过非阻塞任务句柄收取结果。原有队列支持 ABI v1；后续已接入 ABI v2 的动态内容命令及纯转换任务，Cap’n Proto v6 与资料库格式保持不变。

## 调用与所有权

可信宿主先验证／准备包、建立连接并授予具体对象权限，再将三者移交给 Worker。运行中不能从 UI 侧同时访问其 Store 或修改连接。工作线程只执行固定包；包摘要和真实宿主实例同时匹配、连接仍 Ready 时才允许启动。已停止连接和其他宿主的连接在执行前拒绝，不依赖 guest 自己调用某条内容命令后才发现。

| 接口 | 行为 |
| --- | --- |
| `Worker::spawn` | 创建一个原生线程，容量设为 1–64 个未完成任务（包含正在执行者）；创建失败明确返回 |
| `submit_task(input, timeout)` | 提交已校验的内容或纯转换输入；结果分别为核心 Response 或插件产出的 TransformOutput |
| `submit(timeout)` | 有界非阻塞提交，队列满返回 Busy；超时必须大于零且不超过一小时，包含排队时间 |
| `TaskHandle::try_result` | 非阻塞轮询；完成结果只消费一次；Unavailable 不表示没有提交 |
| `TaskHandle::cancel` | 取消该任务；不停止其他任务，不自动重试 |
| `drain(timeout)` | 停止接收新任务，保留已接收任务，将其期限缩短到排空截止时刻 |
| `stop()` | 停止接收，先发出实例单向撤权信号，再取消全部任务；立即返回 Stopping，等待实际执行退出 |
| `try_finish()` | 先确认线程已经结束，再取回独占 HostRuntime；正常结束前退休插件连接 |

ABI v2 任务通过固定导入读取宿主提供的输入，返回关联完成消息；详见 [任务契约](PLUGIN_TASK_PROTOCOL.md)。旧 submit 保留给 ABI v1 回归。任务句柄 worker／serial 仅用于本机跟踪，不代替内容 operation_id 或权限；任务持久化与恢复仍待实现。

任务结果发送有界且不等待 UI 消费。丢弃 TaskHandle 会请求取消；丢弃 Worker 会请求停止但不会阻塞调用线程。需要确认关闭、回收或取回核心的调用方必须保留 Worker 并等到 `try_finish` 完成，不能以 Drop 或一个状态值作为线程终止证据。启动前的模块编译仍是同步准备 API，应由可信后台准备流程调用；主 Flutter 界面尚未接入此 API。

## 取消、期限与提交

取消和期限在排队结束、进入 guest、每次宿主导入前后及退出时检查。过期的排队任务零宿主调用；迟到的响应被抑制并报告 Deadline。期限使用宿主 Instant；权限仍使用同一可信单调时钟，不接受插件提供的时间。

**停止先撤权，取消不代表回滚。** stop 通过核心提供的单向信号立即撤销该实例；核心在执行、事务提交前和读取结果交付前复核。正在准备但尚未通过最终授权的操作会被拒绝，旧信号也不能影响后续新实例。测试在宿主时钟入口阻塞，stop 后释放，证明未产生重命名提交。另一测试先由独立数据库连接观察到真实提交，再阻塞并停止，证明既有修订保留。

最终授权检查与实际提交之间的已接纳操作仍可能完成；单个 TaskHandle 的取消以及排空期限也不撤销其他任务共享的实例权限。因此取消、期限或线程故障后，仍须根据稳定 operation_id 查询权威结果，不能自动重跑整个插件任务。

纯 guest 计算由 fuel 限制，取消／时间限制不保证立刻中断死循环；阻塞的数据库／系统调用也不能由此线程适配器强制终止。正常排空意味着允许已接收的 guest 任务继续提出获授权命令，核心连接保持 Ready，直到队列结束后统一撤权、停止和退休。这与核心单条内容命令的 Permit 排空层次不同，不能混为已经完成生产生命周期。

工作线程捕获可展开的宿主 panic 后先撤权，再进入 Failed，丢弃连接所属核心并关闭结果通道，任务返回 Unavailable。此机制不捕获进程 abort、内存安全故障或操作系统故障，也不是恶意原生代码沙箱。已经提交的操作仍由重新打开数据库核对。

## 实测与下一步

复现：`tool/verify_plugin_runtime.ps1`。实际 C／C++／Rust 与 C++ 分配器包各提交两个后台任务，然后排空并退休连接；同一操作的重复请求保持修订 2 和两条原子事件。阻塞、取消、过期排队、线程故障等由独立测试覆盖，见 [验证记录](../reports/plugin-worker-validation.md)。

后续任务：

1. 在已完成的动态内容命令任务上扩展通用计算／转换提案、多步骤任务和 UI 事件；统一生产操作身份与持久恢复。
2. 多实例调度、授权控制消息、强制停止后端与隔离；在已有单向实例撤权基础上扩展任务／对象控制，明确最终授权后的已接纳操作语义。
3. 任务恢复采用 Protobuf＋LZ4；与操作结果、审计和证据关联，禁止恢复旧权限句柄。
4. 将非阻塞事件接入 Dart／Flutter，再实现声明式插件 UI 的有界组件树、动作和代次校验；后台 Rust API 本身不证明界面集成。
5. 平台各自验证 Worker／进程和分发机制；Windows 线程结果不外推到 Android、iOS、Web 或其他桌面。
