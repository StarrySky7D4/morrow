# Web 与 Windows 同进度工作表

目标：Web 达到当前 Windows 开发线的产品、数据与插件功能进度。编译通过或单个适配层通过不算完成；Windows 自身尚未完成的功能不在此被宣称完成。

基线：2026-09-25 当前工作树，应用 `0.1.9-test.55+59`。保留前一轮 Win/Web 环境与生成绑定修复。

用户补充边界：允许服务部署在云端，但数据必须存于设备侧本地。Web 的卡片、附件、草稿、设置、审批及凭据以设备本地持久化为准；可用云端服务补充浏览器能力，但不能用云端数据库代替本地权威存储，也不能把业务内容写入云端日志或缓存。云端部署、网络执行和设备本地数据的接口仍需实现及验收。

用户已澄清“云端提供母本，运行在本地”“web 不需要下载，直接运行”：用户打开网址即可使用，无需手动下载、安装桌面程序或 Rust 环境。云端提供应用静态资源，浏览器自动加载 Flutter 与 Rust/Wasm 并在设备执行；业务数据和身份密钥留在设备。正式 Web 入口现已接通，完整产品验收仍在进行。

## 实施约束

- 复用 Rust 核心、实际插件原包和现有协议；不复制业务规则以伪装为同等功能。
- 现有浏览器数据不得被自动丢弃或由空库覆盖；迁移需有可验证的来源、回执和恢复路径。
- 不把 browser Number 当作 u64；不改变已有内容、插件包和签名数据的语义。
- 生产 Web 构建不携带故障注入入口或不受权限约束的探针管理控制。
- 浏览器无法直接提供的 OS 能力必须有明确产品实现边界；在实现和验收之前保持未完成。
- 每一行都要有运行证据后才能关闭；本表当前所有产品对齐行均未完成。

## 进行中

插件运行基础已推进到共用 `Manager`、`Pool`、依赖路由和审批规则，OPFS 仅负责设备侧持久化。这不等于产品已对齐。

已通过 `tool/verify_web_packages.ps1`：Chrome 154.0.8037.57 实际执行同一工作台包，9 组原生/Web 完成回执逐字节一致；摘要不匹配、内容命令拒绝、燃料耗尽与 130 次连接回收通过。另有 12 个审批状态快照与原生逐字节一致，单 Worker 重复打开拒绝、Worker 重开与停用状态保留通过。冻结的 Rust/C/C++ 原包经共享依赖路由执行，撤销提供方使旧会话失效，重新启用不复活旧会话。

下一阶段仍需把正式工作台内容、草稿和管理页面接入同一浏览器宿主，并实现设备本地身份、备份/恢复及云端服务边界。测试入口不得替代正式应用入口。详细证据见 [阶段记录](../reports/web-parity-runtime-2026-09-25.md)。

工作台宿主增量：`tool/verify_web_workbench.ps1` 已通过原生与 Chrome 154 的同一二进制协议用例：创建、编辑、过期修订拒绝、分块中文长草稿与 UTF-16 光标、语言设置、插件审批、关闭后独立 Worker 重开、错误密钥拒绝及审计完整性检查。审计封存算法已由两平台共享，Windows 密钥/身份/会话 17 项回归通过。浏览器探针使用明确的固定测试身份；正式应用入口、本地受保护身份及附件文件适配仍未完成。
