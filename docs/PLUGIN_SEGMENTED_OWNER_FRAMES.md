# 服务期间完整私有请求的有界分段

2026-09-21，应用私有连接合同；不属于 guest IO ABI 或公共 SDK。

## 适用范围

原本合法的 UI→工作台完整请求最多128 KiB，但服务运行期间拥有者命令单次输入上限64 KiB。现将超过64 KiB、未超过128 KiB的完整请求分段送入**同一原拥有者**；小请求继续原路径。请求只序列化一次，不截断字段，不复制 Store，不绕过原业务权限或把停止解释成回滚。

本改动不提高 `MAX_OWNER_COMMAND_INPUT`，不改变 guest `morrow_io_v1.call` 或插件输入上限。更大的附件/捕获/偏好继续使用各自的有界传输；任意大网络请求、响应流、SSE/WebSocket及插件流式IO仍需独立契约。

## 私有动作与额度

| 动作 | 字段与行为 |
| --- | --- |
| commandFrameBegin | transfer 为非零64位小写十六进制关联标识；绑定 totalLength 和32字节 sha256；创建单个暂存槽 |
| commandFrameAppend | 精确 transfer + offset，payload 非空且不超过32 KiB；回执返回累计接收长度 |
| commandFrameFinish | 精确 transfer/totalLength/sha256，必须收齐全部字节并通过完整摘要；取走暂存后验证原私有请求，再调用原业务处理一次 |
| commandFrameAbort | 仅清理匹配 transfer，不修改业务内容，也不撤回已执行效果 |

每个动作仍作为独立、最多64 KiB的原拥有者命令入队，使用既有命令身份/数量/历史/取消/授权规则。全逻辑请求最多128 KiB；每个原工作台只有一个暂存槽，独立内存上限128 KiB。槽从 Begin 起使用固定120秒单调截止，Append不续期；到期后拒绝使用并在下次暂存操作清除，原worker退出及工作台关闭也清除。上传字节、返回原件和解析临时输入由擦除型缓冲区管理；不承诺操作系统或语言运行时所有内部副本均可擦除。

这些动作只在拥有者命令通道内接受，不能直接走本地外层业务入口。完成后的原请求不得是调度动作或另一个暂存动作，避免递归调度、递归暂存。非法offset、错误token、长度或声明摘要不能推进/破坏另一个有效上传；内容摘要失败清除原槽。重复完成不能再次取得已消费的原件。

响应上限保持不变：内层业务响应128 KiB，commandRead外层最多256 KiB。完成前仍按原worker规则复核当前运行和权限，修改仍由同一个原Store执行。

## 身份、错误与清理

客户端固定原service task、原完整字节及其摘要。Begin/Append分别有自己的命令提交身份；最终Finish使用原业务提交身份，其命令摘要包含transfer、长度和完整请求sha256。原命令登记簿负责同一提交的状态恢复和消费后不重放。

客户端核对Begin/Append的精确回执偏移；任一步失败不继续Finish。所有步骤共享原调用的总截止，期间状态/停止仍可进入原调度通道。最终业务响应保持原Action的QueryFailure等错误分类及敏感缓冲寿命。

丢失或损坏Finish回执可能对应已提交效果：保留该最终命令/提交身份为Unknown，不重发。健康通道上的清理仅尽力发送同token Abort；已失效或关闭通道不再发送，原退出清理负责释放。Abort和命令Cancel控制的是暂存与执行/交付两个不同对象，均不是回滚证明。清理回执被丢弃不等于已清理，不能据此宣布业务未执行。
