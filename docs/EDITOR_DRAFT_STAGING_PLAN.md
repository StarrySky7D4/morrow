# 编辑草稿持久暂存接入方案

状态：2026-09-23 Core归属、持久导入、私有客户端、独立进程决定恢复，以及工作台附件决定恢复页已接入。全程串行发现解决页间写入问题；最新客户端/UI组合68项、11目标分析及九语言检查通过，Windows Release重建。正式编辑器/正文恢复、默认autosave、附件来源交接和长期维护仍待完成，详见[最新UI报告](../reports/editor-draft-import-recovery-ui-2026-09-23.md)及[后续接线计划](EDITOR_UI_PERSISTENCE_PLAN.md)。

## 持久记录与操作身份

采用每草稿一个有界、仅保存元数据的私有审计记录。未选附件不能作为该记录的 CardRecord attachments，否则会产生永久 event_blobs 引用。字节通过可释放的 Snapshot owner 保留。

导入请求冻结 cardId、draftId、原操作号、草稿代次、显示名、媒体类别、精确长度和 SHA-256；本机路径仅是本次读取入口，不替代固定内容身份。owner 由宿主按草稿和原操作派生，不让客户端任意认领全局 blob。新接口要求已有活动草稿；新卡先显式保存空白草稿。现有内存导入的兼容路径必须明确区别，不能升级文案冒称已有持久保证。

草稿元数据代次与导入暂存记录代次独立，避免导入一个附件使正文的在途保存基线悄悄改变。导入同一内容的不同操作应有独立逻辑身份/归属，但可共享物理 blob。

## 状态与恢复

1. **Pending**：先在原核心审计路径记录固定导入意图和容量预留，再允许读取文件。
2. **Bytes retained**：调用 stage_blob_retained 将验证过的原字节和归属原子提交。若后续 Ready 记录尚未写成，重启仍能按已持久 Pending owner 找到并验证字节。
3. **Ready**：持久确认原字节、归属和元数据后才返回成功。整个过程由固定外部导入操作关联阶段记录；内部阶段操作号也须确定，禁止失败后随机换号。
4. **Consumed / Abandoned**：选入已确认草稿或明确放弃后失去暂存使用资格。旧导入重试只能返回历史结果和当前失效状态，不能复活。

重启、列表、查看首先只读核对。Pending 但找不到归属意味着没有确认字节，不能用全局 hash 相同的任意 blob 冒领成功，也不能在后台重开路径；用户显式重试时才以同一固定请求读取并验证。已存在归属的重试不得再依赖原文件存在。释放 owner 不等于封存业务操作，后者必须由持久操作历史/放弃记录保证。

## 选中、放弃与清理顺序

草稿保存必须在同一草稿事务中绑定所选附件和精确的已消耗导入身份，防止保存已成功但暂存清理未完成时重启复活。读取/导出暂存同时核对当前草稿活动状态及消耗事实；已消费或整个草稿已放弃的导入不再列为可选。

消耗列表不能无界累积。推荐在下一次更改草稿之前，先将上一代待清理的消耗身份可靠地确认到暂存元数据；确认完成后，新草稿可移除已处理标记。每次只记录本轮有限的选中身份。暂存记录清理未确认时阻止依赖它的后续代次推进，而非跳过关联事实。整槽放弃立即通过非活动草稿状态封禁所有导入，逐个 owner 的物理释放可随后安全重试。

已确认草稿的业务回执不应因后续物理清理失败而伪装成未提交。清理失败保留待处理状态和配额计费，不允许先记已释放。只有确认不再需要的 Snapshot owner 才能释放，之后按已有宽限回收；保留任何正式 card/event/其他 owner 引用的字节不能删除。

必须继续给导入条目、逻辑字节、元数据、待清理状态和审计增长设限。配额拒绝不截断记录、不删除证据；历史保留/归档仍是独立门槛，不能靠无限扩展暂存记录解决。

## 私有接口与客户端

新增独立能力接口，支持固定请求导入、按原操作 inspect、按草稿列举、精确导出和固定操作放弃。回执应区分历史导入与当前是否仍 Ready，以及当前草稿/暂存代次；仅返回一个 assetId 不足以核对未知结果。

Dart 保存不可变 ImportRequest。发送前本地校验失败可标记未提交；进入可能产生宿主效果的请求之后，回执丢失、损坏或 EOF 均保留 Unknown 和原请求。缓冲 abort 只释放传输资源，不撤销导入。恢复先 inspect，显式重试原操作；同一导入未知时不得悄悄改用新操作号。

泛用附件导入、剪贴板 capture scope 和 guest 转换票据仍是不同来源，不能借此复活旧授权或将普通 assetId 伪装为草稿持久来源。

## 验收矩阵与剩余边界

Core 原子性、宿主关键写入失败与真实退出、新协议分段与丢回执核对已覆盖，结果分层记录在宿主和客户端报告中。当前库/协议测试已验证未选附件列举/导出、消费/放弃后不可复活、同字节不同归属以及失败清理仍计费。仍须补全全局容量压力、应用进程实际关闭后的待决动作恢复和 UI 不自动执行业务/恢复授权；保留调用方对象后重开宿主不等于完整应用重启验收。


## 私有传输接线决策

旧 action 100 在操作核对前打开路径，且只返回 assetId/name/kind/bytes，不具备固定导入操作和摘要，继续作为兼容入口；新会话不能使用它恢复未知结果。新增独立 editor_draft_staging_api.capnp，避免改变已验证的正文草稿协议摘要。

| 操作 | 请求与执行边界 |
| --- | --- |
| BeginImport | 冻结 card/draft/importOperation、主草稿 expectedGeneration、名称、类别、精确长度与 SHA-256；没有路径，先持久登记 Pending |
| InspectImport / ListImports | 只读原操作或当前条目，不自动完成导入、释放或重开路径 |
| CompleteImport | 使用同一完整固定提案；先核对，Ready/Retired 只读返回；Pending 且已保留原字节时不打开源文件；仅缺少字节时才读取本次明确提供的路径并核验 |
| ExportImport | 绑定当前主草稿代次与原 importOperation；只允许当前可选条目；已经选入草稿的附件走现有草稿导出接口 |
| AbandonImport | 使用独立固定 abandonOperation，绑定原 importOperation 与主草稿代次；明确放弃与内部自动清理使用不同审计意图 |
| ReconcileImports | 显式、幂等地完成待清理记录；返回实际剩余状态，Retired 不等于空间已释放 |

响应同时包含完整原提案、逻辑附件身份、Pending/Ready/Retired、当前可选状态、实际归属状态、主草稿当前代次/活动状态与暂存记录修订。主草稿代次和暂存修订不得混用；一次性传输关联号也不能替代固定业务操作号。读取操作逐项加入协议只读门禁，变更操作仍走写权限。

客户端保存不可变请求，进入可能产生宿主效果的调用后，EOF、丢回执、错误关联或损坏回执均保留 Unknown；先 Inspect，显式原请求 Complete。缓冲清理不等于业务撤销。列表只包含当前暂存条目，已清理操作仍可用原操作号查历史；会话不能丢弃在途操作身份。导出目标写成但回执丢失时，须核对原摘要/长度，不能把目标已存在误判成没有副作用。

## 当前容量边界与后续维护

宿主暂存限定每草稿 20 个当前条目、全库 320 个当前条目、64 MiB 声明字节预留、每条暂存记录 1 MiB 元数据、256 个记录身份，每记录最多 256 次修订。Pending、Ready 与尚未清理的 Retired 均计费；失败不先释放名额。首次接纳前预留 Ready/Retired/Pruned 的剩余修订，不能因历史上限让已接纳的附件无法完成清理。

这是明确拒绝超限的测试阶段门槛，并非无限期可用的历史维护方案。满历史后的归档/迁移及草稿来源交接仍需设计和验证，不得自动换操作号、改草稿身份或删除审计证据绕过上限。独立正文草稿与正式附件历史的保留规则不受临时 Snapshot 释放影响。


## 待决决定恢复门槛

EditorDraftImportSession 当前只是独立于 Widget 的内存会话，不是新的持久存储。已经登记的原导入请求可由宿主 List/Inspect 恢复，但 _pendingAction 和固定放弃意图仍须上层保留。尤其 Inspect 得到 Retired 时，无法凭此证明某个 abandonOperation 已提交。

下一阶段应让宿主为明确决定保留可查询的操作身份/原代次，并将当前条目清理后的决定回执继续关联到审计历史；界面打开只读核对。应用进程关闭后必须能恢复原决定，再由用户明确重试或确认。不能创建第二份权威内容库，也不能通过新操作号或自动清理掩盖未知结果。此前私有协议、Dart 适配和宿主复用测试只证明已有边界，不替代该门槛。


## 决定恢复补充

放弃操作在执行前必须持久准备原身份和主草稿基线。取消用同一原操作号提交终态，与实际放弃互斥。状态由确切审计历史判定，不能从 Retired 推断成功；全局范围列表先发现活动/失活草稿，再分页读取决定。恢复页扫描阶段必须阻止新增决定或从头重扫，当前分页不提供固定快照。独立进程测试已经证明读取索引可恢复原操作，正式 UI 接线仍为下一步。容量上限拒绝新身份，旧确切提交可只读确认；长期维护和回收另行实现。


后续扫描实现已在同一共享作业中串行遍历全部页，同工作区写入不能穿插；工作台恢复入口使用这一完整扫描，而非独立分页循环。裸分页接口没有被改为通用快照协议。正文与附件自动保存的关闭/来源交接仍未完成。
