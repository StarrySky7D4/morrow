## 私有协议

沿用 editor draft 独占传输队列、分段上传/下载、契约摘要、精确 u64 和失败清理。新增动作应追加到枚举，不改变现有编号；公开插件 SDK 不得到这些宿主私有写入权限。

Prepare 发送完整冻结提案。上传完成不等于提案已持久：只有 Prepare 回执或原身份 Inspect 能证明。Prepare 发生后，调用方即使没有收到回执，也只能使用原 child operation 查询，不能换新 child/draftId。宿主提交子和退休父是独立动作，不用页面打开或扫描触发重放。

Inspect 返回冻结 request/link/retirement operation、提案修订、历史状态和当前父子代次/活动状态，严格匹配 card/parent/child operation。完整请求允许分段，不向 outer frame 塞入数 MiB 正文。

发现页应只返回有界摘要（身份、状态、修订、游标），用户选中后再按身份分段读取完整提案。Rust 库的 full-record list 最多 32 项，但单项请求可达 4 MiB，不能把整页完整正文直接编码进 8 MiB 传输上限。客户端验证游标推进和唯一身份，整次扫描不穿插写操作。

取消固定原 child operation，宿主同一 owner 核对未提交并以该号写入取消记录；此后迟到 child 不可复活。退休号也保留在不可变提案中，不能被另一提案或旧退休入口复用。核对结果未知时清理的仅是传输缓冲，不是草稿或提案。

所有新协议动作可用并完成新旧回归后，再迁移 Dart handoff 接口。不能先封死所有未 Prepare 的旧协议，从而使当前仍使用旧接口的客户端失效；过渡边界必须明确记录，不能宣称所有旧调用已具备持久提案恢复。

## 工作台会话与界面

工作台持有原提案及查询结果，视图只附着。先持久父最新完整快照，Prepare 确认可恢复，再建立子，最后条件退休父。所有阶段保留当前 S2 原始输入、选区、IME 与附件来源，不因历史成功回执覆盖后来编辑。

恢复入口先只读展示 Pending、ChildCommitted、ParentRetired、Cancelled 或 Conflict；明确处理后才提交相应动作。权限、内容库身份、当前来源和插件状态重新核验。切库后迟到结果不得更新新工作区。

正式 S1 的恢复提示/临时证据应在 S2 交接可恢复后才确认清理。宿主长期证明来自 operation_commit/operation_evidence，但不能由此推断当前编辑器捕获来源、临时 pin 和 UI 草稿都已经有独立持久归属。

## 下一步验收

- 独立 Dart 客户端进程：Prepare 已落盘但首回执丢失、子提交已落盘但首回执丢失、父退休首回执丢失；下一进程只从宿主发现，不靠测试调用方保存原对象。
- 分段序号、摘要、外层身份、超限与首回执缓冲归属错误；不能借清理触发重发。
- 32 项摘要页、最大正文、资源上限和取消保留余量，分别核对界面和宿主边界。
- 正式编辑器 S1/S2、附件、关闭、切库、语言/字体切换、富捕获证据及冲突恢复。
- 原私有 wire 迁移与旧精确历史回执可读；长时间历史维护和容量回收另行验收。

Rust 独立进程测试仅证明宿主库提案持久边界，不代替上述 Flutter/Dart 端到端验收。
