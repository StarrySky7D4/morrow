# 持久服务配置与只读恢复查询

本轮实现属于原生宿主底座，应用版本仍为 `0.1.9-test.52+56`。测试范围与结果见 [验证报告](../reports/service-recovery-2026-09-20.md)。主应用发布界面和完整 SDK 尚未接入；后续入站批准解析见 [持久服务授权](PLUGIN_SERVICE_AUTHORITY.md)。

## 持久配置

`core::service_config::Config` 保存稳定 namespace、保留期限、服务与处理器、包摘要、修订、禁用标记、主体身份／认证引用、精确内容范围和资源批准引用。引用固定为非零32字节标识，不提供明文 token 或密钥字段。配置按严格规范 Protobuf＋LZ4 编码，解码前检查字段、层级、数量和字节上限；拒绝重复、未知字段、非法操作范围及非规范顺序。

配置使用原 Store v18 的 `service_configs`，没有新增旁路数据库。原 v17→v18 迁移在单个事务中完成，不重写已有内容和证据；旧版本无法直接打开升级后的数据库。`save_service_config_local` 使用预期修订 CAS：0创建修订1，更新必须恰好递增。namespace 和 service 不能原地替换，namespace 不可被另一配置复用；通过新修订禁用，不提供删除后回收身份的接口。

最多128条配置、每条128KiB原文、64主体／128项总内容范围／64批准引用。配置与原事件、IO材料、容量预留共用字节额度。替换只在事务内扣除旧行，失败保留完整旧配置；分页每次最多32条。

加载配置只恢复期望状态。`ServiceJournal::from_config` 必须匹配当前实际 `ServiceGrant` 的包、服务与处理器，并拒绝禁用配置或已撤销资源；监听器、原实例授权、主体凭据与内容授权仍须重新建立。单独使用此 journal 帮助函数不监听配置变化；通过后续 `ResolvedService` 恢复的路由会在原 Store 配置／批准变更时撤销，见 [服务授权合同](PLUGIN_SERVICE_AUTHORITY.md)。出站凭据保护和配置审计链仍待接线。

## 不执行的查询

`IoWorker::query_service_history` 接受原请求、原幂等键、当前服务授权、journal 及可选内容授权。调用者必须重复原完整业务输入；固定 namespace、实际主体、服务与 key 确定历史身份，包、处理器、保留策略、目标、正文、业务头和有效内容范围必须匹配。

查询使用原 worker、Store、实例、队列、job和累计字节额度。此路径没有网络适配器，不调用 guest，不创建 Prepared，不认领执行，不补写证据，也不把 Unknown 改为成功。没有记录仍保持没有记录。已完成结果校验原请求／响应材料后才返回；返回字节再次计费。所有成功状态在读取前后重新授权，保留状态继续携带原 TTL，在 Ready/read 复查，不续期。

原生查询返回明确的 Missing、Prepared、Unknown、Cancelled、Expired、Observed；冲突及材料不可用另行分类。Unknown 仍须有依据的核对，不能自动重发。Prepared 是读取时的状态快照，不是预留执行权。

## HTTP 入口

`ServiceHost::query_route(&original_route, query_path)` 只能从同一宿主的持久普通／内容路由派生，查询路径必须不同且合法，不能从查询路由再次派生。它继承原方法、固定业务路径、journal、内容策略和主体范围表。客户端在查询路径重复原方法、查询串、业务头、正文与 Idempotency-Key；宿主还原业务路径，重新认证当前 Principal，不接受客户端自行指定历史主体或处理器。

查询不会构造 RouterFactory。未找到返回404，Prepared返回202，Unknown／Cancelled／输入冲突返回409，到期返回410，材料或存储不可用返回503；这些由查询入口生成的状态带 `morrow-service-state`。Observed 返回原保存响应的状态、重复头和正文，不增加或删除响应头，避免原合法响应恰好达到头部预算时查询失败。原响应中的同名头仍是业务数据，不能当作宿主认证的状态；此 HTTP 入口是原响应恢复接口，机器可判别的完整状态以原生 `JobReport` 为准，统一外部状态信封仍待协议化。

内容路由保持实际 Principal→当前范围映射，原件包含的内容范围摘要必须与现在完全一致；范围改变返回冲突。认证或授权失败不开放历史结果。撤权不能撤回已经交付的字节。
