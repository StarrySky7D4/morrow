# test.38：设置批量证据与隔离重放

当前应用版本 `0.1.9-test.39+44`，内容库格式 10。test.38 建立下述设置批次，test.39 另为 create／apply 增加[版本化内容投影](PLUGIN_CONTENT_PROJECTION.md)。默认 Windows 宿主把一次设置保存的全部纯转换验证页录制为一份证据，并与设置变更原子提交。证据内共用一份历史包，保留规范保存意图和每页实际观察；已提交重试复用原命令和原件。这里的批次是单包、有序、同步的纯任务集合，不能据此重放完整依赖图或重建通用宿主内容投影。

## 固定证据契约

预编译 `core/schemas/task_evidence.proto` 保留原消息名称与字段 1～10，增加 `TaskEvidence.batch = 11`。外层仍为有界 Protobuf＋LZ4；外部固定摘要针对完整原始 Protobuf，包含未知可选字段，不针对解析后重编码的对象，也不等于压缩文件摘要。

| 契约 | 内容与约束 |
| --- | --- |
| schema 1 | 原单观察字段、故障及业务失败规则、原始大小限制保留；`batch` 必须不存在。既有合法 v1 原容器及原始 PB 不被重编码 |
| schema 2 | `package_archive` 保存一份共用原包；旧顶层 invocation／budget／backend／completion／fault／exit／计数必须为空或默认值；`batch` 必须存在 |
| `Batch` | 非空可见 ASCII `intent_type`，最多 128 字节；`intent` 当前最多 12 MiB，通用契约允许空；test.38／内容库格式 9 的原上限为 4 MiB；`total_fuel` 与 1～1024 条有序 `Observation` |
| `Observation` | 原 Invocation、逐页预算、后端、原 completion、fault／exit、实际 host_calls 和 fuel_remaining；必须无故障、退出 0 且 completion 是关联成功 Output，业务 Failure 不能组成批次 |

每份批次原始 PB 最多 24 MiB，单 Invocation 和 completion 继续各最多 128 KiB，转换输入／输出及包注册限制继续生效。每操作最多 16 份证据，原始 PB 加原容器按每个引用位置累计最多 64 MiB；一份 649 页批次计为一份证据，其全部原件字节仍计入预算。这不是全库配额。

解压前后限制长度，在 Protobuf 分配之前校验固定层级、字段类型、重复已知字段、消息及观察数量，拒绝 group、截断长度、超限输入和未知版本。v1 另外按实际原始 PB 长度及原字段总量执行旧上限，不能通过新增未知字段借用 v2 的 24 MiB 容量。原包每份解析一次；每个任务仍须是该包注册的 ABI 2 纯转换，带依赖声明或动态依赖调用功能的包拒绝。

## 捕获与实际燃料

`Pool::record_transform_batch(manager, host, session, inputs, intent_type, intent, total_fuel)` 验证真实宿主、管理器、会话和当前包绑定，自行执行任务。调用者不能把外部 TaskReport 传入该入口冒充实际捕获。每页执行前后维护并检查会话；陷阱、任务协议或执行限额故障隔离实际根，撤权后的结果不再交付。任一页失败、业务错误、结果缺失或总预算超限都返回错误，不签发可提交的部分批次。

契约总燃料范围为 1～10,000,000,000；默认设置入口采用 1,000,000,000。每页预算不超过当前包／宿主上限及批次剩余额度，执行后扣除 `budget.fuel - fuel_remaining`。保存格式再次按页序校验每页预算不大于此前剩余额度，再扣实际消耗；不是简单把各页最大预算相加，也不会逐页重置总预算。

`CapturedBatch` 提供实际 reports 和 Evidence，但不提供内容写权限。核心 `encode` 仍只是格式工具，能接受调用者构造的合法观察；证据容器和摘要本身不能证明执行来源或作者身份。内容提交及后续签名关联沿用[原子关联机制](PLUGIN_COMMITTED_EVIDENCE.md)。

## 默认设置保存与历史重试

宿主先 decode／encode 设置得到规范原意图，标识为 `morrow.studio.preferences-save.v1`；固定完整意图、原正文未知字段和基准修订，再按既有规则生成有序页。最大结构为 1 个头页、512 个条目页、8 个完成状态页及128个组件页，合计649页，同时受完整设置4 MiB及单页64 KiB约束；最大页数与每页最大字节并不保证能同时达到。

所有页通过实际 `studio.preferences` 转换，宿主逐页核对成功、没有核心回复、输出类型和设置值不变。随后一次 with_evidence 调用保存设置内容和一份批次证据；页之间不拆分内容提交。新操作仍根据已冻结的内容修订提交，失败不会发布部分设置。

已提交操作先核对全局操作归属，再读取 `operation_commit` 和原证据。宿主比较完整规范意图、全部原页的顺序与字节、原成功 completion，以及原 CreateCard／SetContent 正文。匹配后使用当前内容授权复用原命令和原件进入幂等路径，不重跑插件，不把后续设置改回旧值。不同意图、跨卡操作、当前权限不可用或原操作没有受支持批次时拒绝。

真正无内容变化的保存不生成操作回执和证据，也不占用操作 ID；仍执行原有输入和单页边界校验。以上是已提交操作的恢复，不是未提交保存意图的持久队列，也不意味着插件停用时仍可写入。

## 隔离重放

`replay_batch(evidence, policy, total_fuel)` 不接受 HostRuntime、Connection、Store、凭据或路径回调。它在执行任何页之前检查所有记录的后端和逐页策略；每页使用嵌入的历史包、原任务及原预算创建新的 Runner，同时受调用者总燃料策略约束。没有 WASI、内容提交或依赖调用；普通核心 exchange 拒绝。

逐页比较完整 completion、退出与成功状态、实际调用数和剩余燃料，使用本次真实消耗推进总预算。首个不匹配停止后续执行，返回 `matches = false` 和已执行报告。后端不支持或策略不足明确拒绝，不提高额度、不恢复旧批准。成功匹配仍不证明业务结论正确、保存意图必然推导出最终内容，或整个宿主历史可重建。test.38 的 `morrow-transform-replay` 按 schema 1／2 分派单观察与批次，保留外部原始 PB 摘要 pin，并报告观察数。CLI 逐页使用默认 `Limits`、批次总燃料固定 1,000,000,000（1B）；通用 Rust API 由可信调用方指定总策略，最高 10,000,000,000（10B），不代表 CLI 自动采用该上限。命令退出 0 表示匹配、2 表示不匹配、1 表示拒绝。CLI 的6项独立实际进程测试与严格Clippy已通过；捕获后删除原合成宿主库和目录，再验证匹配、错误摘要／容器、超政策拒绝和首处不匹配退出。

## test.38 格式 9、迁移与物理共享

内容库格式 9 接受证据 schema 1／2。格式 4～8 经完整性核验按阶段原子迁移；8→9 在同一事务校验旧状态、更新版本、再检查新状态，旧证据、原 Commit、签名和块载荷不重编码。旧格式内冒充新批次拒绝，不通过改写或修复掩盖格式不兼容。独立只读核验接受格式 5～9，不创建或迁移文件。

[test.37 的32 KiB物理分块](PLUGIN_SHARED_EVIDENCE_STORAGE.md)继续使用，配方 schema 仍为1，原始配方上限扩到64 KiB以容纳批次容器；逻辑预算不放宽。批次内部共用一个包与跨证据按固定块复用是不同机制，不保证任意包或跨版本只有一份物理存储。无自动 GC、全局证据配额或自动 VACUUM。

## 已验证范围与后续

test.38 独立核心8项专项测试使用合成观察，覆盖1024项／4 MiB意图边界、三层重复字段、长度／wire／group和24 MiB总量、成功结果绑定、有序燃料、v1／v2混用拒绝及v1原字节保留。这些测试验证格式，不能作为实际 guest 执行来源证明。

真实 SDK 宿主7项专项测试覆盖649页最大结构、81页近4 MiB设置及逐页原输入／输出比较和隔离重放，并验证重开、历史重试不覆盖、意图冲突、停用权限、无变化ID、跨卡操作及坏页拒绝。81页样本实测消耗327,874,820 fuel，证据原PB为12,739,069字节，容器854,264字节；数值仅描述该合成设置与实际插件样本，不是通用性能或压缩率承诺。迁移另验8→9原字节保留、迁移前后进程故障边界，以及将合法新批次放入旧格式时只读／可写入口均拒绝。

这些是核心与实际 Rust 宿主专项结果，Windows GUI、完整产品和六平台验收不能由此推定。test.39 已实现默认 create／apply 的完整 Card 投影；capture→create 来源／编辑因果关联、查询证据、设置及其他通用宿主投影、完整依赖图／宿主响应证据、全局容量／保留／GC及未提交意图恢复继续推进。准确命令、结果和本轮其他验证由[阶段报告](../reports/test.38-settings-batch-evidence.md)记录。

## test.39 容量与投影扩展

schema 2 布局不变，当前 intent 上限为12 MiB，完整批次原始 PB 仍最多24 MiB，每操作16份／64 MiB的逻辑预算也不变。增加容量用于保留原来合法的8 MiB完整 CardRecord及有界宿主事实，不能用截断未知字段回避旧意图容量限制。设置协议自身仍限制整份设置4 MiB，并未随意图容量一起扩大。

当前内容库格式10接受旧格式4～9按阶段校验迁移，独立只读接受5～10。9→10仅在同一事务核验并更新容量门槛，不改原包、证据、Commit、签名或物理块；格式9拒绝intent大于4 MiB的批次。工作台投影使用独立intent_type，设置仍保留自己的原意图与页验证协议，不能把设置页精确重放当成完整设置Card投影。见[内容投影](PLUGIN_CONTENT_PROJECTION.md)及[test.39记录](../reports/test.39-content-projection.md)。
